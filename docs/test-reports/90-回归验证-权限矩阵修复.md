# 回归验证：member 角色权限矩阵修复

## 一、修复说明

**问题背景**：此前测试发现 member 角色（原 `permissions={"all":false}` 简写格式）对 `agents.create` / `chats.create` 等全部写权限被拒（返回 `403 FORBIDDEN_PERMISSION`），与需求 09 §2.3「项目成员默认具备：群聊发消息与 @、Agent 查看与克隆/自定义」冲突。受影响用例：TC-AGT-013、TC-CHAT-025、TC-CHAT-037。

**修复内容**：
- `seed.ts` 中 member 角色权限矩阵已补全为完整格式（8 资源 × 操作粒度）：`agents{view,create,edit=true,delete=false}`、`chats{view,create,edit=true,delete=false}`、`tasks{view,create,edit,review=true}`、`artifacts{view,create=true}`、`projects{view=true,create=false}`、`skills{view=true,create=false,edit=false}`、`workers{view=true,edit=false}`
- DB 中 member 角色 permissions 已同步更新（`PermissionGuard` 实时查库，无需重启）

**验证环境**：API `http://192.168.10.78:13000/api/v1`，执行时间 2026-08-10（UTC 15:31 ~ 15:34）
**认证**：admin/admin123（管理员）、seed-member/Admin@123456（member 角色，未加入任何项目）

## 三、结论

- **修复项全部 PASS**：member 角色现可创建 Agent（TC-AGT-013 201）；群聊发消息与私聊创建对非项目成员返回语义正确的 `PERMISSION_PROJECT_NOT_MEMBER`（TC-CHAT-025/037，权限守卫已放行、service 层成员校验拦截），与用例文档预期一致。
- **不变量无破坏**：只读端点（agents/skills/workers GET）全部放行；skills 写、workers 编辑仍按矩阵拒绝；tools/users 管理端点仍由 AdminGuard 拦截；注册默认 member 与 seed-member 权限矩阵一致。
- **测试数据已清理**：两个测试 Agent（a_0000000011、a_0000000012）已由 admin 删除（复核 404 AGENT_NOT_FOUND）；临时用户 reg_user_1786375994 已禁用（enabled=false，users 无 DELETE 端点）；未触碰任何 seed 数据。
