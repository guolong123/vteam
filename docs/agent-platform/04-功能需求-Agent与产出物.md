# 功能需求：Agent 管理与产出物

本文档定义 Agent 协作平台中「Agent 管理」「产出物协议」「任务文档库」三部分的功能需求，是 02 篇用户故事 US-04（查看产出物）与 US-05（配置 Agent）的功能落地。所有功能点以 FR-xx 编号、名称、描述与优先级（P0 核心必做 / P1 重要 / P2 增强）形式给出。

> 编号约定：本文档独立使用 FR-30 起编号区间，与 03 篇（任务与群聊协作）的 FR 编号互不冲突；若后续合并章节需统一编号，可在评审阶段按序重排。其中 FR-47（默认模型）、FR-48（工具权限）为补充编号，位置按功能域组织（工具权限紧随工具配置 FR-35，默认模型紧随权限范围 FR-36），编号不严格按出现顺序递增。

## 1. Agent 管理

Agent 是平台中的 AI 协作者，每个 Agent 都有角色定位、配置项与独立会话。平台提供「预置模板 + 模板克隆 + 完全自定义」三种创建方式，满足团队从开箱即用到深度定制的需求。

### 1.1 预置角色模板

**FR-30 预置角色模板** | P0

平台预置产品经理、架构师、开发者、测试四类角色模板，各自带有符合角色定位的默认提示词、技能、工具、权限范围与默认模型。预置模板开箱即用，成员可直接将其加入任务，无需任何配置。

| 模板 | 定位 | 默认模型建议 |
|------|------|-------------|
| 产品经理 | 需求拆解与文档化 | 通用对话模型，擅长结构化文本梳理与需求整理 |
| 架构师 | 技术方案设计与推演 | 推理模型，擅长复杂逻辑推演与方案权衡 |
| 开发者 | 编码实现与问题排查 | 代码能力突出的通用模型，兼顾实现与解释 |
| 测试 | 用例设计与缺陷验证 | 推理模型，擅长边界推演与场景穷举 |

预置模板中的产品经理（或团队自定义的项目经理）可作为任务的主 agent（负责人），牵头组织虚拟团队、推进任务直至验收。主 agent 的定义与协作方式详见 03 篇，本篇仅说明其在 Agent 管理中的定位：主 agent 同样是平台中的一名普通 Agent，其角色、配置项与默认模型按本篇规则统一维护。

**FR-31 模板克隆** | P0

成员可以预置模板（或团队内已自定义的 Agent）为起点克隆出一个新 Agent，在克隆副本上调整提示词、技能、工具、权限范围与默认模型，原模板不受影响。克隆是团队快速建立贴合项目规范的 Agent 的主要方式。

**FR-32 完全自定义** | P1

成员可以从空白创建完全自定义的 Agent，自行定义其角色名称、定位与全部配置项。自定义 Agent 与预置模板 Agent 在能力上无差别，均可加入任务参与协作。

### 1.2 Agent 配置项

每个 Agent 都可独立配置以下五项，配置对团队内可见，由创建者或具备权限的成员维护：

**FR-33 提示词配置** | P0

Agent 的提示词定义其行为方式与角色边界（如"以产品经理视角拆解需求，输出验收标准"）。成员可查看、编辑提示词，配置即时生效并作用于该 Agent 的后续会话。

**FR-34 技能配置** | P1

Agent 可启用一组技能（如文档撰写、代码审查、用例设计），决定其擅长执行的工作类型。成员可为 Agent 勾选或移除技能。

**FR-35 工具配置** | P1

Agent 可使用一组工具完成实际操作（如读取仓库文件、搜索、执行命令）。工具配置由**启用开关**与**每个工具独立配置的权限 effect** 两部分组成：

- **启用开关**：工具可单独启用或停用，被停用的工具 Agent 无法调用。
- **权限 effect**：每个工具独立配置其执行策略，取值 `allow`（允许，无需确认）/ `ask`（每次执行前向成员确认）/ `deny`（禁止）。**工具名即权限 action**（如 `jenkins-build`），支持通配符批量授权（如 `jenkins-*` 一次覆盖全部 jenkins 前缀工具）。

工具权限的逐工具配置规则见 FR-48。

**FR-48 工具权限** | P1

Agent 的工具权限按「工具（action）× effect（allow/ask/deny）」**逐工具**配置，每个工具对应一个独立的权限点：

- **权限点 = 工具名（action）**：工具注册时自动以其名字成为新权限点（如 `bash`、`jenkins-build`）。工具权限不是固定的枚举集合，而是随工具注册动态扩展的开放命名空间。
- **effect 三态**：`allow`（允许）/ `ask`（每次确认）/ `deny`（禁止），与 opencode PermissionV2 对齐。
- **默认策略**：有副作用的工具（构建、部署、写操作等）默认 `ask`；只读、低风险工具默认 `allow`。
- **来源徽章**：每个工具标注来源——**内置**（引擎/平台自带基础能力）、**自定义**（团队注册的自定义工具）、**MCP**（经 MCP 接入的外部工具，权限点形如 `<server>_<tool>`）。
- **通配符**：支持 `jenkins-*` 形式的通配 action，批量配置同类工具的 effect。

配置界面中每个工具一行：启用开关 + 工具名（action）+ 来源徽章 + effect 三态选择，与下方 agent-config 原型预览对应。

**FR-36 权限范围配置** | P0

Agent 的操作权限范围可配置，限定其可访问的资源与可执行的操作边界（如仅可读取指定项目、仅可查看文档库，不可执行写操作）。超出权限范围的操作不直接执行，由平台转交用户确认后放行。

权限范围与工具权限的关系：**工具权限 = 每个工具单独的 effect**（该工具能否被调用、调用前是否需确认，见 FR-48）；**权限范围 = 资源范围**（被授权的工具能访问哪些项目、文档、仓库）。两者正交、叠加生效：工具权限回答「这个工具有没有被授权、以什么策略执行」，权限范围回答「被授权之后能触及哪些资源」。

**FR-47 默认模型配置** | P0

创建或编辑 Agent 时，可为该 Agent 设置默认模型，决定其在会话处理中使用的基础能力侧重（如通用对话、代码生成、复杂推理等）。模型列表由底层引擎（opencode）接口动态获取，成员从列表中选择；未选择时沿用模板默认模型。默认模型属于技术愿景级能力，模型清单与接口实现细节不在本 PRD 范围。

### 1.3 会话模型

**FR-37 每 Agent 每任务独立会话** | P0

平台为每名 Agent 的每个任务维护一个独立会话（session），群聊中 @ 触发与私聊共用该会话，会话内上下文连续；不同任务之间的会话相互隔离，互不串扰。会话处理过程可被成员实时查看，但 Agent 的内部处理过程不广播到群聊，群聊只显示其最终回复。

Agent 管理（预置模板、克隆与自定义、五项配置）的界面效果见下方原型预览：

```prototype
id: agent-config
title: Agent 配置页
device: desktop
height: 720
```

配置面板覆盖提示词、技能、工具、权限范围与默认模型五块配置项，与 FR-33~36、FR-47 逐一对应，工具配置区含逐工具权限 effect 配置（FR-35 / FR-48）；右侧提供「克隆此 Agent」入口落实 FR-31。

## 2. 产出物协议

产出物是 Agent 工作成果的载体。平台定义统一的产出物提交规则，保证任何 Agent 产出的成果都能被归档、查看与复用。

### 2.1 结构化输出

**FR-38 产出物结构化输出规范** | P0

Agent 按平台规定的结构化格式返回产出（结论文本、文档、文件三类），提交时附带必要的元信息（产出类型、标题、作者 Agent、所属任务）。结构化格式的具体定义属于设计阶段产物，本文档只约束"必须结构化返回并可归档"这一规则。

### 2.2 产出物类型与归档

**FR-39 产出物类型** | P0

产出物分为三类：**结论文本**（简短结论、问答摘要）、**文档**（需求文档、设计文档、测试用例等长文）、**文件**（代码文件、配置文件等附件）。

**FR-40 结论文本直接归档** | P0

Agent 的结论文本产出由平台直接归档为任务全局文档，无需额外导出步骤。

**FR-41 文档经平台拉取** | P1

Agent 产出的文档由平台从其工作环境拉取后归档为任务全局文档；拉取失败时产出保留在会话中并向成员提示，不产生不完整的归档记录。

**FR-42 产出物为任务全局文档** | P0

归档后的产出物成为任务的全局文档，对团队所有成员与任务内所有 Agent 可见。任务文档是各环节衔接复用的唯一权威载体，不依赖对话记录。

**FR-43 版本历史 append 递增** | P0

对同一产出物的更新不覆盖原内容，而是追加为新版本，版本号依次递增（v1、v2、v3...）。团队成员可查看每次版本的内容与变更时间、作者，追溯产出演进过程。

**本版边界：产出物不可删除。** 产出物（含各版本）本版不可删除，只能由 Agent 重新产出追加新版本；已验收版本不可修改或覆盖（见 03 篇 FR-04「已验收版本不可覆盖」），保证验收结论对应的内容不可变。

## 3. 任务文档库

任务文档库集中管理任务的全部产出物，是团队查看成果与 Agent 获取上下文的统一入口。

**FR-44 文档库文档列表** | P0

任务文档库提供产出物列表，展示每份文档的类型、标题、版本、作者 Agent 与提交时间，成员可按类型或名称筛选查找。

**FR-45 文档查看与版本切换** | P1

成员可打开任一产出物查看内容，并支持在版本历史间切换查看；文档只读，修改通过 Agent 重新产出新版本完成。

**FR-46 @触发时注入文档库上下文** | P0

在群聊 @ 触发 Agent 时，平台自动将群聊历史与任务文档库内容注入该 Agent 的会话上下文，Agent 无需用户重复背景信息即可基于任务最新状态作答。

任务文档库的界面效果见下方原型预览——产出物列表、文档查看器与版本切换统一呈现在任务详情页：

```prototype
id: task-detail
title: 任务详情与文档库
device: desktop
height: 720
```

文档库左栏列出产出物类型与版本，右侧查看器支持版本历史切换，与 FR-43/FR-44/FR-45 的定义对应。

## 4. 技术底座愿景（概述）

完整平台的技术底座基于 opencode 的编程式驱动能力（opencode serve 与 SDK）：每个 Agent 对应一个独立会话，由平台统一调度；产出物结构化输出依托 opencode 的 json_schema 能力；权限请求通过人机协同的请求-确认机制完成。以上仅作为产品愿景的支撑前提，具体设计不属本 PRD 范围。
