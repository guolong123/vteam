# 派发-回执配对机制

## 1. 背景与问题

`tm_0000000002` 群聊实证（2026-09-15/16）：架构师 m_426 首轮 REJECT、m_445/m_452/m_454/m_464/m_472/m_474 五次跟进，PM 全部没看见，连记四次“架构视角无回执”并发出重复催办（m_526）。PM 自查（m_516）承认 `chat_history` 增量查询 132KB 被截断，无法确证。反例：凡带 `@项目经理-1` 的回执（开发者 m_437、测试 m_440 系）次次必达。

**根因一句话：PM 是 opencode 会话，只有被 @（`dispatchAgentMention`）或用户直触才会醒；成员的 `group_post` 与完工文字不产生任何指向 PM 的触发。** 平台只管送信（`triggered=true`），“送达—回执—收敛”后半段无人负责。

## 2. 目标与非目标

* 目标：任何派发（notify/dispatch）都有可查询的回执状态；目标回应后派发人**恰好被唤醒一次**并收到摘要；超时未回时催办幂等。
* 非目标：不改变现有触发语义（@ 即唤醒保持）；不做 PM 的轮询心跳（浪费 token）；不碰任务状态机。

## 3. 详细设计

### 3.1 待回执账本（新表 `message_receipts`）

| 字段 | 说明 |
|---|---|
| `id` | `mr_` 前缀主键 |
| `messageId` | 触发派发的源消息（notify 落库的那条） |
| `fromInstanceId` / `toInstanceId` | 派发人 → 目标 |
| `taskId` / `teamId` | 归属（团队维度 taskId 可空） |
| `summary` | 事项摘要（派发词前 100 字，展示用） |
| `status` | `pending` → `acked` / `expired` |
| `createdAt` / `ackedAt` | 记账/清账时间 |

写入点：`dispatchAgentMention` 成功进入 `dispatch()` 后记一条 `pending`（与派发同事务或紧随其后，失败不阻断派发，只记 warn）。

### 3.2 清账规则（只增不改，全部幂等）

1. 目标在群聊发布带 `@派发人` 的消息 → 清其名下全部 `pending`（以最新一条为准聚合）。
2. 目标的 `task.completed` 回流 → 清其名下全部 `pending`（完工即默认回执）。
3. 清账瞬间向派发人发**一次**定向唤醒（复用 `dispatchAgentMention`，正文为回执摘要聚合：`你派发的 N 项已有回音：…`），随后不再打扰。
4. 去重：若目标的回执消息本来就 `@` 了派发人（m_437 类），派发人已被正常唤醒，**不再**二次唤醒（以 `mentions` 含派发人为判据）。

### 3.3 超时与催办幂等

* 超时可配，默认 10 分钟（对齐 30 篇协作规约）。
* 超时未清：允许**一次**催办（同一 `(from, to, 事项)` 10 分钟窗口内第二次催办请求直接返回上次催办记录，不再派发）。
* 二次超时：按规约升级——转 issue 跟踪 / 改派 / 提示成员，不再无脑重发。

### 3.4 待回执看板（可观测）

* `GET /messages/receipts?taskId=&teamId=&status=pending` 返回 `n/N` 聚合（按目标分组）。
* `team_view` / `task_context` 扩展 `pendingReceipts` 计数，PM 一句话可查，不再翻 132KB 历史。
* `chat_history` 修复（顺带）：默认 `limit=20`，超长响应给摘要 + `truncated/total` 标记，全文走分页；m_516 式截断不再发生。

### 3.5 提示词补丁（与机制互锁）

* 成员规约升级为硬规则：一切回执类消息必须 `@派发人`（m_445 式漏 @ 即违规，PM 有权退回重发）。
* PM 铁律：不得凭印象记录“未回执”，判定缺席前必须先查待回执看板。

## 4. 验收标准

1. 复演 m_426：架构师回执不带 `@PM` → PM 仍被唤醒一次并收到摘要，看板从 0/1 变 1/1。
2. m_437 式自带 `@PM` 的回执不产生二次唤醒（全链路只唤醒一次，可数）。
3. 同一事项 10 分钟内第二次催办被拦，返回上次催办记录。
4. `chat_history` 默认 20 条，有 `truncated` 标记。

## 5. 实施步骤

1. 迁移建 `message_receipts` 表 + Prisma 模型（15 篇风格）。
2. `dispatchAgentMention` 成功后记账；`worker-event.ingress` 的 `task.completed` 与群聊 `@` 路径加清账+唤醒（复用既有 dispatch，不开新通道）。
3. `GET /messages/receipts` + `team_view/task_context` 计数扩展。
4. `chat_history` 分页默认值与截断标记。
5. 成员/PM 提示词补丁（seed）。
6. 回归：既有 notify/dispatch 单测 + 新增配对单测（记账/清账去重/超时幂等）。
