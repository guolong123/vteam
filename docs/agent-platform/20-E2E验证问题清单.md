## 3. 问题清单

### P1【严重】会话复用导致 Agent 回复内容错乱

- **现象**：群聊/私聊复用同一 opencode session 后，Agent 最终回复聚合了会话历史全部内容。新任务回复返回旧任务内容。
- **证据**：
  - `m_0000000103`（针对"创建 e2e-doc.md"新消息）回复却是上一条任务（bash 测试）的旧内容。
  - `m_0000000106`（私聊问"介绍一下自己"）回复聚合了 bash 测试 + e2e-doc 产出物声明 JSON + 全部历史。
  - 群聊消息 text 中出现 `[群聊历史消息]` + `<doclib>` 注入内容重复拼接。
- **影响**：用户无法获得正确回复；聊天界面显示大量冗余内容；产出物声明无法被可靠提取。
- **定位线索**：`server/src/chat/worker-dispatcher.ts` `aggregateText()` + 会话复用逻辑；`worker/src/exec/exec-server.ts` 轮询聚合。
- **修复**（worker 侧 `driver/prompt-await.ts`）：`sendAndAwait` 在 sendMessage **前**取基线消息 id 集合（复用会话快照），`awaitCompletion` 只对基线后新增消息做完成判定/文本聚合/首字判定——历史轮次的 step-finish 与回复不再误命中本轮；`MessageDeltaTracker` 只上送 assistant 消息（user prompt 注入内容不再进入流式 delta）。

### P2【严重】Agent 创建的文档无法访问

- **现象**：
  1. Agent 创建的文件落在 worker 容器 `/tmp/opencode/` 下，浏览器不可达。
  2. 手动提交 doc 产出物后，下载链接 `/uploads/xxx.md` 返回 **404**（文件未上传控制面）。
  3. doc/file 产出物 `sha256` 为空内容哈希（`e3b0c442...`，空字符串标准哈希）。
- **证据**：`/uploads/english-mini-program-requirements.md` → HTTP 404；产出物详情 `filePath=/tmp/opencode/...`，`fileSize=null`。
- **根因**：`artifacts.service.ts` 注释明确"Phase 3 不真实拉取，重试逻辑注释预留"——doc/file 仅存 fileRef 路径占位；前端却渲染为可点击下载链接。
- **影响**：**用户核心诉求——聊天页面无法访问 Agent 创建的文档**。
- **修复**（worker 上送 + server 落盘 + 前端降级）：
  1. worker 完成时从回复 text 提取 doc/file 声明并读取工作目录文件内容（上限 1MB），随 `task.completed` 上送 `artifacts`（`worker/src/exec/artifact-extract.ts`）；
  2. server 归档时 doc/file 携带真实内容 → `FileStorageService.saveTextFile` 落盘 uploads 生成可访问 URL，替换 worker 路径占位（`artifacts.service.ts`）；
  3. 前端 `fileUrl` 为 `/uploads/` 且 `fileSize==null`（磁盘不存在信号）→ 降级纯文本展示，不再渲染死链（`web/app/(main)/artifacts/page.tsx`）。

### P3【严重】产出物声明自动归档链路未生效

- **现象**：用户消息明确要求回复带 `{"type":"doc","title":"端到端文档测试","fileRef":"/tmp/opencode/e2e-doc.md"}`，Agent 回复文本中确实出现了该 JSON，但产出物列表仍为空（total=0）。
- **根因**：归档依赖 worker 回流 `payload.artifacts` 数组 + server 端 `extractArtifacts(text)` 提取，链路未打通（worker 侧无提取能力或回流时 text 聚合错乱导致声明丢失）。
- **影响**：产出物只能通过手动旁路提交（POST /tasks/:id/artifacts），Agent 自动沉淀文档库不可用。
- **修复**（`server/src/chat/worker-dispatcher.ts`）：`handleTaskCompleted` 合并 worker 显式上送（`payload.artifacts`）与 server 从回复 text 提取（`extractArtifacts`）的声明并去重归档——方案 A 下 worker 完成事件不带 artifacts 时，text 提取路径兜底生效（P2 的 worker 上送同时补齐显式路径）。

### P4【严重】模型首字超时导致任务执行失败且无反馈

- **现象**：新任务执行中模型首字超时 → worker abort 会话 → 消息永远停留在 `processing` 状态。
- **证据**：worker 日志 `[prompt-await] 会话 ses_0143806d7ffee1SyZ2OnoSgYb0 等待首字超时（可能模型无响应或会话挂起）`；`m_0000000109` 已 5+ 分钟仍 processing。
- **影响**：用户误以为 Agent 仍在处理，实际已失败；无失败提示、无重试。
- **修复**：
  1. server `worker-dispatcher.ts` `handleAgentStatus` error 分支 → 频道内该 agent 最新 processing 消息标记 `failed` + 错误内容落库广播（无 processing 消息则新建 failed 消息）+ `failedSessions` 标记防迟到回流；
  2. 前端消息渲染层对 `processing` 超 3 分钟的消息降级为失败形态（`data-testid="msg-timeout"`，30s interval 时钟驱动）。

### P5【中等】worker 心跳不稳定

- **现象**：worker 心跳多次失败（`fetch failed` / HTTP 408 / HTTP 500）。
- **证据**：server 日志 `PrismaClientKnownRequestError: Timed out fetching a new connection from the connection pool (limit: 33)`。
- **影响**：worker 状态可能误判离线，任务调度可靠性下降。
- **修复**（`server/src/workers/workers.service.ts`）：心跳 token 校验结果内存缓存（tokenHash 指纹 + 30s TTL）——每 10s 心跳不再重复 CPU 密集 bcrypt，降低多 worker 并发/注册风暴下的 DB 连接池压力（连接池超时根因之一）。

### P6【中等】群聊回复文本拼接全局消息 —— 用户提交需求①

- **现象**：`[群聊历史消息]` + `<doclib>` 系统上下文直接拼进 AI 回复 text，前端显示难看。
- **用户要求**：维护一个全局消息，由系统自动注入，不拼进 AI 回复文本。
- **修复**：
  1. 根因随 P1 修复消除（worker 只聚合/上送本轮 assistant 消息，注入内容不再进入回复与流式 delta）；
  2. 前端兜底过滤（`web/lib/strip-injected-context.ts`）：渲染 agent 文本前剥离 `<doclib>...</doclib>` 块与 `[群聊历史消息]` 历史行。

### P7【低】产出物协议与 @ 机制需注入全局提示 —— 用户提交需求②

- **现象**：Agent 默认不会按产出物协议（`<artifact>` / JSON / `[artifact]` 声明）回复，需在每条消息中显式要求。
- **用户要求**：将产出物协议格式 + @ 定向机制说明放入全局提示（system prompt），让 Agent 默认知晓如何声明可归档产出物。
- **修复**（`worker-dispatcher.ts` + worker 链路）：新增 `GLOBAL_SYSTEM_INSTRUCTIONS`（产出物协议 + @机制），经 opencode `prompt_async` **顶层 `system` 字段**下发（`worker.client.ts`/`exec-server.ts`/`v1-driver.ts` 透传）——serve 将其拼入 LLM system message（role:system），不进 user 消息、不显示在聊天记录。

### P8【低】侧边栏导航被内容区拦截

- **现象**：从任务页点击侧边栏导航按钮时，`<div data-testid="app-content">` 拦截 pointer events，点击失败。
- **证据**：Playwright 点击 `nav-item` 多次重试被拦截。
- **影响**：部分页面无法通过侧边栏导航切换，需用 URL 直连。
- **根因**：非 z-index 问题（dock 已是 z-index:50）——收起态 dock 仅 56px 宽且 `overflow:hidden`，`nav-item` 命中点（x≈150）落在 dock 外；Playwright 直点 nav-item 中心时鼠标不在 dock 上 → `:hover` 不触发 → dock 不展开 → 命中测试落到 `app-content` → 死锁。
- **修复**（`web/src/components/layout/nav-dock.tsx`）：新增透明命中热区（`navdock-hitzone`，覆盖 x∈[68,260] 与 dock 同高），hover 触发展开（`navdock-expanded` 类）；dock 展开后经 `~` 兄弟选择器置热区 `pointer-events:none` 让位 panel 内 nav-item 可点。

## 5. 建议修复优先级

1. **P2 + P3**：产出物归档与访问（用户核心诉求，端到端闭环）
2. **P1**：会话复用回复错乱（正确性）
3. **P4**：超时失败提示与重试（可靠性）
4. **P6 + P7**：全局消息注入 + 全局提示（用户明确提交的需求）
5. **P5**：心跳/连接池稳定性
6. **P8**：导航拦截
