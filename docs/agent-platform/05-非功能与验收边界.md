# 非功能需求与验收边界

本文档定义 Agent 协作平台的非功能需求（性能、安全、可用性、可扩展性、可维护性）、完整平台阶段的技术约束愿景、本迭代与完整平台的验收边界，以及风险与开放问题。技术相关内容均为平台愿景级描述，本迭代不实现任何可运行系统。

## 1. 非功能需求

以下指标均为**目标值**，用于指导完整平台阶段的验收，不含任何技术实现方案。

### 1.1 性能

| 指标 | 目标值 | 说明 |
|------|-------|------|
| 消息发送到群聊显示 | ≤ 1 秒 | 用户发送消息后的可见性反馈，保证协作的即时感 |
| @ 触发后 Agent 首字响应 | ≤ 5 秒 | 从消息发出到 Agent 开始输出，平台调度与模型首 token 延迟之和 |
| Agent 单轮回复完成 | 分钟级 | 受模型与任务复杂度制约，不设绝对上限，但应可感知进度 |
| 会话流实时查看延迟 | ≤ 2 秒 | 用户点击查看 Agent 会话后，事件流到达界面的延迟 |
| 多 Agent 并行 | 单任务 4~6 个 Agent 并行 | 一个 Agent 的长时间响应不阻塞其他 Agent 与其他消息 |

### 1.2 安全

| 方面 | 要求 |
|------|------|
| 认证 | 平台内置账号体系，登录凭证妥善保管，密码不以明文存储或传输 |
| 权限 | 项目级权限模型：成员仅在所属项目内可见任务、群聊与 Agent；跨项目数据不可见 |
| Agent 权限范围 | Agent 的工具与操作权限可配置，默认最小权限；配置变更需可追溯 |
| 产出物访问控制 | 产出物归属任务，仅任务所在项目的成员可查看；文件类产出物按任务隔离 |
| 敏感操作授权 | Agent 请求敏感操作（写文件、执行命令等）时需用户授权确认，不得静默执行 |

### 1.3 可用性

- 平台服务目标可用性 ≥ 99.5%（完整平台阶段愿景）。
- **单 Agent 故障不影响其他 Agent 与平台主体功能**：一个 Agent 会话出错或中断，其余 Agent 与群聊继续工作。
- **任务与产出不因中断丢失**：群聊消息、任务状态、产出物在 Agent 会话中断后依然完整可查，可恢复推进。

### 1.4 可扩展性

- 多任务并发：平台同时承载多个任务，每个任务内多个 Agent 并行协作，任务间互不影响。
- 水平扩展预留：平台设计为可横向扩展（完整平台阶段），满足团队规模增长。
- Agent 规模：单平台可管理数十个 Agent 角色模板与自定义实例。

### 1.5 可维护性

- Agent 配置可复制、可版本化（模板克隆与修改），团队可沉淀最佳实践。
- 任务与产出物归档后可长期追溯，决策过程可回查。
- 平台运行过程可观测：用户可实时查看 Agent 会话流，平台自身状态有日志可查。

## 2. 技术约束（平台愿景）

本节为**完整平台阶段**的技术约束，作为产品愿景的一部分写入 PRD。本迭代只交付 PRD 文档与静态原型页面，不落地任何技术选型实现。

| 约束项 | 愿景说明 |
|--------|---------|
| 底层引擎 | 基于 opencode（目标版本 1.18.x），通过 opencode serve 编程式驱动，服务地址可配置，便于环境隔离与迁移 |
| 技术栈 | Node.js + TypeScript，前后端语言统一 |
| 数据存储 | MySQL 作为主要存储；本机验证/开发环境可先用 SQLite 简化部署 |
| 前端框架 | Next.js 全栈框架，承载管理界面与协作界面 |

这些约束仅用于约束未来完整平台的方向，本迭代的验收与它们无耦合。

### 3.4 后续迭代项清单

以下能力明确属于后续迭代，不在第一版范围，与产品范围 EXCLUDE 保持一致：

**范围外（后续迭代）**：

- **真实仓库操作与 PR 合并**：与代码托管平台强绑定的能力
- **部署与 CI/CD 集成**：发布流水线能力
- **SSO 单点登录**：对接企业统一认证
- **多租户**：跨组织隔离、计费与订阅
- **对象存储**：大规模文件存储（第一版预留接口）
- **SSE 实时推送**：第一版以事件流为基础，后续迭代完善实时能力
- **token 压缩与分层上下文**：应对群聊历史注入带来的 token 增长

**下一版增强（已确认方向）**：

- **通知与消息推送**：任务进展、被 @、验收提醒时平台内通知 + 邮件/飞书等外部推送
- **全局搜索**：跨任务搜索消息、产出物、任务标题
- **Agent 会话断点续接**：任务/系统重启后恢复 Agent 会话上下文（save/load）
- **审计与操作日志**：记录用户/Agent 的创建、修改、删除等操作留痕
- **群聊成员管理（人类成员）**：任务群聊添加/移除人类成员（非仅 Agent）
- **任务模板**：预置任务流程模板（默认 Agent 组合 + 主 Agent + 背景文档）
- **消息回复引用**：群聊引用上一条消息回复
- **看板拖拽与批量操作**：卡片拖拽变更状态、批量归档/启停
- **数据导出**：任务/产出物/会话导出（JSON/Markdown/压缩包）
- **体验优化**：深色模式、国际化 i18n、任务收藏/星标、群聊免打扰、产出物评论、快捷键

> 注：以上「下一版增强」项仅确认方向，本版不做设计与排期。

## 4. 风险与开放问题

### 4.1 风险清单

| 风险 | 说明 | 缓解方向（愿景级） |
|------|------|-------------------|
| opencode serve 并发稳定性 | 多 Agent 并行驱动同一 serve 服务的稳定性未经大规模验证 | 每 Agent 独立 session；serve 地址可配置，便于按环境隔离；上线前并发压测 |
| token 成本 | 群聊历史注入会导致 token 快速增长，成本不可控（研究教训：AutoGen 群聊 token 爆炸） | 按 Agent 过滤相关历史；token 分层上下文（已列入后续迭代） |
| Agent 死循环 | Agent 之间互相 @ 可能形成无终止的响应循环 | @ 显式寻址约束触发面；限制单轮互 @ 次数；用户可随时中断 |
| 结构化输出失败率 | Agent 返回不符合产出物协议的概率不为零 | 产出物校验与重试；失败时降级为结论文本，保证任务不阻塞 |
| 状态持久化缺失 | 会话与任务状态若不持久化，中断即丢失（研究教训：LangGraph 中状态持久化是平台功能，而非模型能力） | 任务/会话/产出物状态落库，支持中断恢复（完整平台实现） |
| 单 Agent 故障扩散 | 一个 Agent 出错不应影响其他 Agent 与平台（研究教训：per-agent 错误边界） | 每个 Agent 独立隔离，错误边界收敛在单 Agent 内 |
| 错误表达方式差异 | 底层框架不以进程退出表达错误（研究教训），异常可能表现为静默失败或异常输出 | 统一错误捕获与呈现，把底层异常转为平台可理解的信号 |

### 4.2 开放问题

- 群聊历史注入的 token 上限与按 Agent 过滤策略如何设定（后续迭代细化）。
- 产出物协议（结构化输出 Schema）的版本管理方式。
- opencode serve 单实例可承载的并发 session 上限。
- 是否需要跨任务共享的 Agent 会话，或严格每 Agent 每任务一个会话。
- 上下文交接的污染控制（研究教训：CrewAI 上下文交接存在污染风险）的具体边界。

本文档与 01~04 篇共同构成完整的 Agent 协作平台 PRD。本迭代的验收以 3.1 节交付物为准，完整平台功能仅作为蓝图，不构成本迭代的交付承诺。
