# 团队模型与排队设计

本文档是全局团队域的**完整设计**：Team/TeamMember/TeamQueue 三表的全局团队模型、串行 FIFO 排队与六态任务、一团队一群与按任务分区的群聊/会话/私聊复用、记忆开关（`reuseSession` / `resetAfterComplete`）与批量重置。它是 14 篇 §5 的展开与唯一事实源，落库见 15 篇 §3.3/§3.5/§3.6/§4/§8，API 见 09 篇 §3.4 团队域。

## 1. 定位与文档关系

**一句话：团队是全局域，任务归属团队串行排队，群聊与会话按团队复用。** 旧模型每任务一群（`task_group`），多任务并行易冲突；新模型一团队一群、单团队一次仅一任务进行中，其余 FIFO 排队，记忆可选跨任务复用。

## 2. 团队模型（Team / TeamMember）

### 2.1 实体

| 表 | 主键 | 关键字段 | 约束 |
|----|------|---------|------|
| `teams` | `tm_` | `name`（全局唯一）、`reuse_session`（默认 true）、`current_task_id`（队首进行中）、`version`（乐观锁）、`created_by` | `name` UNIQUE，`current_task_id` FK → tasks.id |
| `team_members` | `tmm_` | `team_id` + `agent_id`（模板）+ `alias`（默认「<角色>-<seq>」）+ `seq`（同模板同团队内序号）+ `work_dir` | `UNIQUE(team_id, agent_id, seq)`，并发由 `SELECT MAX(seq) FOR UPDATE` 保证 |
| `team_queues` | `tq_` | `team_id` + `task_id`（唯一，一任务仅在一队列）+ `position`（1..N FIFO）+ `enqueued_at` | `task_id` UNIQUE，`INDEX(team_id, position)` 扫队/重排 |

### 2.2 创建与成员管理

| 动作 | 端点 | 约束 |
|------|------|------|
| 创建团队 | `POST /teams` `{name!, description?, reuseSession?, members[]}` | `name` 必填且全局唯一（409），`members` 中 `agentId` 必填，`alias/workDir` 缺省按 `ROLE_LABELS[role]` + `seq` 生成 |
| 列表 | `GET /teams?page=&pageSize=&name=` | `name` contains 搜索，分页 |
| 详情 | `GET /teams/:id` | 返回 `members[]` + `queue[]`（队列含 `taskTitle/taskStatus` 展开） |
| 更新团队 | `PATCH /teams/:id` `{name?, description?, reuseSession?, version?}` | `version` 乐观锁 CAS（`updateMany where version`），冲突 409 `VERSION_CONFLICT` |
| 删除团队 | `DELETE /teams/:id` | 仅空闲且队列空（`currentTaskId` NULL + `queue` 空）可删，否则 409 `TEAM_BUSY` / `TEAM_QUEUE_NOT_EMPTY` |
| 增成员 | `POST /teams/:id/members` `{agentId!, alias?, workDir?}` | 同模板多次添加时 `seq` 递增（事务内 `MAX(seq) FOR UPDATE`），`alias/workDir` 缺省同上 |
| 改成员 | `PATCH /teams/:id/members/:memberId` `{alias?, workDir?}` | 仅 alias/workDir 可改 |
| 删成员 | `DELETE /teams/:id/members/:memberId` | 物理删除 |

### 2.3 多实例

同一模板 Agent（如开发者）可在同一团队内添加多次，各实例以 `seq` 区分（1、2、3…），`alias` 默认「开发者-1」「开发者-2」，`workDir` 为 `/data/vteam-worker/<sanitize>-<seq>`。各实例拥有独立的 `team_member_id`、`task_agent_id` 快照、会话与私聊，`@` 与 issue 指派可精确到实例。

## 3. 排队设计（TeamQueue，FIFO 串行）

### 3.1 任务归属

`POST /projects/:pid/tasks` `{teamId!, title!, description?, priority?, resetAfterComplete?}`。`teamId` 必填（旧 `agentIds[]/mainAgentId` 已废弃），`resetAfterComplete` 可选（覆盖团队 `reuseSession`）。任务归属团队后，`team_members` 快照为 `task_agents`（alias/seq/workDir 原样复制），并创建 `sessions`（`team_member_id` 绑定）。

### 3.2 入队与状态

```
团队空闲（current_task_id IS NULL）
  → 任务 status = pending，teams.current_task_id = taskId（CAS + version++）
团队忙（current_task_id 非空）
  → 任务 status = queued，team_queues 追加 {team_id, task_id, position = MAX(position)+1}
```

并发保证：`SELECT team FOR UPDATE` + `SELECT MAX(position) FOR UPDATE` + `teams.version` 乐观锁 CAS（`updateMany where version` 重试 3 次），仅一任务可抢到 `pending`，其余 `queued`。

任务状态六态顺序：`queued → pending → in_progress → pending_review → completed → archived`（13 篇 §2.1 扩展）。

### 3.3 晋升（promoteNextInTx）

`accept` / `archive` / `reject` 成功后，同事务内执行：

```
SELECT team FOR UPDATE + SELECT team_queues ORDER BY position FOR UPDATE
if 队列非空
  队首 queued → pending
  删除队首 team_queues 行
  剩余 position 重排 1..N
  teams.current_task_id = 新队首 taskId，version++
else
  teams.current_task_id = NULL，version++
广播 team.queue.changed（team scope）+ team.changed（global）
```

晋升与批量重置（§4）同事务原子性。

### 3.4 取消排队

`DELETE /teams/:id/queue/:taskId` 仅 `queued` 可取消，否则 409 `TASK_NOT_QUEUED`。事务内删除队首并重排剩余 1..N，若被取消的是队首则晋升下一队首（`queued→pending`），双广播同上。不支持拖拽重排。

### 3.5 看板与队列视图

- 看板新增「排队中」列（`status=queued`），`GET /tasks?status=queued` 过滤。
- `GET /teams/:id` 的 `queue[]` 含 `taskTitle/taskStatus` 展开，前端 `TeamQueueCard` 展示 FIFO 徽章（#position）、当前位置高亮与取消入口（仅 `queued` 可点）。
- 团队详情队列预览 + 任务详情 `TeamQueueCard` + `TeamMemoryCard`（§4.3）。

## 4. 群聊/会话复用与记忆开关

### 4.1 一团队一群（team_group）

| 项 | 约定 |
|----|------|
| 频道类型 | `team_group` 一团队一群（`chat_channels(team_id, team_member_id)` 唯一，`team_member_id` NULL 表示群聊）；`task_group` 已废弃，请求 `type=task_group` 返回 400 `CHANNEL_TYPE_DEPRECATED` |
| 创建 | 懒创建：首任务创建时建 `team_group` 频道（`team_id` + `taskId` 首任务），复用团队后续任务不再新建 |
| 索引 | `idx_chat_channels_team_id (team_id)` 按团队查群聊/私聊 |

### 4.2 消息按任务分区

`messages.task_id` 分区：团队群跨任务复用时，同一频道内多任务消息共存。查询按 `taskId` 过滤（`WHERE channelId=? AND taskId=?`，`idx_messages_channel_task`），创建新任务时插入系统分隔「--- Task B started ---」并双广播 `channel:<id>` + `team:<teamId>`，历史跨任务可见。SSE 订阅 `team:<teamId>` 可收团队群消息。

### 4.3 私聊按 teamMember 复用

`private` 频道按 `team_member_id` 复用（`uk_channels_team_member`），`POST /dm-channels` `{teamId!, teamMemberId?/agentId?}`（二选一，`teamMemberId` 优先，`agentId` 时取 `teamId+agentId` 最小 `seq` 实例），幂等按 `(teamId, teamMemberId)`（含 soft delete 复活），`taskId` 滞空（团队私聊全局复用，不为每任务建频道）。`getSessionHistory` 按 `teamMemberId` 维度跨任务保留历史（`reuseSession=true` 时前任务绑定仍命中），`reset` 后清空则回退空表。

### 4.4 会话记忆开关

| 开关 | 位置 | 默认 | 语义 |
|------|------|------|------|
| `teams.reuse_session` | 团队级 | `true` | true 跨任务复用 `sessions` 行（`team_member_id` 同行延续，`instanceRef` 保留，opencode history 延续）；false 每任务新行 |
| `tasks.reset_after_complete` | 任务级覆盖 | `false` | true 时覆盖团队开关：本任务完成/归档时为团队所有成员开新会话，下一任务上下文全新 |

生效规则：`effectiveNewSession = resetAfterComplete || !reuseSession`。

### 4.5 批量重置（resetTeamSessionsInTx）

触发：`accept`/`archive` 同事务内若 `effectiveNewSession` 为 true，或手动 `POST /teams/:id/reset-sessions`（幂等，空会话 0 幂等）。

步骤（同事务内，顺序锁死）：

```
按 team_member_id 维度 findMany sessions
  → 软删 TaskGroupInstance（removedAt，先于 delete）
  → deleteMany sessions
  → create 新 s_ 行（status=created，workerId/instanceRef 清空）
  → 插入系统消息「已为下一任务开新会话」到 team_group 频道
  → 广播 chat.message.new + team.changed
```

`Memory` 表不动（记忆与会话分离）。

## 5. API 与事件

### 5.1 团队端点（09 篇 §3.4）

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| POST | `/teams` | `teams:create` | 创建团队 |
| GET | `/teams` | `teams:view` | 分页搜索 |
| GET | `/teams/:id` | `teams:view` | 详情（含 members/queue） |
| PATCH | `/teams/:id` | `teams:edit` | 更新（version 乐观锁） |
| DELETE | `/teams/:id` | `teams:delete` | 仅空闲且队列空 |
| POST | `/teams/:id/members` | `teams:edit` | 增成员 |
| PATCH | `/teams/:id/members/:memberId` | `teams:edit` | 改成员 |
| DELETE | `/teams/:id/members/:memberId` | `teams:edit` | 删成员 |
| POST | `/teams/:id/reset-sessions` | `teams:edit` | 手动批量重置 |
| DELETE | `/teams/:id/queue/:taskId` | `teams:edit` | 取消排队（仅 queued） |
| POST | `/projects/:pid/tasks` | `tasks:create` | 创建任务（`teamId!` 必填） |

### 5.2 事件（SSE scope）

| 事件 | scope | 说明 |
|------|-------|------|
| `team.created` / `team.updated` / `team.deleted` | `team:<teamId>` + global | 团队创建/更新/删除 |
| `team.queue.changed` | `team:<teamId>` | 入队/晋升/取消（`{teamId, promoted?, queueLength}`） |
| `task.status_changed` | global | 任务状态变更（含 `queued→pending` 晋升） |
| `chat.message.new` | `channel:<id>` + `team:<teamId>` | 消息双广播（团队群） |

订阅：`GET /api/v1/events?scope=team:<teamId>,task:<taskId>,global`（逗号分隔多 scope，`team_group` 与 `task_group` 双订阅过渡兼容见 15 篇 §8）。

### 5.3 权限与导航

- 团队为全局域，需 `teams` 资源权限（`view/create/edit/delete`，`member` 预置 `view/create/edit`，`admin` 全量）。
- 前端 `NAV_VISIBLE` `teams` 受 `teams:view` 控制，无权限不显示入口；`ProjectMembershipGuard` 豁免 `/teams/*`。
- Swagger `@ApiTags('teams')` 分组展示 10 端点。
- 团队会话入口（task-team-chat-separation 已落地）：常驻团队会话页 `/teams/:id/session` 为团队唯一聊天入口（群聊 + teamMember 维度私聊 + 模型选择 + 成员管理 + 可拖拽面板 + Question/Issue/任务编辑/评审弹窗 + 右侧状态/配置/产出三 Tab + 队列/记忆卡片）；看板任务卡片点击改为任务详情抽屉（抽屉内“进入团队会话”按钮统一指向该路由），团队列表/详情的“进入会话”统一指向该路由；`/tasks/:id` 已剥离中央聊天区（仅保留任务详情 + 右侧面板 + 迁移提示横幅），深度编辑仍可跳该路由。

## 6. 迁移与回滚

同 15 篇 §8：expand 阶段新建 3 表 + 4 列 nullable 过渡（`tasks.team_id` / `chat_channels.team_id/team_member_id` / `sessions.team_member_id` / `messages.task_id`）+ `team_group` 与 `task_group` 双写兼容；contract 阶段 `tasks.team_id` 改 NOT NULL，`task_group` 逻辑下线（400）。回滚为重建库（`prisma migrate reset` 或 `docker compose down -v && up -d --build` + `migrate deploy` + `seed`）。

## 7. 开放问题

| # | 问题 | 现状 | 触发条件 |
|---|------|------|---------|
| ① | 队列拖拽重排 | 仅 FIFO，不支持拖拽重排；重排仅由晋升/取消触发 | 出现优先级插队诉求时评估 `position` 手动重排 + 队首保护 |
| ② | 团队间任务迁移 | 任务归属团队后不可改 `teamId` | 出现跨团队改派诉求时定义迁移 API 与队列重排语义 |
| ③ | 存量任务补数据 | 存量任务不补 `teamId`，新任务必填 | 存量归档后自然收敛，无需批量回填 |
