# 29 团队化改造 — 产品需求说明

> **面向对象**：产品 / 设计 / 运营 / 验收
> **版本**：v1.1（产品版）2026-09-01
> **状态**：已交付可用
> **一句话**：先建团队、再派任务；同一团队一次只做一件事，群聊按团队复用，默认保留上下文、可选“下一任务用新会话”。

---

## 1 背景与目标

### 1.1 之前怎么用
- 每建一个任务，就要重新挑一遍 Agent（产品经理、架构师、开发者、测试等），并自动新建一个群聊。
- 团队没有名字、不能被复用；相似任务要反复做同样的勾选。
- 同一个班子可以同时被派到多个任务，消息和历史被分散到多个群。

### 1.2 想要什么
1. **把团队变成可复用的对象**：给团队起名字，一次配好人，以后任务直接选团队。
2. **同一团队一次只做一件事**：避免班子被多任务并行打断；新任务自动排队，完成一个再做下一个。
3. **群聊跟着团队走**：同一团队的连续任务共用一个群，历史可回看、按任务分段。
4. **记忆可保留也可清空**：默认跨任务保留上下文，需要时为下一任务开启全新会话。

### 1.3 成功标准
- 管理员 1 分钟内建好一个团队并在列表中看到它。
- 用同一团队连续建 2 个任务：第一个可立即开始，第二个显示“排队中”，第一个完成后第二个自动可开始。
- 同一团队的两个任务共用一个群聊历史，且能按任务分段查看。
- 默认跨任务保留上下文；勾选后下一任务为全新上下文。

## 2 用户与场景

| 角色 | 诉求 |
|------|------|
| 项目管理员 | 沉淀固定班子，减少重复配置，统一成员与协作方式 |
| 任务发起人 | 选团队即可发起任务，清晰知道排队位置与何时可开始 |
| 团队成员（人） | 在统一群内与 Agent 协作，不因换任务而丢失上下文 |

**典型场景**
- **S1 沉淀班子**：管理员创建 `vteam开发团队`，加入产品/架构/开发者/测试，保存后团队出现在列表。
- **S2 连续派活**：发起人用同一团队建任务 A（可开始）→ 再建任务 B（排队中，显示第 1 位）→ 完成 A 后 B 自动可开始。
- **S3 协作不丢上下文**：在团队群内讨论任务 A，任务 B 仍能看到同一群的完整历史并按任务分段。
- **S4 需要全新开始**：对保密或需要隔离的任务，勾选“下一任务用新会话”，则下一任务为全新上下文。

## 3 功能概览

### 3.1 团队
- **创建团队**：起团队名（全平台唯一）、写简介、开关“默认保留上下文”、挑选成员（同一角色可添加多名，如开发者-1/开发者-2，可改别名与工作目录）。
- **查看与搜索**：列表分页、按名称搜索；卡片展示成员、当前任务、队列长度与保留开关。
- **编辑团队**：改名/简介/保留开关；增删改成员；删除仅在“空闲且队列为空”时可操作。
- **重置会话（可选）**：一键为下一任务开启全新会话。

### 3.2 任务与排队
- **选团队发起**：新建任务时改为下拉选团队（替代逐个选人），可预览团队成员，可勾选“完成后为下一任务开新会话”。
- **队内串行**：一团队一次只做一件事；忙时新任务显示“排队中”，并告知排队位置。
- **自动晋升**：当前任务完成/归档后，队首自动可开始；非队首不可提前开始。
- **取消排队**：仅“排队中”的任务可取消，取消后队列重排；不支持拖拽重排。
- **看板**：新增“排队中”筛选与徽章。

### 3.3 群聊与私聊
- **每团队一群**：同一团队的所有任务共享一个群聊；历史按任务分段展示，不再每任务建新群。
- **私聊按成员**：与某成员的私聊在同一团队内复用，跨任务可见（除非已为下一任务开新会话）。

### 3.4 上下文记忆
- **默认保留**：跨任务保留群聊与会话上下文，Agent 能基于前任务的知识继续协作。
- **可选清空**：团队默认保留；可在创建/编辑任务时勾选“下一任务用新会话”，或在团队详情一键重置；清空不影响已沉淀的知识库记忆。

## 4 页面与交互

| 页面 | 路径 | 核心交互 |
|------|------|----------|
| 团队列表 | `/teams` | 搜索、分页、新建入口；卡片显示成员/当前任务/队列/保留开关 |
| 团队新建 | `/teams/new` | 填写团队名/简介、保留开关、成员多实例配置（别名/工作目录） |
| 团队详情 | `/teams/[id]` | 行内改名/简介/开关；当前任务卡；队列列表（位置/标题/状态/入队时间 + 取消）；成员增删改；删除（仅空闲） |
| 任务新建 | `/tasks/new` | 下拉选团队（必选）+ 成员只读预览 + “下一任务用新会话”勾选 |
| 任务详情 | `/tasks/[id]` | 团队群聊（按团队聚合）、成员面板（来自团队）、队列状态卡（排队位置/队首高亮）、记忆状态卡（是否下一任务新会话） |
| 看板 | `/board` | 任务卡按状态筛选，新增“排队中” |

**导航**：侧边栏新增“团队”入口（需有查看权限），未登录访问自动跳登录。

## 5 详细规则

### 5.1 团队
- 团队名全平台唯一，重名提示冲突。
- 同一角色可添加多名成员，默认别名 `角色-序号`，工作目录自动生成。
- 删除团队：仅当“无当前任务且队列为空”时可删。

### 5.2 排队
- 活跃定义：`待开始/进行中/待验收` 算占用；`已完成/已归档` 算释放。
- 队首才可开始；非队首点击开始提示不可操作。
- 取消：仅 `排队中` 可取消，取消后队列自动重排为 1..N。

### 5.3 群聊
- 同一团队的群聊历史保留并按任务分段展示，切换任务不建新群。
- 私聊与成员一一对应，同一团队内跨任务复用。

### 5.4 记忆
- 默认：跨任务保留上下文；
- 勾选“下一任务用新会话”或关闭团队的“默认保留”后，下一任务为全新上下文，并有系统提示“已为下一任务开新会话”。

## 6 验收清单（按用户可感知的效果）

- [ ] 可创建名为 `vteam开发团队` 的团队并在列表中看到它；重名创建被阻止。
- [ ] 用同一团队建任务 A 可立即开始；再建任务 B 显示“排队中 第 1 位”。
- [ ] 完成任务 A 后，任务 B 自动变为可开始；非队首不可提前开始。
- [ ] 取消排队中的任务 B，队列正确重排。
- [ ] 同一团队的任务 A/B 共用一个群聊历史，且按任务分段可回看。
- [ ] 默认跨任务保留上下文；勾选“下一任务用新会话”后下一任务为全新上下文。
- [ ] 看板可按“排队中”筛选，团队管理三页（列表/新建/详情）可用，侧边栏“团队”入口可见。

---

## 7 边界与不做

- 团队内不支持并行多任务（坚持 FIFO 串行）。
- 首版团队为全平台可见，不做按项目隔离。
- 任务创建时不可同时改团队成员（成员仅在团队侧管理）。
- 不支持跨团队 @ 与跨团队会话复用。
- 不涉及计费/配额/审计等运营能力。
- 本次允许数据模型直接调整（不兼容旧数据）的上线方式。
