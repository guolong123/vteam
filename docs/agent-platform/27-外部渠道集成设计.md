# 27 外部渠道集成设计

> 状态：已实现（v2 拆分架构，message-channels inbound-only + notification-channels outbound-only）
> 关联：10 篇（群聊与消息机制）、08 篇（平台架构）、09 篇（API 设计）、13 篇（任务状态机）、21 篇（平台 MCP Server）、15 篇（数据模型 ER）
> 目标：通过双模型双适配器将外部渠道按「消息入站」与「通知出站」正交拆分，实现可插拔接入、fieldMapping 归一化、join-table 任务绑定与安全基线闭环。

---

## 1 概述

### 1.1 背景

v2 前的 `server/src/integrations` 为单模型 `IntegrationChannel(direction=in|out|inout)` + 单适配器 `ChannelAdapter(direction+send+verify)` 统一承载入站与出站，耦合方向开关与事件过滤，重构后按职责正交拆分为：

- **消息域 `message-channels`** — inbound-only，负责外部系统/IM 的入站归一化（webhook / 企微 aibot / GitHub / Gitee）→ 群聊 `post_message` 与审批 `card_action`。
- **通知域 `notifications`** — outbound-only，负责平台事件 `task.status_changed / agent.reply / agent.question` → 外部 webhook / 企微群机器人推送。

拆分收益：无 `direction` 字段、路由表独立（`TaskMessageChannel` / `TaskNotificationChannel`）、适配器契约单一、验证链路独立可演进。

### 1.2 设计原则

| 原则 | 说明 |
|------|------|
| 模型正交 | `MessageChannel` 仅入站，`NotificationChannel` 仅出站，零 direction 分支 |
| 适配器隔离 | `MessageAdapter` / `NotificationAdapter` 各自抽象，`MESSAGE_ADAPTERS` / `NOTIFICATION_ADAPTERS` Symbol 多提供者注入 |
| 宿主透传 | `MessageHost` / 通知侧无宿主（直连 Prisma + Registry），入站经 `MessageRegistry.bindInboundDelegate` 解耦循环 |
| join-table 绑定 | 任务与渠道 N:M 经 `TaskMessageChannel(taskId, messageChannelId)` 与 `TaskNotificationChannel(taskId, notificationChannelId)` 绑定 |
| 安全默认 | HMAC-SHA256 + 300s 窗口、externalId 唯一去重、secrets 遮蔽为基线 |
| 可观测 | `MessageDelivery(md_)` / `NotificationDelivery(nd_)` 每条投递独立记录，游标分页 |

### 1.3 术语

| 术语 | 含义 |
|------|------|
| MessageChannel | 消息渠道配置（`mc_`，`generic_webhook`/`wecom_aibot`/`github_webhook`/`gitee_webhook`，config 含 fieldMapping，secrets 含 HMAC secret） |
| NotificationChannel | 通知渠道配置（`nc_`，`webhook`/`wecom_group_robot`，config 含 targetUrl/events，secrets 含签名 secret） |
| MessageDelivery | 入站投递记录（`md_`，direction=inbound，status ok/failed/rejected/skipped） |
| NotificationDelivery | 出站投递记录（`nd_`，direction=outbound，status ok/failed/skipped） |
| fieldMapping | 入站字段模板 `{content, source, user}`，`{{ body.path }}` 渲染后拼 `text=[source] user: content` |
| join-table | 任务绑定关联表，替代旧 `IntegrationChannel.taskId` 单 FK |

## 2 双模型 ER

```
Task 1──* TaskMessageChannel *──1 MessageChannel 1──* MessageDelivery(md_)
     │
     └──* TaskNotificationChannel *──1 NotificationChannel 1──* NotificationDelivery(nd_)

ChatChannel(task_group) ◄── MessageInboundService.post_message (senderType=external)
AgentQuestion ◄── MessageInboundService.card_action / NotificationDispatcher.question_card
```

### 2.1 MessageChannel（`message_channels`，`mc_`）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | VarChar(32) | PK `mc_<n>` | 渠道 ID |
| name | VarChar(64) | — | 展示名 |
| type | VarChar(32) | `generic_webhook\|wecom_aibot\|github_webhook\|gitee_webhook` | 适配器类型 |
| config | Json | default `{}` | 含 `fieldMapping?`、`events?`、`lastChatid?` 等 |
| secrets | Json | default `{}` | `secret`/`botId` 等，读时遮蔽 |
| enabled | Boolean | default true | 总开关，禁用则入站 401 `CHANNEL_DISABLED` |
| lastStatus/lastError | VarChar | nullable | 运行时态 |
| createdAt/updatedAt | DateTime | auto | 时间 |

无 `direction`、`taskId` 列；任务关联经 `TaskMessageChannel`。

**config 示例**：

```json
// generic_webhook 入站
{ "fieldMapping": { "content": "{{ body.content }}", "source": "{{ body.repo }}", "user": "{{ body.sender.login }}" } }
// wecom_aibot 入站（运行时回写 lastChatid/lastChattype）
{ "lastChatid": "xxx", "lastChattype": "single" }
// github_webhook 入站（X-GitHub-Event 分支 + 自定义 fieldMapping 覆盖默认）
{ "fieldMapping": { "content": "{{ body.head_commit.message }}" } }
```

### 2.2 MessageDelivery（`message_deliveries`，`md_`）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | VarChar(32) | PK `md_<n>` | 投递 ID |
| channelId | VarChar(32) | FK MessageChannel CASCADE | 所属渠道 |
| externalId | VarChar(128) | nullable，`@@unique([channelId, externalId])` | 去重键（`x-vteam-event-id`/`msgid`/`sha1(rawBody)`） |
| direction | VarChar(8) | default `inbound` | 固定 inbound |
| status | VarChar(16) | `ok/failed/rejected/skipped/pending` | 终态 |
| kind | VarChar(32) | nullable | `post_message`/`card_action` |
| payload/meta | Json | nullable | 请求/响应摘要 |
| createdAt | DateTime | auto | 时间 |

索引：`@@index([channelId, createdAt])` 游标分页。

### 2.3 NotificationChannel（`notification_channels`，`nc_`）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | VarChar(32) | PK `nc_<n>` | 渠道 ID |
| name | VarChar(64) | — | 展示名 |
| type | VarChar(32) | `webhook\|wecom_group_robot` | 适配器类型 |
| config | Json | default `{}` | `targetUrl` + `events: ["task.status_changed","agent.reply","agent.question"]` |
| secrets | Json | default `{}` | `secret` 等 |
| enabled | Boolean | default true | 总开关 |
| lastStatus/lastError | VarChar | nullable | 运行时态 |

### 2.4 NotificationDelivery（`notification_deliveries`，`nd_`）

同 `MessageDelivery` 结构，`direction=outbound` 固定，`channelId` FK `NotificationChannel`。

### 2.5 绑定关联表

```prisma
model TaskMessageChannel {
  taskId           String  @map("task_id")
  messageChannelId String  @map("message_channel_id")
  task             Task    @relation(fields: [taskId], references: [id], onDelete: Cascade)
  messageChannel   MessageChannel @relation(fields: [messageChannelId], references: [id], onDelete: Cascade)
  @@id([taskId, messageChannelId])
  @@map("task_message_channels")
}
model TaskNotificationChannel {
  taskId                String @map("task_id")
  notificationChannelId String @map("notification_channel_id")
  task                  Task   @relation(fields: [taskId], references: [id], onDelete: Cascade)
  notificationChannel   NotificationChannel @relation(fields: [notificationChannelId], references: [id], onDelete: Cascade)
  @@id([taskId, notificationChannelId])
  @@map("task_notification_channels")
}
```

绑定经 `TasksModule` 的 `TaskChannelBindingsController`（`POST /tasks/:taskId/message-channels` / `notification-channels`）维护。

## 3 双适配器契约

### 3.1 MessageAdapter（inbound-only）

```typescript
export interface MessageChannelResolved {
  id: string; type: string; name?: string;
  config: Record<string, any>; secrets: Record<string, any>;
  enabled: boolean; lastStatus?: string | null; lastError?: string | null;
}
export interface MessageHost {
  submitInbound(channelId: string, commands: InboundCommand[]): Promise<{ results: Array<{ok:boolean; internalMessageId?:string}> }>;
  getChannel(id: string): Promise<MessageChannelResolved | null>;
  updateChannelRuntime(id: string, patch: { lastStatus?: string; lastError?: string; configMerge?: Record<string, any> }): Promise<void>;
  requestStop(channelId: string): Promise<void>;
  registerStreamCorrelation?(internalMessageId: string, ref: { channelId:string; frameHeaders:unknown; streamId:string }): void;
}
export type InboundCommand =
  | { kind:'post_message'; text:string; senderExternalId?:string; senderName?:string; dedupKey?:string }
  | { kind:'card_action'; aqId:string; action:string; operatorExternalId?:string };

export abstract class MessageAdapter {
  abstract readonly type: string;
  supportsInbound?: boolean;
  attach?(host: MessageHost): void;
  verifyInbound?(req:any, channel: MessageChannelResolved): Promise<void>;
  handleHandshake?(req:any, res:any, channel: MessageChannelResolved): Promise<boolean>;
  abstract normalizeInbound(req:any, channel: MessageChannelResolved): Promise<InboundCommand[]>;
  start?(ctx: MessageHost): Promise<void>;
  stop?(): Promise<void>;
  registerStreamCorrelation?(internalMessageId:string, ref:{channelId:string; frameHeaders:unknown; streamId:string}): void;
}
```

实现：`GenericWebhookInboundAdapter`（HMAC + fieldMapping）、`WecomAibotAdapter`（WS + placeholder 关联）、`GithubWebhookAdapter` / `GiteeWebhookAdapter`（事件分支 + X-Hub-Signature / fieldMapping）。

### 3.2 NotificationAdapter（outbound-only）

```typescript
export interface NotificationChannelResolved {
  id:string; type:string; name?:string;
  config: Record<string,any>; secrets: Record<string,any>; enabled:boolean;
}
export interface OutboundMessage { kind:'markdown'|'text'|'question_card'; title?:string; text:string; actions?:{key:string;label:string}[]; aqId?:string }
export abstract class NotificationAdapter {
  abstract readonly type: string;
  supportsOutbound?: boolean;
  abstract sendOutbound(channel: NotificationChannelResolved, msg: OutboundMessage): Promise<{ externalId:string|null; meta?:Record<string,any> }>;
}
```

实现：`WebhookNotificationAdapter`（HTTP POST + HMAC `x-vteam-signature`）、`WecomGroupRobotAdapter`（企微群机器人 webhook）。

### 3.3 注册表

- `MessageRegistryService`：`Map<type, MessageAdapter>`，`attach(host)` 注入，`onModuleInit` 调用 `adapter.start(host)`，`bindInboundDelegate(fn)` 供 `MessageInboundService` 回调。
- `NotificationRegistryService`：`Map<type, NotificationAdapter>`，仅 `get(type)`，无长连接。

## 4 入站链路（Inbound，含 fieldMapping）

```
外部系统 ──POST /api/v1/message-channels/:id/inbound──► MessageChannelsInboundController (@Public)
  Headers: x-vteam-signature (HMAC-SHA256), x-vteam-timestamp, x-vteam-event-id(optional)
  Body: rawBody Buffer（main.ts verify 注入 req.rawBody）
            │
            ▼ adapter.verifyInbound(rawBody, headers, channel.secrets)  // 验签 + 300s 窗口
            ▼ adapter.normalizeInbound(body, rawBody, channel)
              ├─ fieldMapping 存在 → renderFieldTemplate(content/source/user) → text=`[source] user: content`
              ├─ 无 mapping → body.text 回退（generic）
              └─ github/gitee → X-GitHub-Event / X-Gitee-Event 分支 + 自定义 mapping 覆盖默认
            ▼ MessageHost.submitInbound(channelId, commands)
            ▼ MessageInboundService
              - enabled/task 绑定校验（TaskMessageChannel 存在性）
              - dedup: delivery.tryBeginIngest(externalId=event-id|sha1(rawBody)|msgid)
              - post_message → chatService.createMessage(group, senderType=external)
              - card_action → questionsService.reply（校验 pending/TTL/kind）
              - wecom: registerStreamCorrelation(internalMessageId, {frameHeaders, streamId})
```

**fieldMapping 渲染**：`field-template.util.ts` `renderFieldTemplate(tpl, data)` 将 `{{ body.a.b }}` / `{{ body.commits[0].message }}` 按路径取值，缺失为空串；`GenericWebhookInboundAdapter` 在 `fieldMapping` 对象存在时强制走模板链路，否则回退 `body.text`。

## 5 出站链路（Outbound）

```
Realtime Bus (subscribe) Events: TASK_STATUS_CHANGED / AGENT_QUESTION / chat.message.new
            │ handle(event)
            ▼ NotificationDispatcherService
              - resolveChannelsForTask(taskId, eventType)
                → TaskNotificationChannel.findMany({taskId}) → NotificationChannel.findMany({id IN ids, enabled:true})
                → hasEvent(config.events, eventType) 过滤（空 events 视为不匹配，需显式订阅）
              - per-channel 串行队列 Map<channelId, Promise<void>>
              ▼ NotificationRegistry.get(type) → NotificationAdapter.sendOutbound(resolved, msg)
                ├─ webhook: POST config.targetUrl，HMAC x-vteam-signature=sha256(JSON.stringify({event,taskId,text}))
                └─ wecom_group_robot: POST 群机器人 webhook
              ▼ NotificationDelivery log/finish (pending→ok/failed)
辅助：MCP channel_send → NotificationDispatcher.sendToChannelByIdOrName(taskId, target(id|name), text)
      REST test-send → NotificationChannelsController 经 dispatcher 单发验证
      AGENT_QUESTION pending && !managedMode && hasQuestionEvent → per-channel queue → sendOutbound kind=text
```

## 6 任务绑定（join-table）

- 创建渠道：`POST /message-channels` / `POST /notification-channels`（`channels.manage` 权限，`secrets` 落库，返回遮蔽）。
- 绑定任务：`POST /tasks/:taskId/message-channels { messageChannelId }`、`POST /tasks/:taskId/notification-channels { notificationChannelId }`（`TaskChannelBindingsController`，校验渠道存在 + 去重）。
- 解绑：`DELETE /tasks/:taskId/message-channels/:channelId` 等。
- 列表：`GET /tasks/:taskId/message-channels` 返回绑定渠道详情（secrets 遮蔽）。
- 入站校验：`MessageInboundService` 收到 `submitInbound` 后查 `TaskMessageChannel` 是否存在绑定，无绑定则按全局放行（wecom 运行时 lastChatid 隐式关联）。
- 出站路由：`NotificationDispatcher.resolveChannelsForTask` 仅在 `TaskNotificationChannel` 绑定范围内选择渠道，未绑定任务的事件不推送。

## 7 安全基线

### 7.1 HMAC 签名 + 时间窗（入站）

| 项 | 规则 |
|----|------|
| 算法 | HMAC-SHA256，`sha256=<hex>`（小写） |
| 签名对象 | `rawBody` 原始字节（`express.json({verify:(req,_,buf)=>req.rawBody=buf})` 注入） |
| Header | `x-vteam-signature` 必传，`x-vteam-timestamp` 必传（秒级 Unix） |
| 时间窗 | `abs(nowSec - timestamp) <= 300s`，超窗 401 `SIGNATURE_INVALID` |
| 对比 | `timingSafeEqual` 等长对比 |
| 出站签名 | webhook 出站附加 `x-vteam-signature: sha256=<HMAC(bodyStr)>`，`bodyStr=JSON.stringify({event,taskId,text,title,ts})` |

### 7.2 去重与幂等

| 项 | 规则 |
|----|------|
| 去重键 | `x-vteam-event-id ?? sha1(rawBody)`（message 入站）；wecom `msgid`；通知侧 `externalId` 由适配器返回 |
| 约束 | `@@unique([channelId, externalId])`，`tryBeginIngest` 捕获 Prisma `P2002` 判 duplicate |
| 状态 | duplicate → `skipped/duplicate`，不重复落库 |
| 记录 | 每次 `tryBeginIngest/finish/log` 均落 `MessageDelivery/NotificationDelivery` |

### 7.3 敏感字段遮蔽

| 项 | 规则 |
|----|------|
| 存储 | `secrets` Json 明文存库（KMS 见 Roadmap） |
| 读取 | `GET` 列表/详情返回 `secrets: { "<key>": "***" }`（`maskSecrets`） |
| 更新 | `PATCH` 若值为 `***` 或空则忽略，不覆盖原值 |
| 日志 | `Delivery.payload/meta` 仅摘要，不落完整 secrets |

### 7.4 单 WS 守卫与限频（wecom_aibot）

- `Map<channelId, WSClient>` 单例，`start` 去重守卫；`stop` 清理。
- SDK `maxReconnectAttempts:-1`，连续 >3 次 `reconnecting` 上报 `runtime.lastError`。
- 企微 5s placeholder、`24h 窗口`、`30/min` 限频约束见旧 §7，入站已由消息域承载，出站由通知域无此窗口。

## 8 路由与权限

- 管理 REST：`MessageChannelsController` `@Controller('message-channels')`、`NotificationChannelsController` `@Controller('notification-channels')`，`channels.manage` 守卫（`PermissionGuard`），`GET` 列表/详情已登录可见，`POST/PATCH/DELETE/enable/disable/deliveries/test-send` 需 `channels.manage`。
- 入站公开：`MessageChannelsInboundController` `@Controller('message-channels')` `@Public()` `POST /:id/inbound`，`verifyInbound` 失败 401，channel 不存在/停用 404/401。
- 旧路由 `integrations/channels` 已删除（`server/src/integrations` 目录在 v2 移除，`grep -r integrations/channels --include=*.ts` 0 命中）。
- 方向字段：`MessageChannel` / `NotificationChannel` 均无 `direction` 列，`message-channels` 域 `grep direction` 仅 `DELIVERY_DIRECTIONS.inbound/outbound` 常量，无渠道方向字段。
