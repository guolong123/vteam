# 派发幂等与先查后派机制

## 1. 背景与问题

`tm_0000000002` 群聊实证：用户 m_521 一句“怎么样了”，PM 在**没查到**架构师 m_519 回执（“已完成第二轮评审，无需催办”，两分钟前发出）的前提下，直接 m_524 派计划员修订 + m_526 催办架构——后者是纯重复动作。PM 的“超时再点名一次”话术本身就没有幂等：同一事项可被派 N 次。

**根因一句话：派发动作无锁、无去重键，PM 提示词无“动手前先查状态”的强制步骤，被用户一催就凭印象动手。**

## 2. 目标与非目标

* 目标：同一事项在途时重复派发被拦并回显原记录；PM 被催促的标准动作是“先同步在途状态”，而不是“直接动手”。
* 非目标：不限制老师的明确重派指令（显式 `force` 可绕过，但须落原因）；不动任务状态机。

## 3. 详细设计

### 3.1 在途锁：复用 issue 状态机（不建新表）

* 约定：一切派活必须绑定一个 issue（派发词带 `issueId`；`notify_agent` 新增可选参数 `issueId`，缺省则按内容相似度提示、不硬拦，见 §3.3）。
* 派发前检查（`dispatchAgentMention` / `notifyAgent` 入口统一）：
  * issue 状态非 `open`（即 `in_progress` 等）**且**负责人未变 → 拒绝本次派发，返回 `{triggered: false, reason: 'duplicate', origMessageId}`（复用上轮修的 `triggered/reason` 返回，一点即通）。
  * issue 已 `resolved/closed` → 允许（视为新一轮，调用方应在派发词注明轮次）。
* 锁的释放：issue 流转到终态自动解；负责人变更视为新派发（需派发词写明改派原因）。

### 3.2 短窗去重键（防连击）

* 去重键 = `(fromInstanceId, toInstanceId, issueId ?? 内容hash前64)`，10 分钟窗口（内存 + 落库双记，重启不丢凭库表行，可复用 `message_receipts` 加 `dedupKey` 唯一索引，见 31 篇 §3.1）。
* 命中：不派发，直接返回上次成功记录 `{messageId, triggered}`。m_526 式“已回复后的催办”在这里被拦（结合 31 篇看板：无 pending 即无催办资格）。

### 3.3 PM 铁律（提示词，seed 落字）

1. **动手前先查**：任何派发/催办前必须先 `issue_get`（看状态与负责人）+ 翻最近 20 条群聊（看是否已有回执/在途）。跳过此步的派发视为违规操作。
2. **被催促标准动作**：用户说“怎么样了”时，第一步是报在途状态（谁在干、卡在哪、等谁、issue 号），第二步才是问“要不要加压”，**禁止直接动手**。m_529 式“已继续推进”改为“已同步状态，待你拍板”。
3. **催办格式**：必须引用原派发 `messageId` 与 issue，写清“这是第几次催办、上次是何时”。

### 3.4 chat_history 配合（31 篇 §3.4 同源，此处只定 PM 侧用法）

PM 查上下文必须用小步分页（`limit=20`，翻页追溯），禁止一次性拉全量后凭截断片段下结论；m_516 式“我查不到所以当没有”改为“我查不到所以挂起并上报盲区”。

## 4. 验收标准

1. 同一 `(PM→开发者, is_0000000002)` 10 分钟内第二次派发被拦，返回原 `messageId` + `reason=duplicate`。
2. issue 已 `in_progress` 时换词重派同样被拦（状态锁），换负责人才放行。
3. 老师显式 `force` 可绕过，且绕过记录带原因可审计。
4. 用户催促场景回归：PM 先报在途状态，不直接派发（抽查 m_521 式输入）。

## 5. 实施步骤

1. `notify_agent` 加可选 `issueId` 参数（schema + service 透传；缺省不硬拦，只在返回里标注 `issueBound: false` 提醒）。
2. `dispatchAgentMention` 入口加状态锁 + 去重窗检查（`message_receipts.dedupKey` 唯一索引，31 篇的表）。
3. PM/成员提示词补丁（seed）：铁律三条 + 催办格式。
4. 单测：在途锁（同负责人拦/换人放/终态放）、去重窗（连击拦/过期放/force 过）、返回体 `reason=duplicate`。
5. 与 31 篇联调：无 pending 即无催办资格的端到端用例。
