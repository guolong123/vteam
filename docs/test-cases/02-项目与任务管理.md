# 项目与任务管理测试用例

## 1. 模块范围与环境

本文档覆盖两个模块：**项目管理（Projects）**、**任务管理（Tasks）**，对应需求 `docs/agent-platform/03-功能需求-任务与群聊协作.md` 的 FR-01~08（任务创建 / 虚拟团队 / 状态机 / 验收 / 归档 / 背景文档 / 启动 / 主 Agent）与 FR-25（项目生命周期）、`13-任务状态机与全生命周期.md`（五态状态机 / 迁移动作 / 验收 / 归档）、`06-交互与页面设计.md` §2.2/§2.3/§2.4/§2.7/§3.4、`09-API设计.md` §3.3/§3.4。

**测试环境**

| 项 | 值 |
|----|----|
| Web 入口 | http://192.168.10.78:13001 |
| API 入口 | http://192.168.10.78:13000/api/v1 |
| 管理员 | `admin` / `admin123`（角色 admin，`permissions: {all:true}`） |
| 成员（非项目成员） | `tc_member` / `Tcmember@123`（`auth/register` 注册，默认 member 角色、无项目归属） |
| 认证方式 | JWT Bearer；access token 默认 2h，refresh token 默认 7d |
| 预置 Agent | `a_product`（产品经理）、`a_architect`（架构师）、`a_developer`（开发者）、`a_tester`（测试） |

**冒烟命令**（登录拿 token 后用于 API 用例）：

```bash
curl -X POST http://192.168.10.78:13000/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin123"}'
# 返回 {accessToken, refreshToken, user}
```

**实现与需求差异说明**（用例预期均以**实际实现为准**，已在上线环境实测确认）：

1. **状态迁移端点返回 `201` 而非文档所述 `200`**：`09 §2.1` 写「已处目标态返回 200」，实际实现所有 POST 端点（含幂等重复请求）均返回 `201`（NestJS POST 默认状态码），幂等不重复产生 `task_events`。用例统一按 `201` 编写。
2. **单 Agent 任务也必须显式指定主 Agent**：`FR-07/08` 与 `13 §4.2` 写「仅选一个 Agent 的简单任务无需额外指定主 Agent，该 Agent 即主 Agent」；实际实现 `start` 前置校验 `mainAgentId` 必须非空，未指定返回 `400 MAIN_AGENT_NOT_SET`（已实测）。用例按实现编写并在 `TC-TASK-037` 标注。
3. **项目不存在时任务列表返回 `403` 而非 `404`**：`ProjectMembershipGuard` 对 `/projects/:pid/tasks` 路由直接取 `pid` 校验 `project_members`，项目不存在时成员记录也不存在 → `403 PERMISSION_PROJECT_NOT_MEMBER`（已实测）。
4. **`agentIds` 含重复值导致 `500`**：实现未做去重，`task_agents` / `sessions` 的 `@@unique(taskId, agentId)` 约束冲突抛出 500（已实测）。需先修正去重，用例 `TC-TASK-009` 按当前行为编写。
5. **`GET /projects` 实现仅返回调用者已加入的项目**：`09 §3.3` 写「管理员可见全部」，实际实现按 `project_members` 过滤，admin 也须为该项目的成员（owner 也是 member）。用例 `TC-PRJ-011` 按实现编写。
6. **项目管理端点仅实现列表与创建**：`09 §3.3` 的 `GET/PATCH /projects/:id`、`POST /projects/:id/members`、`DELETE /projects/:id/members/:userId` 在控制器中**未实现**（Phase 2），不在本用例范围。
7. **背景文档无独立上传端点**：`09 §3.4` 的 `POST /tasks/:id/background-docs`（multipart）**未实现**，背景文档通过创建请求 `backgroundDocs[]` 字段传入（FR-06 的「背景文档入文档库」按元数据记录）。
8. **状态机五态枚举与 13 篇一致**：`pending / in_progress / pending_review / completed / archived`，迁移表 `start / mark-pending-review / accept / reject / archive` 与 `13 §3.2` 一致，无差异。

**状态迁移汇总**（服务端校验，非法迁移 409 `TASK_INVALID_TRANSITION`，details 含 `{from, to, current}`）：

```
待开始 ──start──▶ 进行中 ──mark-pending-review──▶ 待验收 ──accept──▶ 已完成 ──archive──▶ 已归档
                        ▲                            │
                        └──────── reject ────────────┘
```
