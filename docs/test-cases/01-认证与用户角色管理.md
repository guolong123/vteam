# 认证与用户角色管理测试用例

## 1. 模块范围与环境

本文档覆盖三个模块：**认证（Auth）**、**用户管理（Users）**、**角色与权限（Roles）**，对应需求 `docs/agent-platform/03-功能需求-任务与群聊协作.md` 的 FR-22/23/24、`06-交互与页面设计.md` §2.1/§2.9/§2.10、`09-API设计.md` §3.1/§3.2/§3.10，以及 `17-仓库权限与凭证机制.md` 的权限边界约定。

**测试环境**

| 项 | 值 |
|----|----|
| Web 入口 | http://192.168.10.78:13001 |
| API 入口 | http://192.168.10.78:13000/api/v1 |
| 管理员 | `admin` / `admin123`（角色 admin，`permissions: {all:true}`） |
| Seed 管理员 | `seed-admin` / `Admin@123456` |
| Seed 成员 | `seed-member` / `Admin@123456`（角色 member，`permissions: {all:false}`） |
| 认证方式 | JWT Bearer；access token 默认 2h，refresh token 默认 7d |
| 预置角色 | `admin`（isBuiltin=true，`{all:true}`）、`member`（isBuiltin=true，`{all:false}`） |

**冒烟命令**（登录拿 token 后用于 API 用例）：

```bash
curl -X POST http://192.168.10.78:13000/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin123"}'
# 返回 {accessToken, refreshToken, user}
```

**实现与需求差异说明**（用例预期均以**实际实现为准**，已在上线环境验证）：

1. `09 §3.1` Auth 端点表仅收录 register/login/refresh，**实际实现另有** `POST /auth/forgot-password`、`POST /auth/reset-password`、`GET /auth/profile`。
2. **找回密码无验证码/邮件**：需求侧提及「验证码流程」，实际实现为 `forgot-password` 直接返回一次性 `resetToken`（hex32，有效期 30 分钟），无邮件服务，token 内网手动传递。用例按此编写。
3. `09 §3.2` 的 `POST /users`、`PATCH /users/:id` 请求要点含 `projectIds[]`，**实际实现 DTO 不含 projectIds**（项目归属分配未纳入用户管理接口）；`GET /users/:id` 标注「本人可查自己」，实际实现挂 `AdminGuard`，仅管理员可查。
4. `09 §3.10` 的 `GET /roles` 文档标注分页，实际实现**返回全量角色数组（无分页）**；`GET /roles/:id`、`GET /permission-scopes` 两端点**文档存在但未实现**，不在本用例范围。
5. `09 §3.10` `DELETE /roles/:id` 预置角色文档标注 409 `ROLE_BUILTIN_IMMUTABLE`，实际实现返回 **403 `FORBIDDEN_BUILTIN_ROLE`**；删除成功返回 200 + `{deleted:true, id}`（非 204）。
6. `09 §3.10` `POST /roles` 的 `scopes` 文档为数组，实际实现为**对象** `{ global, projects, innerRoles }`。
7. 禁用用户后**已有 access token 访问 users/roles 等 AdminGuard 端点返回 401**（AdminGuard 实时查库校验 enabled）；访问 `/auth/profile` 仅验签不查启用态，仍返回资料。

**权限判定说明**：users/roles 全部端点挂 `AdminGuard`（`permissions.all===true` 或 `permissions.users.manage===true` 放行，否则 403 `FORBIDDEN_ADMIN`）；未认证/用户被禁用返回 401 `AUTH_UNAUTHORIZED`。全局 `JwtAuthGuard` 仅接受 `type=access` 的 token，refresh token 冒用一律 401。

## 3. 用户管理模块用例（TC-USER）

> users 全部端点挂 `AdminGuard`：非管理员访问返回 403 `FORBIDDEN_ADMIN`；未认证/账号被禁用返回 401 `AUTH_UNAUTHORIZED`。所有响应对象**不含 password_hash**。以下 API 用例默认前置条件为「已用 `admin`/`admin123` 登录获得 admin accessToken」；创建/禁用/重置等用例执行后建议清理测试数据。

## 4. 角色与权限模块用例（TC-ROLE）

> roles 全部端点挂 `AdminGuard`（同 users）。权限矩阵为 8 资源（tasks/chats/artifacts/agents/workers/skills/users/roles）× 6 操作（view/create/edit/delete/review/manage）。预置角色 `admin`/`member`（isBuiltin=true）**只读**，PATCH/DELETE 返回 403 `FORBIDDEN_BUILTIN_ROLE`。

### 4.1 正向用例

| 用例编号 | 用例名称 | 用例类型 | 优先级 | 前置条件 | 操作步骤 | 预期结果 |
|---------|---------|---------|-------|---------|---------|---------|
| TC-ROLE-001 | 角色列表返回预置与自定义角色 | 正向 | P0 | admin accessToken | 1. `GET /api/v1/roles` | 1. 返回 `200 OK`，为角色数组（无分页）<br>2. 至少包含 `admin`（permissions `{all:true}`，isBuiltin=true）与 `member`（permissions `{all:false}`，isBuiltin=true）<br>3. 每项含 id/name/permissions/scopes/isBuiltin/时间戳 |
| TC-ROLE-002 | 创建自定义角色 | 正向 | P0 | admin accessToken | 1. `POST /api/v1/roles`，body：`{"name":"reviewer_<ts>","permissions":{"tasks":{"view":true,"create":true,"edit":false,"delete":false,"review":true,"manage":false},"users":{"view":false,"manage":false}},"scopes":{"global":false,"projects":[],"innerRoles":[]}}` | 1. 返回 `201 Created`，角色对象 `isBuiltin=false`，permissions/scopes 与提交一致<br>2. `GET /roles` 列表中出现该角色 |

| TC-ROLE-006 | 角色与权限页功能走查（Web） | 正向 | P0 | 浏览器可用 `admin`/`admin123` 登录 | 1. 登录后进入「用户管理」→「权限配置」<br>2. 查看左侧角色列表（预置 admin/member + 自定义角色）<br>3. 点击角色切换，查看右侧权限矩阵（8 资源 × 6 操作，✓/◐/✗）<br>4. 切换权限范围（全局/指定项目/项目内角色）<br>5. 查看底部「平台权限与 opencode 权限相互独立」边界说明 | 1. 角色切换时右侧面板随之更新（FR-23）<br>2. 权限矩阵格值可编辑并保存（FR-23）<br>3. 权限范围支持三种形态且随角色切换重置（FR-24）<br>4. 底部展示平台权限与 opencode 权限边界（FR-23 边界） |

## 5. 用例汇总

**覆盖端点清单**（均为 `/api/v1` 前缀，含 API 与 Web 页面）：

- Auth（6 端点）：`POST /auth/register`、`POST /auth/login`、`POST /auth/refresh`、`POST /auth/forgot-password`、`POST /auth/reset-password`、`GET /auth/profile`
- Users（6 端点）：`POST /users`、`GET /users`、`GET /users/:id`、`PATCH /users/:id/status`、`PATCH /users/:id`、`POST /users/:id/reset-password`
- Roles（4 端点）：`GET /roles`、`POST /roles`、`PATCH /roles/:id`、`DELETE /roles/:id`
- Web 页面（3 页）：登录页（§2.1）、用户管理页（§2.9）、角色与权限页（§2.10）

**反向覆盖维度**：参数缺失/格式非法（400）、账号已存在（409）、资源不存在（404）、密码错误/用户不存在防枚举（401 同码）、token 无效/过期/伪造/refresh 冒用（401）、未认证访问（401）、非管理员越权（403）、禁用用户登录（401 AUTH_DISABLED）、禁用用户访问管理端点（401）、重置 token 失效与复用（401）、预置角色只读（403）、被引用角色删除（409）、refresh token 复用边界（401）等，均已覆盖。
