# 群聊与实时通信测试用例

## 1. 测试范围与环境

本文档覆盖 Agent 协作平台「群聊/私聊」与「实时通信（SSE）」两大模块的功能测试用例，依据 `docs/agent-platform/` 下的需求文档（03 篇 FR-09~21、06 篇 §2.5/§2.6/§3.1/§3.2、09 篇 §3.5/§4、10 篇全篇）与 `server/src/chat/`、`server/src/realtime/` 实现编写，参考 `20-E2E验证问题清单.md`（P1/P4/P6/P7 已修复点）作为反向用例与边界用例来源。

**测试环境：**

| 项 | 值 |
|----|----|
| API 入口 | http://192.168.10.78:13000/api/v1 |
| Web 入口 | http://192.168.10.78:13001 |
| 管理员账号 | `admin` / `admin123` |
| 认证方式 | `Authorization: Bearer <accessToken>`；登录 `POST /auth/login` 请求体 `{"username":"admin","password":"admin123"}` |
| SSE 鉴权 | query 参数 `?token=<jwt>`（EventSource 无法携带 Header），须为 **access** token |
| 测试隔离 | 用例数据使用**新建测试任务/测试频道**验证，验证后删除（soft delete），不在线上真实频道批量灌消息 |

**功能点映射（FR → 用例）：** FR-09 任务群聊 → TC-CHAT-001/003；FR-10 消息模型 → TC-CHAT-006/007/004/005；FR-11 定向 @ → TC-CHAT-008/009；FR-12 @all → TC-CHAT-010；FR-13 Agent 互 @ → TC-CHAT-010 注；FR-14 私聊群聊共用会话 → TC-CHAT-012~015；FR-15 上下文注入 → TC-CHAT-015/041；FR-17 实时查看 → TC-RT-003；FR-19 消息持久化 → TC-CHAT-004/005/020；FR-20 Loading → TC-RT-003；FR-21 错误反馈 → TC-RT-007/TC-CHAT-029 注。

## 2. 实现确认与需求差异标注

> 以下为**以代码实现为准**的确认结果。凡与需求文档描述存在出入处，均在此标注，用例预期按实现行为编写。

| 项 | 需求文档描述 | 代码实现（事实） | 用例处理 |
|----|-------------|----------------|---------|
| 消息发送者三态 | `senderType` = user/agent/system | 一致（`event.constants.ts` SENDER_TYPE） | 按实现断言 |
| 消息状态机 | sending→sent；pending→processing→completed/failed | 一致（MESSAGE_STATUS 含 sending/sent/pending/processing/completed/failed）；用户消息落库即 `sent`，Agent 回复经回流终态化 | 按实现断言 |
| 频道类型 | task_group（任务群聊）/ private（私聊） | 一致（CHANNEL_TYPE） | 一致 |
| @ 提及语法 | 正文书写 `@产品经理`/`@all`，前端解析为 `mentions` 数组 | 实现按 DTO 提交 `mentions` 数组（`{type:'agent',agentId}` 或 `{type:'all'}`），服务端二次校验 | 一致 |
| @ 触发结果 | triggers: dispatched / no_session / agent_removed | 一致；agent 不在团队 → 400 `MENTION_AGENT_NOT_IN_TEAM`；type 非法 → 400 `MENTION_TYPE_INVALID` | 一致 |
| ACK 收到确认 | 需求未显式列出 | 实现：@ 分派后立即为每个 dispatched 目标落库 agent「收到，正在处理…」消息（`agent.ackMessage` 可配，默认 `DEFAULT_ACK_MESSAGE`） | 按实现补充正向用例 |
| 消息删除端点 | 需求：消息不支持撤回/编辑，无 DELETE | 一致：仅频道有 `DELETE /channels/:id`（soft delete），消息无删除端点 | 按实现断言 |
| SSE 事件帧格式 | 09 §4.1：`event: <type>` + `data:{id,type,data,timestamp}` | **差异**：实现输出 SSE 帧 `id` + `data:{id,type,payload,timestamp}`（字段名为 `payload` 非 `data`，type 在 JSON 内、不输出 `event:` 行，EventSource 以默认 message 事件派发；心跳帧 type='heartbeat'） | 用例按**实现**帧格式断言 |
| SSE scope 取值 | task:\<id\> / channel:\<id\>，不传=global 广播 | **扩展**：另支持 `all`（全量订阅但仅收调用者成员项目事件）、逗号分隔多 scope 合并、`since` 补拉、`since=latest` 跳过历史 | 用例按实现扩展断言 |
| 私聊频道幂等 | 09 §3.5 仅「创建私聊频道」 | **补充**：`task_id+agent_id` 唯一键，重复创建返回已有频道（幂等）；已 soft delete 的私聊频道重复创建会**复活**（deletedAt 置空） | 按实现补充用例 |
| 归档任务频道发消息 | 10 §9：归档后仅可查看 | 实现：`POST /channels/:id/messages` 对归档任务频道返回 409 `TASK_ARCHIVED` | 一致 |
| Agent 错误反馈 | FR-21：错误以消息形式反馈 | 实现：`agent.error` SSE 事件 + 频道内该 Agent 最新 processing 消息标记 `failed` 落库并广播 `chat.message.new`（status=failed）；watchdog 首字超时（默认 60s）/空闲判死（默认 30min）触发 | 按实现编写 |
| 上下文注入 | FR-15：注入群聊历史 + 文档库 | 实现：`<doclib>` 块 + `[群聊历史消息]` 前缀注入 prompt 前，单文档/历史各 32KB 上限、doclib 总量 128KB 上限；P1/P6 修复后注入内容不再拼进回复文本，前端剥离 `<doclib>` 与 `[群聊历史消息]` | 按实现编写边界用例 |
| 群聊/私聊 parts | 群聊不渲染过程片段（FR-18） | 实现：task_group 仅保留结论性 text part（`extractConclusionParts`），private 保留全量 parts | 按实现断言 |

**用例修正记录（2026-08-10）：**
1. `TC-CHAT-022`：原预期「空串 `type=` 等同未传返回全量列表」，实际 `chat.service.ts` `findAccessibleChannels` 显式校验空串为非法枚举 → `400 CHANNEL_TYPE_INVALID`（仅 `undefined` 等同未传），已修正。
2. `TC-CHAT-043`：原预期「未 start 的任务 @ Agent → no_session」，实际 `tasks.service.ts` 创建任务事务内为每个团队 Agent eager 创建会话（status=created，防 M2 验收阻断），@ 直接 `dispatched`；`no_session` 仅在会话行缺失（如被清除）时出现，已修正。

**已知环境状态（2026-08-10 部署）：** 任务群聊与私聊频道均为 `c_<序号>`，消息为 `m_<序号>`（id 数值序即字典序，兼作历史游标与 SSE 事件游标同源）；预置 Agent 含 `a_product` 产品经理 / `a_architect` 架构师 / `a_developer` 开发者 / `a_tester` 测试。用例前置条件中的数据（项目/任务/频道/Agent）可按环境实际值替换。

## 3. 群聊与私聊用例（TC-CHAT）

### TC-CHAT-001 可访问频道列表（任务群聊+私聊全量）
- **用例类型**：正向　**优先级**：P0
- **前置条件**：admin 已登录获得 accessToken；admin 至少加入一个含任务的项目，该项目已创建任务（自动生成 task_group 频道）或已有私聊频道
- **操作步骤**：
  1. `GET /api/v1/channels`，Header `Authorization: Bearer <accessToken>`
- **预期结果**：200；响应 `{items:[...], total}`；items 中同时含 `type=task_group`（任务群聊）与 `type=private`（私聊）频道；每项含 `id/type/taskId/agentId/pinned/lastReadAt/task{id,title,status,projectId}/createdAt`；不含已删除（deletedAt 非空）频道；排序按 `pinned desc, createdAt desc`（置顶优先）

### TC-CHAT-002 频道列表按类型过滤
- **用例类型**：正向　**优先级**：P1
- **前置条件**：同 TC-CHAT-001
- **操作步骤**：
  1. `GET /api/v1/channels?type=private`
  2. `GET /api/v1/channels?type=task_group`
- **预期结果**：步骤 1 返回的 items 全部 `type=private`；步骤 2 返回的 items 全部 `type=task_group`；total 与 items 数量一致

### TC-CHAT-003 频道详情（关联任务与 Agent 成员）
- **用例类型**：正向　**优先级**：P0
- **前置条件**：admin 可访问某 task_group 频道 `c_group`（其任务已选入 2 个以上 Agent）
- **操作步骤**：
  1. `GET /api/v1/channels/c_group`
- **预期结果**：200；响应含 `id/type=task_group/taskId`；`agentMembers` 为任务虚拟团队内**未移除**（removedAt=null）的 Agent 数组，每项含 `id/name/role`；不含已移除 Agent

### TC-CHAT-004 消息历史第一页（FR-19 持久化）
- **用例类型**：正向　**优先级**：P0
- **前置条件**：admin 可访问频道 `c_group`，频道内有 ≥3 条历史消息（用户/Agent/系统消息混合）
- **操作步骤**：
  1. `GET /api/v1/channels/c_group/messages`（不传 cursor/limit）
  2. `GET /api/v1/channels/c_group/messages?limit=2`
- **预期结果**：200；响应 `{items:[...], nextCursor}`；items 按 `id` 升序（最早 limit 条）；每条含 `id/channelId/senderType/senderId/content{text,parts}/mentions/status/createdAt`；senderType 覆盖 `user/agent/system` 三类；limit=2 时 items 长度 2 且 nextCursor=第 2 条 id；历史消息在任务归档后仍可查询（FR-19/05）

### TC-CHAT-005 消息历史游标翻页
- **用例类型**：正向　**优先级**：P0
- **前置条件**：频道 `c_group` 内有 ≥5 条消息
- **操作步骤**：
  1. `GET /api/v1/channels/c_group/messages?limit=2`，记下响应 `nextCursor`
  2. `GET /api/v1/channels/c_group/messages?limit=2&cursor=<nextCursor>`
  3. 继续翻页直至 `nextCursor=null`
- **预期结果**：每页 items 严格接续上一页（id 递增、无重复无遗漏）；游标=上页最后一条消息 id；末页 nextCursor=null；翻页完整覆盖频道全部消息（持久化可全量追溯）

### TC-CHAT-006 发普通消息（无 @ 触发）
- **用例类型**：正向　**优先级**：P0
- **前置条件**：admin 可访问 `c_group`；任务未归档
- **操作步骤**：
  1. `POST /api/v1/channels/c_group/messages`，Body：`{"text":"大家好，这里是任务群聊"}`，Header Bearer
- **预期结果**：201；响应 `{message:{id,channelId,senderType:"user",senderId:"u_admin",content:{text,parts:[]},mentions:[],status:"sent",createdAt}, triggers:[]}`；triggers 为空（无 @ 不触发 Agent）；该消息可在历史中查到；频道订阅者收到 `chat.message.new`（见 TC-RT-002）

### TC-CHAT-007 发消息携带附件
- **用例类型**：正向　**优先级**：P1
- **前置条件**：先经 `POST /api/v1/uploads`（multipart）上传文件获得 `{url,name,size,ext}`；admin 可访问 `c_group`
- **操作步骤**：
  1. `POST /api/v1/channels/c_group/messages`，Body：`{"text":"附件文档","attachmentUrl":"/uploads/<uuid>.png","attachmentName":"截图.png","attachmentType":"png"}`
- **预期结果**：201；message 含 `attachmentUrl/attachmentName/attachmentType` 三字段；历史查询 `GET /channels/c_group/messages` 返回的消息同样携带附件三字段；Web 端渲染为附件卡片（可预览/下载）

### TC-CHAT-008 @ 定向触发单个 Agent（FR-11）+ ACK + Loading + 回复
- **用例类型**：正向　**优先级**：P0
- **前置条件**：任务团队含 `a_product` 且会话已创建（任务已开始）；worker 在线
- **操作步骤**：
  1. `POST /api/v1/channels/c_group/messages`，Body：`{"text":"@产品经理 请输出需求文档","mentions":[{"type":"agent","agentId":"a_product"}]}`
  2. 立即（分派后）查询历史；随后等待 Agent 处理
- **预期结果**：201；`message.senderType=user`；`triggers=[{agentId:"a_product",sessionId:<sid>,status:"dispatched"}]`；① 立即查询可见 agent「收到，正在处理…」消息（senderType=agent，senderId=a_product，ACK，mentions=null 不递归触发）；② SSE 收到 `agent.loading`（phase=thinking，随后 operating，见 TC-RT-003）；③ Agent 回复落库后 `chat.message.new`（senderType=agent）替代 Loading；④ 未被 @ 的其他 Agent 无任何响应（FR-11 谁被 @ 谁处理）

### TC-CHAT-009 @ 多个 Agent 定向触发
- **用例类型**：正向　**优先级**：P0
- **前置条件**：任务团队含 `a_product`、`a_developer`
- **操作步骤**：
  1. `POST /api/v1/channels/c_group/messages`，Body：`{"text":"@产品经理 @开发者 请协作完成","mentions":[{"type":"agent","agentId":"a_product"},{"type":"agent","agentId":"a_developer"}]}`
- **预期结果**：201；triggers 含 2 个 dispatched 目标（两个 Agent 均触发）；两个 Agent 均收到并各自回复；其余未 @ Agent 静默

### TC-CHAT-010 @all 广播（FR-12）
- **用例类型**：正向　**优先级**：P0
- **前置条件**：任务团队含 ≥2 个未移除 Agent
- **操作步骤**：
  1. `POST /api/v1/channels/c_group/messages`，Body：`{"text":"@all 请全体知悉","mentions":[{"type":"all"}]}`
  2. 查询该消息历史与 trigger-results
- **预期结果**：201；triggers 展开为当前团队**全部未移除** Agent，各状态为 dispatched；每个 Agent 均收到并回复；落库的 message.mentions 保持 `{"type":"all"}` 原样存储；被移除 Agent 不参与 @all 展开（FR-12）

### TC-CHAT-011 @ 触发结果轮询（SSE 兜底）
- **用例类型**：正向　**优先级**：P0
- **前置条件**：频道内有用户消息 `m_user`，其中 @ 了 `a_product`
- **操作步骤**：
  1. `GET /api/v1/channels/c_group/trigger-results/m_user`
  2. Agent 回复完成后再次调用同接口
- **预期结果**：200；响应 `{triggers:[{agentId,status:"dispatched",replyMessageId?}]}`；Agent 回复落库后 replyMessageId 为该 Agent 于原消息之后的第一条回复消息 id（id 升序取最早）；@all 消息返回全部被触发 Agent 的 trigger 条目

### TC-CHAT-012 创建私聊频道（FR-14）
- **用例类型**：正向　**优先级**：P0
- **前置条件**：任务 `t_1` 存在且 admin 为其项目成员；Agent `a_architect` 在团队内
- **操作步骤**：
  1. `POST /api/v1/dm-channels`，Body：`{"taskId":"t_1","agentId":"a_architect"}`
  2. `GET /api/v1/channels` 查看新频道
- **预期结果**：201；返回频道对象 `{id,type:"private",taskId:"t_1",agentId:"a_architect",...}`；`GET /channels` 中出现该 private 频道；与群聊**共用该 Agent 的任务会话**（FR-14）

### TC-CHAT-013 私聊频道重复创建幂等
- **用例类型**：正向　**优先级**：P1
- **前置条件**：已存在 `t_1` + `a_architect` 的 private 频道
- **操作步骤**：
  1. 再次 `POST /api/v1/dm-channels`，Body 同 TC-CHAT-012
- **预期结果**：201；返回**已有频道**（id 不变，不重复创建，符合 uk_channels_task_agent 唯一约束）

### TC-CHAT-014 私聊发消息（无需 @）
- **用例类型**：正向　**优先级**：P0
- **前置条件**：private 频道 `c_dm`（t_1 × a_architect）存在
- **操作步骤**：
  1. `POST /api/v1/channels/c_dm/messages`，Body：`{"text":"单独讨论架构方案"}`（不带 mentions）
- **预期结果**：201；消息落库到 private 频道；`triggers=[]`（私聊按实现当前不自动触发分派，仅消息进入会话上下文，供后续群聊 @ 时经 FR-15 注入）；私聊历史经 `GET /channels/c_dm/messages` 按 channelId 隔离查询

### TC-CHAT-015 群聊/私聊共用会话上下文连续（FR-14）
- **用例类型**：正向　**优先级**：P0
- **前置条件**：任务 `t_1` 团队含 `a_developer`；会话已创建；worker 在线
- **操作步骤**：
  1. 在群聊 `c_group` 发 `{"text":"@开发者 背景：我们做英语小程序","mentions":[{"type":"agent","agentId":"a_developer"}]}`
  2. 等 Agent 回复完成后，在私聊 `c_dm` 发 `{"text":"@开发者 继续刚才的话题，请总结要点","mentions":[{"type":"agent","agentId":"a_developer"}]}`
  3. 验证第二步 Agent 回复
- **预期结果**：步骤 1/2 命中**同一 sessionId**（taskId×agentId 唯一会话，uk_sessions_task_agent）；步骤 2 的回复能引用步骤 1 的背景上下文（上下文连续，不因入口不同失忆，FR-14/15）；Agent 回复各自回流到**触发来源频道**（群聊 @ 回流群聊，私聊 @ 回流私聊）

### TC-CHAT-016 置顶/取消置顶频道（UX-09）

### TC-CHAT-018 删除会话（soft delete）与私聊复活
- **用例类型**：正向　**优先级**：P1

## 4. 实时通信（SSE）用例（TC-RT）

> 统一 SSE 端点：`GET /api/v1/events?token=<accessToken>&scope=<scope>&since=<eventId>`。订阅方式：SSE（EventSource 兼容，text/event-stream）。**以代码实现为准**的事件帧格式（见 §2）：SSE 帧 `id:<递增事件id>` + `data:{id,type,payload,timestamp}`（业务 type 在 data.type 内）；心跳帧 type='heartbeat'（每 15s，仅保活）。`curl -N` 可限时观察事件流。

### TC-RT-001 SSE 连接建立与心跳保活
- **用例类型**：正向　**优先级**：P0
- **前置条件**：admin 已登录获得 accessToken；`curl -N http://192.168.10.78:13000/api/v1/events?token=<accessToken>&scope=all`
- **操作步骤**：
  1. 建立 SSE 连接（scope=all），保持 20s 观察
- **预期结果**：HTTP 200、`Content-Type: text/event-stream`；连接建立即推送已落库事件（或空）；每 15s 收到 `type=heartbeat` 心跳帧 `data:{id:null,type:"heartbeat",payload:null,timestamp}`（保活防中间件超时断连）；连接不中断

### TC-RT-002 channel scope 订阅收到 chat.message.new
- **用例类型**：正向　**优先级**：P0
- **前置条件**：admin 已登录；另一终端持有 accessToken；目标频道 `c_group`
- **操作步骤**：
  1. 终端 A：`curl -N "http://192.168.10.78:13000/api/v1/events?token=<t>&scope=channel:c_group&since=latest"`
  2. 终端 B：`POST /api/v1/channels/c_group/messages`，Body `{"text":"SSE 测试消息"}`
  3. 终端 A 观察事件流
- **预期结果**：终端 A 收到 `data:{type:"chat.message.new", payload:{message:{id,channelId:"c_group",senderType:"user",content:{text:"SSE 测试消息",...},mentions:[],status:"sent",createdAt}}}`；消息 id 即 SSE 帧 id 同源（先落库后广播）；仅订阅 channel:c_group 的连接收到，其他 scope 连接不受影响

### TC-RT-003 task scope 订阅收到 agent.loading 两阶段（FR-20）
- **用例类型**：正向　**优先级**：P0
- **前置条件**：任务 `t_1` 进行中、Agent `a_product` 会话已创建；worker 在线；终端 A 订阅 `scope=task:t_1&since=latest`
- **操作步骤**：
  1. 终端 A 建立 `GET /events?token=<t>&scope=task:t_1&since=latest`
  2. 终端 B 在 `c_group` 发 `{"text":"@产品经理 分析需求","mentions":[{"type":"agent","agentId":"a_product"}]}`
  3. 终端 A 依次观察事件
- **预期结果**：事件顺序固定——① `chat.message.new`（用户消息，channel scope）；② `agent.loading` data `{taskId:"t_1",agentId:"a_product",sessionId,phase:"thinking"}`（分派后）；③ `agent.loading` phase="operating"（工具执行阶段）；④ `chat.message.new`（Agent 最终回复，senderType=agent）替代 Loading（FR-20 两阶段指示器）；事件均带递增 id 与 ISO8601 timestamp

### TC-RT-004 SSE 事件帧格式校验（以实现为准）
- **用例类型**：正向　**优先级**：P1
- **前置条件**：订阅 channel scope 并触发一条消息
- **操作步骤**：
  1. 建立连接并触发消息，抓取原始 SSE 帧
- **预期结果**：每帧含 `id: <ev_序号>` 与 `data: {id, type, payload, timestamp}` 四字段（JSON 序列化）；事件 id 为 `ev_<零填充序号>` 且**全局递增**（兼作 since 断线续拉游标）；帧内不含 `event:` 行（前端按 data.type 分派）

### TC-RT-005 多 scope 逗号合并订阅
- **用例类型**：正向　**优先级**：P1
- **前置条件**：admin 为 `t_1`（频道 c_group）与 `t_2`（频道 c_group2）所属项目成员
- **操作步骤**：
  1. 终端 A：`GET /events?token=<t>&scope=channel:c_group,task:t_2,global&since=latest`
  2. 分别在 c_group 发消息、对 t_2 触发状态事件、制造一条 global 事件
- **预期结果**：终端 A 单条连接同时收到 c_group 的 `chat.message.new`、t_2 的 `task.status.changed` 等、以及 global 事件（任一 scope 命中即推送，OR 语义）

### TC-RT-006 SSE since 断线续拉补历史事件
- **用例类型**：正向　**优先级**：P0
- **前置条件**：admin 已登录；此前在 `c_group` 已有若干事件落库，记最新事件 id 为 `ev_xxx`
- **操作步骤**：
  1. `curl -N "GET /events?token=<t>&scope=channel:c_group&since=ev_xxx"`（模拟断线重连后的补拉）
- **预期结果**：连接建立后先重放 id **大于** ev_xxx 的该 scope 历史事件（按 id 升序，以 DB 为准），随后续接实时流；断线期间的事件不丢失（FR-19 先落库后转发 + 游标续拉，09 §4.4）

### TC-RT-007 SSE 收到 agent.error 错误反馈（FR-21）
- **用例类型**：正向　**优先级**：P1
- **前置条件**：构造 Agent 处理失败场景（如 worker 无可用、模型无响应超过首字超时窗口，或对已移除 Agent 触发 agent.status=error）
- **操作步骤**：
  1. 终端订阅 `scope=task:t_1&since=latest`
  2. 触发一次失败分派（如停用 worker 后 @ Agent）
  3. 观察事件流与历史
- **预期结果**：收到 `agent.error` 事件 data `{taskId,agentId,sessionId,level:"message"|"retry",errorType,message}`；历史中该 Agent 最新 processing 消息被标记 `status=failed`（P4 修复，不再永久卡 processing）；群聊同时广播该失败消息（status=failed，错误以消息形式反馈，FR-21）；单 Agent 失败不影响其他 Agent（错误收敛单 Agent 粒度）

### TC-RT-008 global scope 收到 task.status.changed
- **用例类型**：正向　**优先级**：P1
- **前置条件**：admin 已登录；任务 `t_1` 处于进行中
- **操作步骤**：
  1. 终端 A：`GET /events?token=<t>&scope=global&since=latest`
  2. 终端 B：对 `t_1` 执行状态迁移（如 `POST /tasks/t_1/mark-pending-review`）
  3. 终端 A 观察
- **预期结果**：终端 A 收到 `data:{type:"task.status.changed", payload:{taskId,from,to,actorType,actorId}}`（任务状态迁移落库成功后广播，FR-03）；global 事件可被登录用户订阅（无项目过滤，仅登录即可）

### TC-RT-009 scope=all 全量订阅按项目过滤
- **用例类型**：正向　**优先级**：P1
- **前置条件**：admin 为项目 P1、P2 成员；存在另一项目 P3（admin 非成员）其事件可被构造（由 P3 成员触发）
- **操作步骤**：
  1. 终端 A：`GET /events?token=<t>&scope=all&since=latest`
  2. 分别在 P1/P2 与 P3 触发事件
- **预期结果**：终端 A 收到 P1、P2 的事件；**收不到** P3 的事件（scope=all 仅推送调用者成员项目的事件，projectId 过滤防信息泄露）

### TC-RT-010 SSE 无 token
- **用例类型**：反向　**优先级**：P0
- **前置条件**：无 token
- **操作步骤**：
  1. `GET /api/v1/events`
  2. `GET /api/v1/events?scope=global`
- **预期结果**：返回 **401**，code=`AUTH_UNAUTHORIZED`（缺少 token，SSE 事件流需 ?token=<jwt> 鉴权）

### TC-RT-011 SSE token 无效/过期
- **用例类型**：反向　**优先级**：P0
- **前置条件**：admin 已登录；伪造或已过期 token
- **操作步骤**：
  1. `GET /api/v1/events?token=<伪造token>`
  2. `GET /api/v1/events?token=<已过期accessToken>`
- **预期结果**：均返回 **401**，code=`AUTH_UNAUTHORIZED`（token 无效或已过期）

### TC-RT-012 SSE 使用 refresh token
- **用例类型**：反向　**优先级**：P1
- **前置条件**：admin 已登录，持有 refreshToken（type=refresh）
- **操作步骤**：
  1. `GET /api/v1/events?token=<refreshToken>`
- **预期结果**：返回 **401**（请使用 access token，payload.type 校验；refresh token 不可用于 SSE 订阅）

### TC-RT-013 SSE scope 格式非法
- **用例类型**：反向　**优先级**：P1
- **前置条件**：admin 已登录
- **操作步骤**：
  1. `GET /api/v1/events?token=<t>&scope=task123`
  2. `GET /api/v1/events?token=<t>&scope=foo`
- **预期结果**：返回 **400**，code=`SCOPE_INVALID`（scope 格式非法，应为 global | task:<id> | channel:<id>；无冒号段报 400）

### TC-RT-014 SSE scope 类型非法
- **用例类型**：反向　**优先级**：P1
- **前置条件**：admin 已登录
- **操作步骤**：
  1. `GET /api/v1/events?token=<t>&scope=user:u_1`
  2. `GET /api/v1/events?token=<t>&scope=agent:a_1`
- **预期结果**：返回 **400**，code=`SCOPE_INVALID`（scope 类型非法，仅支持 task / channel）

### TC-RT-015 SSE scope 缺少资源 id
- **用例类型**：反向　**优先级**：P1
- **前置条件**：admin 已登录
- **操作步骤**：
  1. `GET /api/v1/events?token=<t>&scope=task:`
  2. `GET /api/v1/events?token=<t>&scope=channel:`
- **预期结果**：返回 **400**，code=`SCOPE_INVALID`（scope 缺少资源 id）

### TC-RT-016 SSE 非项目成员订阅 task/channel scope（越权）
- **用例类型**：反向　**优先级**：P0
- **前置条件**：任务 `t_1`（频道 `c_group`）属于项目 P1；userB 非 P1 成员但已登录
- **操作步骤**：
  1. userB `GET /api/v1/events?token=<userB_token>&scope=task:t_1`
  2. userB `GET /api/v1/events?token=<userB_token>&scope=channel:c_group`
- **预期结果**：均返回 **403**，code=`PERMISSION_PROJECT_NOT_MEMBER`（您不是该资源所属项目的成员，无权订阅其事件）

### TC-RT-017 SSE 订阅不存在的 task/channel
- **用例类型**：反向　**优先级**：P1
- **前置条件**：admin 已登录
- **操作步骤**：
  1. `GET /api/v1/events?token=<t>&scope=task:t_nonexist`
  2. `GET /api/v1/events?token=<t>&scope=channel:c_nonexist`
- **预期结果**：返回 **403**（资源不存在统一按无权处理，防信息泄露——不返回 404）

### TC-RT-018 SSE 断线重连续接（Web 场景）
- **用例类型**：正向　**优先级**：P0
- **前置条件**：Web 端已登录 admin 并打开某任务群聊页（前端 EventSource 已订阅 channel/task scope）
- **操作步骤**：
  1. 在 Web 网络面板强制断开 SSE 连接（如断网 5s）
  2. 断线期间由另一终端在群聊发一条消息
  3. 恢复网络，观察前端自动重连与消息补齐
- **预期结果**：EventSource 自动重连（默认自动重试）；重连后携带 `Last-Event-ID`（since 游标）补拉断线期间事件，再续实时流；断线期间的消息最终全部展示（顺序正确）；页面表现：新消息即时出现、不重复、不乱序

### TC-RT-019 SSE 收到 chat.message.new 的 Agent 回复帧（含 parts 过滤验证）
- **用例类型**：正向　**优先级**：P1
- **前置条件**：任务 `t_1` 进行中；群聊 `c_group` 与私聊 `c_dm`（同 Agent a_developer）均存在；worker 在线
- **操作步骤**：
  1. 终端 A 订阅 `scope=channel:c_group,channel:c_dm&since=latest`
  2. 群聊 @a_developer 与私聊 @a_developer 各发一条消息
  3. 观察 Agent 回复事件帧
- **预期结果**：两个频道均收到 `chat.message.new`（senderType=agent）；**群聊**回复的 `content.parts` 仅含结论性 `text` part（reasoning/tool 等过程片段不落库不广播，FR-18 内部过程不广播）；**私聊**回复的 `content.parts` 保留全量（reasoning/tool 折叠展示）；Loading 指示器被最终回复替代（FR-20 处理完成替换）
