## [2026-09-19] F2 fix — make question_confirm self-approval check effective for platform questions
- **The todo-2 self-approval check was structurally dead for platform questions.** `createForPlatform` stored `sessionId = mainAgentSessionOf(taskId)` (the MAIN member's session), and `confirmByAgent` inferred the requester via `row.sessionId → Session.teamMemberId`. For a platform question that resolves to the MAIN member, never the real requester — so a non-main granted role (e.g. `vteam-product`, whose `toolAllows` has BOTH `vteam_team_add_member` and `vteam_question_confirm`) could `team_add_member` then `question_confirm` its own request and add the agent with NO user confirmation. Session-based inference is the wrong seam for a row whose sessionId is a placeholder.
- **Fix = record the requester at creation time, in the existing `content` JSON** (`content.requesterInstanceId`), threaded from `teamAddMember`'s `args.selfInstanceId`. No Prisma schema/migration change (content is `Json`). `confirmByAgent` now compares the recorded requester first; the session-based comparison is kept ONLY as the fallback for non-platform questions and legacy platform rows created before this fix (documented in the docblock — do NOT silently widen; legacy rows stay under the old weaker semantics).
- **The test that would have caught the bug must exercise the REAL round trip** — `createForPlatform` assembling content → capturing the persisted row → `confirmByAgent` reading it back. The old suite was blind because it mocked `prisma.session.findUnique` to return `{teamMemberId: <confirmer>}` (the confirmer's OWN id), which cannot represent a platform row where the real requester is a non-main member. Never mock `session.findUnique` to "prove" self-approval for a platform question; drive the real content.
- **Registering a request ≠ the request being confirmable by its own author.** The one-caller-only assumption (`createForPlatform` ← `teamAddMember`) made it tempting to skip threading identity; that is exactly the gap. When a security check reads a field, prove that field carries what the check assumes for EVERY creation path.
- **`args.selfInstanceId` is the only trustworthy requester identity** at the `teamAddMember` site — already validated by `assertWorkerTask` (anti-impersonation). It was in scope all along; it simply was not passed through.
- **Worker suite flake (unrelated, pre-existing):** `worker/driver/prompt-await.spec.ts:315` failed once in a full `npx jest` run (timing assertion `calls > 10`), then passed on both isolated reruns and on the next full run (26 suites / 683 tests green). No worker file was touched by this fix; it is a timing-sensitive flake, not a regression.
