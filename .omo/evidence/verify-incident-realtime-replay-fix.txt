TRADE-OFF (stated, not silently accepted): a client reconnecting with an explicit
cursor that is ≤ REALTIME_REPLAY_MAX (1000) behind receives a COMPLETE, gap-free
replay. A client >1000 behind receives only the newest 1000 events; the older
events between since and (latest-1000) are DROPPED (documented "让落后太多的客户端
从最新状态续接"). This is a deliberate correctness-vs-memory trade-off: bounded
memory instead of at-least-once catch-up. Acceptable for the live-increment use
case; would be a data-gap only for a consumer needing full historical replay via
the SSE replay path. NOT a defect (bounded, documented, intended) — flagged as design.
