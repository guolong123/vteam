## 2. CHANGES (worker only — 2 source files + 2 spec files)

### worker/src/driver/prompt-await.ts
- import DriverModelRef from './v1-driver'.
- CompletionResult gains `model?: DriverModelRef` (documented: serve-reported model,
  undefined when absent/malformed — never fabricated).
- NEW extractModelInfo(m): index-signature-safe read of info.providerID/info.modelID
  (same defensive style as the existing info.error read at ~:124). BOTH must be
  non-empty strings, otherwise undefined (no half-built "modelID-only" keys).
- NEW exported findAssistantModel(messages): prefers the assistant message that owns
  step-finish(reason=stop) (tool loops may switch models); falls back to the last
  assistant message on the timeout path (no finish). user messages are never used.
- buildResult() (~:381) now sets `...(model ? { model } : {})` alongside tokens/cost.
- Threading: buildResult's output is CompletionResult, returned by awaitCompletion and
  by sendAndAwait → runSendAndAwait already returns it verbatim, so
  `result.model` reaches exec-server with no signature changes anywhere.

### worker/src/exec/exec-server.ts
- NEW exported helper `resolveUsageModelKey(configured, reported)` (~:269) — the ONE
  place the task.completed model chain is produced. Format still comes exclusively from
  usageModelKey (`providerID/modelID`), so the byte format cannot diverge.
  Precedence (documented in the doc comment):
    1. payload.model  — explicit config (agent/worker default_model_id) wins.
    2. serve-reported model (CompletionResult.model) — the only truth source for
       zero-config environments.
    3. UNKNOWN_MODEL_KEY ('unknown') — neither available.
- task.completed (~:1584): `model: modelKey` placed AFTER `...ctx` so it is not
  overwritten by the ctx value (which stays the pre-completion config-only value used
  by streaming events: session.updated running/idle). Backward compatible: the field
  was already required-non-empty string in the event body.
- describeModel() log line extended for ops visibility:
    model=<resolved> (config=<payload.model|default> serve=<info model|default>)

### NOT touched (deliberately)
- server/ — dispatcher is already correct (sends model when configured).
- web/ — no changes (see §5 note about a concurrent sibling session).
- handlePolledCompletion / poll path — dormant under 方案 A; no such symbol exists in
