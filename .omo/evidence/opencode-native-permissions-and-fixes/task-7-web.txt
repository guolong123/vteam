      feat(teams): prefill the member external agent from the role slot
      
      The role's external-agent slot added by todo 2 was write/validate-only: dispatch reads TeamMember.opencodeAgentName (worker-dispatcher.ts:3671-3687) and resolveMemberBinding resolved only the internal defaultAgentId, so a role pointing at an external engine agent reached no member. Binding now mirrors the internal slot: resolveMemberBinding gains rule 5 - explicit member opencodeAgentName wins, else role.defaultOpencodeAgentName prefills, else null - and returns the resolved value for create/addMember to persist on the member row.
      
      The explicit-agentId branch needed the same resolution, not just the roleId-only branch: a role that binds an external agent can never also hold defaultAgentId (todo 2 keeps the slots mutually exclusive), so its members must pass an explicit agentId and the role's external choice only ever flows through that branch. The role row is now read once for both branches (label + both slots) and the private roleBindingOf helper is deleted rather than kept as a second query.
      
      Prefill never overrides: updateMember applies the resolved default only when the request did not set opencodeAgentName and the persisted member value is empty, so an existing member-level choice survives a role change. The request-level precedence is explicit request value > persisted member value > role default. worker-dispatcher.ts is untouched - dispatch precedence is out of scope, this is binding only.
