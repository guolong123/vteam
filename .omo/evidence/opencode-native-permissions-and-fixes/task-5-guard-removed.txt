# 4. INJECTOR SURGERY — LEGACY PURGE (why it is required)
################################################################################
  The worker works on a PERSISTED volume: <workDir>/.opencode-worker-inject.json still
  listed guardRolesFile / guardSessionsDir / guardPluginFile, <workDir>/opencode.json
  still had "./.opencode/plugin/vteam-role-guard.ts" in `plugin`, and
  <workDir>/.vteam-role-guard/roles.json + sessions/ were on disk from the previous
  image. Without a purge, the NEW image would start opencode with `plugin` pointing at
  a file that no longer exists in any image layer, i.e. deleting the source would not
  actually deactivate the layer on an existing deployment.
  purgeLegacyGuardArtifacts() runs on BOTH the success and the neutralized path and
  removes exactly: the .vteam-role-guard/ directory, the generated plugin file, any
  `vteam-role-guard` entry in `plugin`, and the three stale manifest keys. It does NOT
  touch user-authored plugin entries (OmO is preserved — asserted live below).
