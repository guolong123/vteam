IMPLEMENTATION — memorySearch (platform-mcp.service.ts)
--------------------------------------------------------------------------------
(a) COUNTING — after final .slice(0, limit), fire-and-forget:
    const hitIds = ranked.map((row) => row.id);
    if (hitIds.length > 0) {
      void this.prisma.memory
        .updateMany({
          where: { id: { in: hitIds } },
          data: { refCount: { increment: 1 }, lastUsedAt: new Date() },
        })
        .catch((err: unknown) => {
          this.logger.warn(
            `memory_search 引用计数失败（不影响返回） ids=${hitIds.length}：${...}`,
          );
        });
    }
  - ids empty  -> updateMany skipped entirely (no wasted write)
  - .catch logs via this.logger.warn (NO empty catch; F2 guard satisfied)
  - `void` + .catch => rejection never propagates, return value unaffected
  - `{increment:1}` idiom per trigger.service.ts:589 precedent

(b) RANKING — between filterMemoryByTags and slice:
    const ranked = this.sortMemoriesByImportance(
      this.filterMemoryByTags(rows, args.tags),
    ).slice(0, limit);
  New private helper sortMemoriesByImportance (next to filterMemoryByTags):
  - descending computeMemoryImportance(row)
  - tie-break: newer (lastUsedAt ?? createdAt) first
  - `now` evaluated ONCE and passed to every row's score => reproducible ordering,
    no millisecond-tick jitter between rows (also makes assertions stable)
  - sorts a copy ([...rows]); returns input untouched when length < 2
  - import: `import { MemoryImportanceInput, computeMemoryImportance }
             from '../memories/memory-importance';`
    (memory-importance.ts has zero imports => no circular-dependency risk)
