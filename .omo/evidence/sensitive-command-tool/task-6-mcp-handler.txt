-----------------[ RISKS / 残余面 ]-----------------
1) 断开与执行的竞态：signal.aborted 在下发前复核，但「复核通过 → fetch 发出」之间若恰好断开，本次已发出的命令仍会跑完（worker /secret-command 无取消端点，契约已确认不可改）；窗口为毫秒级，且命令自身受 timeoutSec 上限约束。不能声称“断开必可终止在途命令”，只能声称“断开后不再启动新执行”。
2) 单进程门：in-flight Set 是进程内状态；多实例部署下同会话跨实例并发未做分布式互斥（当前 server 为单实例）。
3) keepalive 依赖会话仍在 pending 监控中；若会话被前序静默判败（failedSessions），keepAliveSession 只刷新活动列不复活 watchdog——此为既有语义，避免复活已判死会话。
4) 服务端二次脱敏是精确值替换：变形/编码后的外传无法阻止（计划已声明 best-effort，非安全边界）。
5) timeoutSec 传入 worker 时按「命令超时 + 5000」下发（任务要求），worker 侧命令实际窗口比用户请求多 5s；换取请求超时恒晚于命令结束，避免被客户端默认超时掐断。
6) 服务重启期间遗留 pending secret_input question：hook 随进程丢失，用户提交后只落 {provided,...} 不执行，由 TTL 过期收敛（无幽灵执行，但用户侧会看到“提交后无反应”）。
7) envelope.signal 恒 null：worker 响应契约不回传信号，超时用 timedOut=true 表达（未编造 SIGKILL 值）。
