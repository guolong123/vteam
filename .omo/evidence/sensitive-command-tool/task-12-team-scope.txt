1. ROOT CAUSE (confirmed by red run)
--------------------------------------------------------------------------------
Server create emits carried the REAL task id but no top-level `teamId`, while the
event scope was `{type:'team', id:'tm_...'}`:

  server/src/questions/questions.service.ts
    createForPlatform      emit payload = {question, taskId:'t_...', agentId, sessionId}
    createSecretForPlatform emit payload = {question, taskId:'t_...', agentId, sessionId}
    (reply / expire / resolvePlatformQuestion / worker-event.ingress already emit teamId)

Web subscribes the session page with scope `team:tm_...,channel:...,global`
(web/app/(main)/teams/[id]/session/page.tsx:798-801).

web/hooks/use-sse.ts matchesScope `team:` fallback only accepted
`taskId === id || taskId === 'team:'+id`. A real `t_...` taskId matches neither and
`payload.teamId` was never consulted -> frame dropped before `onAgentQuestion`
-> the secret modal only appeared after a refresh (GET /questions 补拉).

Why QA was falsely green: web/e2e fixtures emitted `taskId:'team:'+id`
(secretQuestionFrame), a shape the live path never produces.

3. FIX
--------------------------------------------------------------------------------
server/src/questions/questions.service.ts
  - both create emits now derive `teamId` from the very scope object they publish with:
      const createScope = await this.scopeOf(row.taskId, row.sessionId);
      payload = { ..., taskId: row.taskId,
                  teamId: createScope.type === 'team' ? createScope.id : null, ... }
      emit(..., createScope)
    (same for createSecretForPlatform with `secretScope`)
  - `payload.taskId` unchanged (still the real `t_...`) -> task-scope consumers and the
    page's existing `payload.taskId.startsWith('team:')` guard keep working unchanged
  - `scopeOf` stays the single source of truth for both scope and teamId (no dead code,
    no second teamIdOf lookup)

web/hooks/use-sse.ts
  - `team:` fallback only:
      return taskId === id || taskId === `team:${id}`
            || (ev.payload as { teamId?: string })?.teamId === id;
  - every other branch and `TEAM_SCOPE_WHITELISTED_EVENTS` behaviour untouched;
    the added disjunct is an exact `=== id` comparison, so cross-team frames still drop

8. RISKS
--------------------------------------------------------------------------------
- The `team:` fallback now accepts any event type carrying a matching top-level
  `teamId`, not only agent.* events. It is an exact equality check on the subscribed
  team id, so cross-team delivery is still rejected; but it does broaden which
  *event types* reach subscribers inside the same team. Existing per-type guards
  (page callbacks) are unchanged.
- `payload.taskId` semantics were deliberately left alone, so `task:`-scope consumers
  and the page's `startsWith('team:')` guard behave exactly as before.
- Real-browser proof covers the frontend delivery path with a stubbed EventSource; the
  server-side emit shape is proven by the Jest create-emit assertions rather than by a
  live end-to-end server broadcast in this todo.
