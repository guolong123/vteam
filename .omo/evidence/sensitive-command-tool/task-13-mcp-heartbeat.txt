5. 修复内容（代码变更）
--------------------------------------------------------------------------------
server/src/platform-mcp/platform-mcp.controller.ts（+125/-11）
  - `handle` 改为自持响应（@Res() raw，@HttpCode 默认 200，通知仍 res.status(202)），
    dispatch 结果是 Promise（仅阻塞 tools/call）时进入 awaitWithHeartbeat：
    * 仅当请求 Accept 声明 text/event-stream（opencode: "application/json, text/event-stream"）
      才启用；常量 MCP_HEARTBEAT_INTERVAL_MS = 30_000（≤60s，保证任意 60s 扫描窗内有字节）；
    * 首次心跳才切换响应头（text/event-stream + no-cache/no-transform + x-accel-buffering: no）
      并写 `: vteam-mcp-heartbeat <epoch>\n\n`；快速返回的请求（非阻塞流量）从不触发切换；
    * settle 后：接管过 → `data: <JSON-RPC>\n\n` + res.end()；未接管 → res.json(整体 JSON)；
    * await 期间抛错：headers 未发送 → 维持原语义抛给 Nest；已接管 → 以 JSON-RPC 错误帧收尾；
    * disconnect 语义不变（res 'close' / req 'aborted' → abort ctx.signal）；close 即清定时器，
      destroyed/writableEnded 后不写帧（断开后无心跳、无收尾写）。
server/src/platform-mcp/platform-mcp.controller.spec.ts（+191/-…）
  - 新增 describe「阻塞 tools/call 心跳」4 个 fake timers 用例：
    1) event-stream 客户端：pending 期间每个 60s 窗口恰 2 条心跳（≥1 是验收线）、
       切到 SSE 响应头、最终 `data:` 帧 JSON.parse 后 {jsonrpc,id:91,result.content[0].text}
       再 parse = {status:'cancelled'}，res.end 被调用、res.json 不被调用；
    2) Accept 不含 event-stream（curl 默认）：推进 600s 零写入、零 setHeader，
       最终仍 res.json 整体 JSON；
    3) 客户端断开：signal 立即 aborted，此后推进 600s 不再写、res.end 不被调用；
    4) 快速返回：即使声明 event-stream 也不切 SSE，走整体 JSON。
  - 既有「客户端断开信号」用例改为断言 res.json 收到整体 JSON-RPC（原 resolves 契约等价迁移）。

8. 风险与限制
--------------------------------------------------------------------------------
1) 心跳只对 Accept 声明 text/event-stream 的客户端启用：声明了却硬要求 application/json
   正文的非标准客户端会收到 SSE 正文（MCP Streamable HTTP 客户端两者皆支持，
   opencode 1.18.32 实测通过；未覆盖其他客户端版本）。
2) 判定为经验结论：abort 机制在 184MB 压缩二进制中未定位到具体实现（60s tick + ~240s 阈值
   由时间戳反推），若上游 opencode 改变该行为，需重跑本探针。
3) final 镜像与 probed 镜像存在一处 prettier 换行差异，未在 final 镜像上重跑 600s 探针
   （理由：无语义变化，且 tsc/lint/320 tests/dist grep/health 全绿）。
4) 并发 lane 在本任务期间清空 tasks/agent_questions 并删除 t_0000000002，
   探针行无法在收尾时逐行核对（原始日志已留档 §2/§3 raw 文件）。
5) que 计数器重启复位（todo 11）本次两次 server 重启均未复现（counter 未归零），
   仍按 todo 11 处理，不在本任务范围。
6) 心跳帧会出现在响应字节流中：任何按「纯 JSON 单帧」做字节级断言的客户端测试需同步更新
   （本仓库既有 spec 已覆盖两种形态）。
