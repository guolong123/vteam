【2. serve 端点实测 —— 根因（Bug2，与 Bug1 question 完全对称）】
v2 端点（detector 当前在用）：
  GET /api/session/ses_00a4f5d74ffek2zmAeCeRUJQIi/permission
  => {"data":[]}        ← v2 独立通道，pending 权限不在其中（恒空）

v1 全局端点：
  GET /permission
  => [{"id":"per_ff6558bbd001P3YmJAqTjpQ7QV","sessionID":"ses_00a4f5d74...",
       "permission":"external_directory","patterns":["/etc/*"],
       "metadata":{"command":"... cat /etc/os-release ..."},"always":["/etc/*"],
       "tool":{"messageID":"msg_ff6557acd...","callID":"call_00_ppe1z..."}}]
  => pending 权限真实在 v1 全局端点，字段名为 permission(=action) / patterns(=resources)

判定：worker PendingQuestionDetector.listPermissions 走 v2 端点恒空 → 永不检测到
pending 权限 → 不上送 session.permission → server 不落库 → 前端不弹窗。
（对照 listQuestions 已修 Bug1 走 v1 /question；permission 侧未修。）

【3. 修复（worker/src/driver/v1-driver.ts）】
a) ServePermissionRequest 接口：新增 v1 字段 permission?/patterns?（兼容 v2 action/resources）
b) listPermissions：GET /permission（v1 全局）→ 按 sessionID 过滤 → 字段归一为 action/resources
c) replyPermission：POST /permission/{requestID}/reply（v1 全局）——实测 v2
   /api/session/{id}/permission/{id}/reply 返回 404（PermissionNotFoundError，Bug3），
   与 Bug1 的 question reply 对称；v1 全局端点实测 200 返回 true
d) exec-server.ts detector：resources ?? [] 兜底（接口字段变可选后 TS 编译通过）
