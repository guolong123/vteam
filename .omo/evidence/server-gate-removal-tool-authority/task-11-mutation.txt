## 0. Root-cause detector selection (why these assertions catch the mutation)
The post-flip matrix specs (`agent-policies.matrix.spec.ts`, `platform-mcp.authority-matrix.spec.ts`)
DERIVE their expectation from `ROLE_BOUNDARIES[*].toolAllows` (the same source they evaluate),
so a mutation to that source can move both sides and hide itself. The independent, non-vacuous
detectors are the specs carrying a HARDCODED grant matrix / exact-value snapshot:
  - server/src/common/constants/agent.constants.spec.ts  (GRANT_MATRIX, lines 110-118; asserts at 121/139/155/156/301)
  - server/src/prisma/seed.spec.ts                        (hardcoded grant expectation, line 882)

  - server/src/execution-policies/policy-canonical.spec.ts       (explicit formerlyGated loop, line 311)
These name the formerly-gated tools explicitly (NOT via the now-empty `ROLE_SERVER_GATED_TOOLS`),
so they cannot go vacuously green. The vacuous-loop trap is explicitly guarded: the loops iterate
FORMERLY_GATED_TOOLS (7 tools) x 7 roles and each asserts `assertions > 0`.
