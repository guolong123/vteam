## (b) THE RETAINED-CHECKS ALLOWLIST

Server-side refusals that STAY, each with its code and why. These are NOT tool-permission
gates; they enforce flow-state legality, topology routing, human authority, or resource scope.

### b.1 `notify_agent` routing — `PLATFORM_MCP_NOTIFY_ROUTING_VIOLATION`
Two throws, both `server/src/platform-mcp/platform-mcp.service.ts`:
- **self-notify** :1479–1484 — `args.selfInstanceId === args.targetInstanceId` → code
  `PLATFORM_MCP_NOTIFY_ROUTING_VIOLATION`, message `不能通知自己；需要协作请通知主 Agent 由其中转`.
- **non-main → non-main** :1499–1507 — `exec.callerId !== routingMainId && args.targetInstanceId !== routingMainId`
  → same code, message ``仅主 Agent（${routingMainId}）可向其他成员派发；请先通知主 Agent 由其中转``.
Reason: **topology routing** — the collaboration graph (main can reach anyone, anyone can
reach main, non-main↔non-main is mediated) is a product invariant, not a tool grant. Declared
`server/src/platform-mcp/platform-mcp.constants.ts:31`.

### b.2 terminal-task execution-dispatch refusal — plain `Error` (no HTTP code)
`server/src/chat/worker-dispatcher.ts:1444–1451` — when
`taskStatusForDispatch === 'completed' || 'archived'`, throws
`任务 … 已终态终止 (terminal, status=…)：execution 派发已拒绝…`.
Reason: **flow-state legality** — no execution may be dispatched into a terminal task.
(review/nudge/wake are exempt by design; see the comment at :1440–1443.)

### b.3 accept/archive refusal — `TASK_AGENT_COMPLETION_FORBIDDEN` at BOTH sites
Declared `server/src/common/constants/task.constants.ts:69`.
- MCP layer: `server/src/platform-mcp/platform-mcp.service.ts:2840–2846`
  (`taskTransition`, before `assertWorkerTask`).
- service layer: `server/src/tasks/tasks.service.ts:1395–1401` (`transitionByAgent`).
Both: `action === 'accept' || 'archive'` → code `TASK_AGENT_COMPLETION_FORBIDDEN`, message
`仅人类用户可在管理界面验收完成/归档任务，Agent 不可调用 accept/archive；…`.
Reason: **human authority** — acceptance/archival is reserved to the human operator.

### b.4 global-memory write scope — `PLATFORM_MCP_ERRORS.FORBIDDEN`
`memory_save`:
- `server/src/platform-mcp/platform-mcp.service.ts:3158–3166` — `args.level === global && team.mainAgentMemberId !== memberId`
  → message `仅主 Agent 可写入全局记忆，禁止普通成员写 global 级`.
- `server/src/platform-mcp/platform-mcp.service.ts:3282–3298` (task-dimension path in
  `memorySave`) — `!globalMainId || globalMainId !== args.selfInstanceId` → same message.
`memory_update`:
- `server/src/platform-mcp/platform-mcp.service.ts:3437–3449` — `row.level === global &&
  (!mainTeam || mainTeam.mainAgentMemberId !== exec.callerId)` → message
  `仅主 Agent 可更新全局记忆，禁止普通成员改 global 级`.
Reason: **resource-scope** — `global`-level memory is team-shared state whose mutation is
scoped to the team's main member; this is a data-scope rule, not a tool grant.
(Team-level cross-team write refusals at :3432–3436 and :3450–3454 also stay — same scope family.)

### b.5 `hook_cancel` owner-or-main — `PLATFORM_MCP_ERRORS.FORBIDDEN` (RESOURCE-OWNERSHIP)
`server/src/platform-mcp/platform-mcp.service.ts:899–913` — when
`hook.ownerInstanceId !== exec.callerId`, allow only if `team.mainAgentMemberId === exec.callerId`,
else throw code `PLATFORM_MCP_ERRORS.FORBIDDEN`, message `仅 hook 所有者或主 Agent 可取消`.
Reason: **resource ownership** — a hook belongs to the instance that registered it; the main
member is the escalation owner. Retained per plan guardrail "No removal of the hook_cancel
owner-or-main check (retained as a resource-ownership rule)".
(Cross-team hook cancel refusal at :893–898 also stays — same ownership family.)

### Governing invariant (one sentence)
**The worker guard is the single source for tool permission; the server retains flow-state
legality, topology routing, human authority, and resource-scope / ownership checks.**
