IS `NULL` (Prisma) SEMANTICALLY IDENTICAL TO `DEFAULT NULL` (handwritten)?
  YES — this is the one legitimate difference and it is not a semantic difference.
  * A nullable MySQL column with no explicit DEFAULT has NULL as its effective
    default; `varchar(191) NULL` and `varchar(191) DEFAULT NULL` produce the same
    column in information_schema (IS_NULLABLE='YES', COLUMN_DEFAULT=NULL in both).
  * `DEFAULT NULL` is merely the explicit spelling of the implicit behavior, and it
    is the repo's own house style for hand-written nullable ADD COLUMNs (the
    20261010030000_worker_update_state migration is cited as that precedent in the
    header comment, and it uses the same form).
  * Case (`VARCHAR` vs `varchar`) is not significant in MySQL DDL.
  So the hand-written DDL and Prisma's canonical output describe the SAME column.
  This is also exactly what guard-spec assertion 7 pins: it normalizes whitespace
  and asserts the three statements in order, treating NULL/DEFAULT NULL as equal
  via the explicit expected strings — i.e. the equivalence is asserted, not assumed.
