# E2E 角色边界验证计划

## 背景
本计划旨在验证团队协作平台中各角色的权限边界是否正确实现。任务 e2e-role-boundaries 要求确保每个角色（计划员、架构师、开发者、产品经理、项目经理、测试）只能执行其职责范围内的操作，不能越权执行其他角色的任务。通过端到端验证，确保系统角色隔离机制有效，防止职责混淆和越权操作。

## 验证步骤
1. **计划员权限验证**：验证计划员（如 tmm_0000000006）只能创建、编辑计划文件（位于 `.opencode/plans/` 目录），且不能执行代码变更、不能直接向用户提问、不能调用任务状态流转工具。
2. **架构师权限验证**：验证架构师（如 tmm_0000000003）只能进行架构设计、评审计划的技术合理性，不能编写实现代码、不能执行测试、不能直接管理用户交互。
3. **开发者权限验证**：验证开发者（如 tmm_0000000004）只能进行代码实现、技术方案设计，不能创建计划、不能进行产品需求分析、不能执行测试验证。
4. **产品经理权限验证**：验证产品经理（如 tmm_0000000001）只能进行需求分析、产品设计，不能编写代码、不能进行架构设计、不能执行技术测试。
5. **项目经理权限验证**：验证项目经理（如 tmm_0000000002）作为主 Agent 可以管理任务状态、分配工作，但不能替代其他角色执行具体任务。
6. **测试权限验证**：验证测试（如 tmm_0000000005）只能进行测试用例设计、执行测试、验证结果，不能编写实现代码、不能进行架构设计、不能管理产品需求。

## 验收标准
1. 所有角色均能成功执行其职责范围内的操作，无权限拒绝错误。
2. 所有角色尝试执行越权操作时，系统应返回明确的权限拒绝错误或提示。
3. 角色之间的协作流程（如计划评审、代码提交、测试验证）能正常进行，不出现职责交叉导致的流程阻塞。
4. 验证过程中发现的任何权限边界问题均应记录并报告，作为后续改进的依据。
5. 验证完成后，应输出完整的验证报告，包括通过项、失败项和改进建议。

## 工作项分解
- T1 计划员权限验证：验证计划员只能写计划文件（验收：尝试执行代码变更被拒绝）
- T2 架构师权限验证：验证架构师只能进行架构设计（验收：尝试编写实现代码被拒绝）
- T3 开发者权限验证：验证开发者只能编写代码（验收：尝试创建计划被拒绝）
- T4 产品经理权限验证：验证产品经理只能进行需求分析（验收：尝试进行架构设计被拒绝）
- T5 项目经理权限验证：验证项目经理管理权限（验收：成功流转任务状态，但无法替代角色执行）
- T6 测试权限验证：验证测试只能进行测试活动（验收：尝试编写实现代码被拒绝）

## 依赖关系
- T1-T6 为并行任务，可同时执行，无依赖关系。
- 验证结果需汇总到最终验证报告中。

## 假设清单
1. 假设各角色权限配置已正确设置（待验证）。
2. 假设系统能正确识别角色身份并应用相应权限策略。
3. 假设验证过程中不会因系统配置问题导致权限验证失败。
