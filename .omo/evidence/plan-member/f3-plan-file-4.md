# F3 手工 QA 验证计划

## 背景
本计划旨在对手工 QA 流程进行端到端验证，确认测试团队可以按标准流程完成手工验证任务。F3 手工验证覆盖产品核心功能的可用性检查，通过测试人员手动操作验证功能符合预期，为自动化测试之外的关键路径提供人工保障。

## 验证步骤
1. **测试用例准备**：测试人员根据需求文档编写 F3 手工测试用例，覆盖核心功能的正向场景、边界场景与异常场景，明确每类用例的预期结果。
2. **功能手工验证**：测试人员在测试环境逐条执行手工用例，记录实际结果与预期结果的差异，对疑似缺陷进行初步定位并留存截图/日志作为证据。
3. **缺陷跟踪**：发现的缺陷通过 issue 工具创建缺陷单，指派给对应研发成员处理，并流转状态直至验证通过后关闭。
4. **回归确认**：研发修复后，测试人员对缺陷关联用例进行回归执行，确认修复有效且不影响既有功能。
5. **验证报告输出**：汇总执行结果，输出 F3 手工 QA 验证报告（通过/失败/阻塞用例数、缺陷清单、遗留问题），提交团队评审。

## 验收标准
1. F3 手工测试用例覆盖需求文档全部核心功能点，无遗漏。
2. 所有用例在测试环境完整执行一轮，执行记录可追溯（执行人、时间、结果）。
3. 发现的缺陷全部经过确认、指派、修复、回归闭环，无未决缺陷遗留（阻塞类除外）。
4. 验证报告完整输出并通过团队评审，可作为交付依据。
5. 验证过程中不出现手工 QA 流程中断或工具不可用导致的阻塞。

## 工作项分解
- T1 测试用例编写：F3 手工用例覆盖核心功能（验收：用例清单与需求功能点一一对应）
- T2 手工执行：逐条执行并记录结果（验收：执行记录完整，每条用例有待审结果）
- T3 缺陷闭环：缺陷创建、指派、修复、回归（验收：全部缺陷状态流转至关闭）
- T4 报告输出：汇总并提交验证报告（验收：报告含通过/失败/阻塞统计与缺陷清单）

## 依赖关系
- T1 前置，T2 依赖 T1；T3 依赖 T2 发现的缺陷；T4 依赖 T2/T3 完成。
- T1 完成后，T2 可启动；T3 与 T2 部分并行（边执行边提单）。

## 假设清单
1. 假设测试环境已部署且可正常访问（待验证）。
2. 假设需求文档已齐备，可作为用例编写依据。
3. 假设缺陷处理涉及研发资源可及时响应。
