## serve 1.18.16 API 实测结论（关键）
| 端点 | 路径 | 实测 |
|---|---|---|
| question 列表 | GET /api/session/{id}/question | `{"data":[...]}`（空=[]）；**v1 /session/{id}/question 返回 HTML（不存在）** |
| question reply | POST /api/session/{id}/question/{requestID}/reply | body `{answers:[[]]}`，204 |
| question reject | POST /api/session/{id}/question/{requestID}/reject | 204 |
| permission 列表 | GET /api/session/{id}/permission | `{"data":[{id,sessionID,action,resources,...}]}` |
| permission reply | **POST /api/session/{id}/permission/{requestID}/reply** body `{reply:"once"\|"always"\|"reject"}` | 204 ✅（v2 生效） |
| ~~permission reply v1~~ | ~~POST /session/{id}/permissions/{permissionID}~~ | 实测 **PermissionNotFoundError**（v1 端点不识别 per_ id，必须用 v2） |
| permission create（测试用） | POST /api/session/{id}/permission | `{"data":{id:"per_...",effect:"ask"\|"allow"}}`；effect=ask 才产生 pending |

⚠️ 重要：计划书假设 permission reply 走 v1 `/session/{id}/permissions/{permissionID}`（body {response}），
实测 1.18.16 该端点返回 PermissionNotFoundError；生效的是 v2 `/api/session/{id}/permission/{requestID}/reply`。
**已按实测改为 v2**（worker v1-driver.replyPermission + server WorkerClient 契约同步）。

## 关键 bug 修复（E2E 发现）
1. **serve permission reply 端点**：v1 端点不识别 per_ id（404）→ 改 v2 `/api/session/{id}/permission/{requestID}/reply`
2. **ingress 反查失败丢弃事件**：同 worker 多 running 会话时 resolvePlatformSessionId 反查不唯一失败
   （adoptNewInstanceRef 放弃回写）→ 原实现直接跳过落库，事件静默丢失。改为保留原始 ses_ sessionId 落库
   （payload taskId/agentId 兜底），reply 时 ses_ 前缀直接透传 worker
3. **ExecServer 检测器实例级标志残留**：detectingPending/reportedPending 为实例级，任务结束残留 true 导致
   后续任务检测全跳过 → 重构为 PendingQuestionDetector 每任务独立实例
