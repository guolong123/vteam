differing values reach:
  - `buildAgentPolicies()` -> agents[] AND guard.roles[] (Todo 3 DB read);
  - `resolveByAgent()` / `resolveManyByAgents()` -> guard payload (Todo 4
    short-circuit removal);
  - the emitted shape satisfies the worker `buildAgentDefinitions()` strict
    field contract exactly (agent {name,description,mode,permission};
    guard role {permission,tools,bashDeny,correction}; tools tri-state;
    bashDeny string[]; no `write` key);
  - a no-rows control asserts the edited value is NOT what the constant path
    yields (proves the assertions are non-vacuous).

4) DISCOVERED OPERATIONAL TRAP (recorded in-script)
--------------------------------------------------------------------------------
`docker compose up -d --force-recreate worker` re-runs the `init` dependency.
On this host the init image is pre-Todo-9, so its seed unconditionally overwrites
`config` -> the just-made DB edit was silently reverted within ~2s and the proof
would falsely show "no change". Fix: reload via `docker restart worker` (or
`docker compose restart worker`), which does NOT re-run init. Implemented as the
script's `reload_worker()` helper. This is why the naive force-recreate form
would have produced a misleading INCONCLUSIVE/FAIL.
