================================================================================

    if (Object.prototype.hasOwnProperty.call(agent.permission, 'write')) {
      throw new Error(`[agent-definitions] agent ${agent.name} permission 非法：不得含 'write' 键 ...`);
    }
  worker/src/resources/opencode-config-builder.ts:74-87 — thrown for ANY agent →
  injector catches and neutralizes the ENTIRE guard.

Built-in rows are normalized (canonicalizePermission strips `write`,
execution-policy.service.ts:188-204). CUSTOM-agent rows are NOT:
  server/src/execution-policies/execution-policy.service.ts:653
      permission: config.permission as Record<string, unknown>,   // resolveByAgent (custom DB row)
  server/src/execution-policies/execution-policy.service.ts:771
      permission: config.permission as Record<string, unknown>,   // buildAgentPolicies custom branch
No canonicalizePermission / write-stripping is applied on either path.

The write-path validator also permits it:
  server/src/execution-policies/execution-policy.service.ts:791-808 assertValidConfig
  only checks permission/correction are objects and tools is an object — it does
  NOT reject/strip `permission.write`.

Reachability: PATCH /execution-policies/:id (now open for template AND custom,
update() at :517-539) with config.permission.write set → stored → emitted raw in
/agent-policies → worker `assertAgentShape` throws → guard neutralized for ALL
agents. This is precisely the failure mode the plan told the executor to defend
against. Pre-existing shape on the custom branch, but the plan explicitly
required it normalized and the new canonicalizer was not wired to it.
Status: BLOCKER (missing normalization for DB-sourced values; safety regression path).
