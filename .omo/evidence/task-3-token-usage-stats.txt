2. 幂等键选择与理由（红线）
====================================================================
两个生产者必须走同一写入函数 handleTaskCompleted → handleTeamTaskCompleted
→ recordModelUsage：
  ① ingress：worker-event.ingress.handleTaskCompleted → taskCompletedCallbacks
     （本次仅补 1 行 model 透传，写入逻辑不在 ingress）
  ② dispatcher 自持轮询：handlePolledCompletion

所选自然键（读事件体后确定）：
  part:<step-finish part 的 opencode part id>
  → 回退 message:<该 part 的 messageID>
  → 再回退 tally:<sessionId|taskId|total/input/output|cost|sha256(text)[0:16]>

选它的理由：
  1) 两个生产者的输入里都真实存在该字段且指向同一份 serve 数据：ingress 路径
     payload.parts（worker 原样上送 assistant parts，见 exec-server.ts:1556-1565 的
     `...result.parts`），轮询路径 messages[].parts（worker-client.getMessages 原样返回
     serve 响应，无字段裁剪）⇒ 同一轮完成跨生产者算出同一个键。
  2) 排除 sessionId+taskId：团队直聊 taskId 恒为 ''（DispatchRequest.taskId 缺省按
     '' 处理），而 sessions 按 (teamId, teamMemberId) 复用同一会话
     （uk_sessions_team_member 的 STORED 生成列 team_member_key）⇒ 同会话多轮会撞键，
     把后续轮次用量整轮吞掉。已用「同会话同 taskId 空串的不同轮次 → 两行」用例钉住。

仲裁方式：DB 唯一约束，不是先查后写。
  model_usages 的唯一约束**只有主键 id**——Wave 1 冻结的 schema/迁移只建了三个
  @@index + PRIMARY KEY，无任何 @@unique 列，且 model-usage.migration.spec.ts 用
  toEqual 双向钉死列集合与索引集合（改它 = 回退 Wave 1 已验收契约，而 Todo 3 被明确
  禁止改 schema/migrations）。故把自然键摘要进主键：
        id = 'us_' + sha256(自然键)[0:32]
  重复投递 → 主键冲突 P2002 → 记 debug 后忽略（唯一赢家已落库）。
  128 bit 摘要，本表量级碰撞可忽略；35 字符 << varchar(191)。

连带说明（对 Wave 1 文档口径的偏离，已在代码注释写明）：
  * id 不再是 'us_' + 计数器序号 ⇒ 本类**不调** resyncIdPrefix('us')：没有
    nextId('us') 生成点，计数器归零撞主键那一类事故在本表不可能发生；
    common/id-resync.guard.spec.ts 的「nextId 生成点须有 resync」方向天然满足，
    实测全绿（见 §5）。若后续希望回到 us_<序号> + 独立 dedupKey 唯一列，需要
    一次 Wave-1 schema/guard 契约变更（不在本 todo 授权范围内）。
  * completedSessions 语义**未动**（仍只挡同进程顺序到达的重复回流），本次只在
    其后追加 DB 级防线，不依赖它。

3. 实现要点
====================================================================
- tokens 按 worker ServeTokens 权威形状解析（worker/src/driver/v1-driver.ts:79-85：
  total/input/output/reasoning/cache.{read,write}），parseUsageTokens 逐字段
  Number.isFinite 校验；非数字/NaN/±Infinity/负数/小数一律归零（截断取整）。
  缺失 tokens 或 cache 子对象 → 六计数全 0，行照落（脏数据归零不断链）。
- cost：typeof number 且有限 → 原样存；否则 null（NULL=未知 ≠ 0=免费）。**不做任何**
  换算/重算/汇总（聚合属 Todo 4）。
- model：事件体 model 非空串则原样存；缺失/空串/空白 → 'unknown'，与 worker 侧
  UNKNOWN_MODEL_KEY 逐字节一致（worker 与 server 无共享 import 路径，两端各定义）。
- 归属：teamId/teamMemberId/agentId 取 handleTeamTaskCompleted 既有的归属解析结果，
  channelId 取 resolveTeamChannel 结果，taskId/sessionId 取 payload（sessionId 缺失时
  落空串——为一个软关联维度丢掉整轮真金白银更糟）。
- 调用点：频道解析之后、message 落库 try 块**之前**（群聊回退分支不建 message 行，
  但模型确实被调用过，用量照样要记）。recordModelUsage 自带 try/catch，任何失败只
  logger.warn 后返回，绝不阻断 prisma.message.create。
- 写失败分级：P2002/ER_DUP_ENTRY（重复投递）→ logger.debug；其他异常 →
  logger.warn。无空 catch、无 as any、无 @ts-ignore。
