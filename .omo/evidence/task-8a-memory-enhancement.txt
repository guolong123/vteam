1. 复用机制的选择（plan 允许二选一；以实际 tsc 与模块读取为准）
================================================================================
选择：**共享纯 helper**（新建 server/src/memories/memory-state.ts），而非注入
MemoriesService 调其 remove()。

依据（三条，均为实际核查结果，非推测）：

(1) MemoriesModule 未导出 MemoriesService（server/src/memories/memories.module.ts:14-19
    只列 providers，无 exports）。注入需改 memories.module.ts —— 该文件是 Todo 9 的
    红线（并行运行中，已被他改），本 todo 不得触碰。
(2) 鉴权口径本质不同，无法直接复用 remove(id, viewer)：
      - REST remove 的 assertRowWritable 按**人类用户**判权：team 行查
        team_user_members（viewer.id = users.id），global 行要求平台管理员
        （memories.service.ts:288-315）。
      - MCP 调用方是**团队成员实例**（tmm_），且按 plan 决策⑤只允许 team 级
        （global/role → 403），管理员身份对 Agent 无意义。
      强行复用需伪造一个 MemoryViewer，语义会失真。
(3) 无循环依赖：memory-state.ts 只 import @nestjs/common(ForebiddenException)、
    ../prisma/prisma.service（type-only import）、./memory.constants。已读
    memories.module.ts + platform-mcp.module.ts 确认方向单向；
    runtime 实测加载通过（见 §4 证据 4）。

共享内容（两条归档路径同一语义出口）：
  - assertTeamScopedMemoryRow(row, callerTeamId)：team 级归属纯守卫（global/role/跨团队 → 403）
  - archiveMemoryRow(prisma, id, archivedAt)：软删唯一写出口（写 deletedAt，不硬删）
REST 侧 memories.service.remove() 已改走 archiveMemoryRow（行为等价：仍是
deletedAt=new Date()，不抛错、不改返回形状；memories.service.spec 全绿）。

2. 权限矩阵（两工具）
================================================================================
服务端硬闸（platform-mcp.service.ts，agent 无法绕过）：
  能力点        默认出厂   生效面
  memory.archive true      仅 vteam-project_manager（团队主 Agent）= true；其余 6 岗 false
  memory.merge   true      同上

MCP handler scope 门（两道工具共用）：
  行不存在 / 已软删              → 404 MEMORY_NOT_FOUND
  level !== 'team'（global/role） → 403 MEMORY_FORBIDDEN
  row.teamId !== 调用方团队        → 403 MEMORY_FORBIDDEN
  merge sourceId === targetId     → 400 MEMORY_INVALID
  merge 任一行已归档              → 404（重复合并不可执行）
  无权限岗位调用                   → 403 PLATFORM_MCP_TOOL_NOT_PERMITTED（既有能力门，
                                    经 capabilityKeyForTool 桥接，无需新增代码）

引擎层（ROLE_BOUNDARIES / buildAgentPolicies）：
  VTEAM_MCP_TOOL_NAMES 32 → 34；vteam-project_manager.toolAllows 增两项 allow；
  其余 6 岗经 mcpDenies 补集自动 deny。层① permission 全 vteam_* 恒 allow
  （既有设计：MCP 权限由服务端能力门兜底）。

入参只读保证：memoryArchiveSchema / memoryMergeSchema 只接受 id 类字段，
不含 refCount / mergedIntoId / deletedAt（zod 非 strict，多余键被剥离，service 层
从不读取这些键 —— 已有 spec 断言 parsed.data 不含它们）。
未暴露 purge / restore（唯一不可逆入口仍只在人工确认路径）。

5. 已知取舍与诚实声明
================================================================================
- 「归档后 memorySearch 不再返回」与「merge 后 source 消失、target refCount=8」两条用例
  用了有状态内存 DB mock（findUnique 读当前行 / update 真落库 / findMany 滤软删行），
  而非两次孤立断言 —— 目的是让「归档 → 检索消失」成为一条端到端链路。其余用例仍是
  单点断言。
- 层① permission（引擎原生）对全部 vteam_* 恒 allow 是既有设计（服务端能力门兜底），
  本 todo 未改该设计；两工具的实际收窄靠 AgentRole.capabilities + handler scope 门。
- baseline-agent-policies.json 属证据 artifact 而非产品代码，重生成走仓库自带捕获脚本；
  spec 中对**旧**历史基线 before-agent-policies.json 的 sha256 闸门未被触碰（仍只读）。
- 未做 git 操作（任务约束）。
- 未跑 web 的 npm run build / lint（任务验收仅要求 server 侧三项 + web role-capabilities
  改动；web 侧改动为纯数据数组字面量新增，tsc 已过）。若需要 build/lint 证据可补跑。
