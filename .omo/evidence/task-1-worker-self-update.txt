[2] 关键设计决策
--------------------------------------------------------------------------------
2.1 版本解析优先级（worker/src/code-version.ts 头部注释已文档化）
    env WORKER_CODE_VERSION（容器/集群注入，**优先**）
      > dist/version.js（打包脚本在 tsc 之后、tar 之前生成的版本戳文件）
      > 'dev'
    - env 空串/纯空白视为未设置（编排层误配不遮蔽文件戳），实测 E2E-3。
    - 运行时模块按**文本读取 + 正则解析** dist/version.js，不 require：
      worker 编译目标为 CommonJS（tsconfig module=commonjs），而版本戳文件由 shell
      生成不经 tsc；require 会在缺失时抛错且把生成格式锁死为 CJS，文本解析对
      `export const` 与 `exports.X =` 两种写法都成立，且不污染 require 缓存
      （自更新覆盖 dist 后同进程再解析可读到新值）。

2.2 ⚠️ 命名冲突（本次实测发现并修复，务必知悉）
    最初按计划新建 `worker/src/version.ts`，tsc 编译产物即 `dist/version.js`，
    而 pack-worker.sh 也写 `dist/version.js`（版本戳文件）→ **后者覆盖前者**：
    发布包内 dist/version.js 是版本戳，运行时解析模块被整个顶掉（线上即崩）。
    仅靠 "tar 内含 dist/version.js" 断言无法发现（文件确实存在，只是内容错了）。
    修复：运行时模块改名 `worker/src/code-version.ts`（产物 dist/code-version.js），
    版本戳文件保持计划约定的 dist/version.js。smoke 已加断言长期防护该类回归。

2.3 容器路径（worker/Dockerfile）
    本 Dockerfile 由 src 直接 tsc 编译（**不经过** pack-worker.sh），镜像内
    dist 无版本戳文件 → env 是容器路径唯一版本来源。
    runner 阶段：ARG CODE_VERSION=container-unstamped → ENV WORKER_CODE_VERSION。
    缺省用显式占位值而非空串：空串会被 resolveCodeVersion 视为未设置而静默回落
    'dev'，看起来像注入成功实则版本丢失。
    运行期 env（compose -e / chart env）优先于镜像 ENV；chart 中 container `env`
    优先于 `envFrom` ConfigMap → **env 优先于文件戳**在三层编排上均成立。

2.4 sha256（无新 npm 依赖）
    系统 sha256sum（Linux/Alpine）→ shasum -a 256（macOS）→ node 内置 crypto 兜底
    （打包链路已要求 node/npm，node crypto 不是新依赖）。

2.5 web/Dockerfile 在镜像构建期调用 pack-worker.sh
    （COPY scripts/pack-worker.sh → RUN ./scripts/pack-worker.sh → runner 阶段
     COPY --from=build /app/web/public ./public），故版本戳 + worker-src.version.json
    随 web 镜像自动发布到静态服务，**生产 tarball 无需任何手动前置步骤**即带版本戳。

2.6 deploy-k8s.sh TAG→worker env：**未改**（留给 Todo 2 的 server env 同批）
    现状该脚本 `--set` 列表只有 server/web/worker 的 image.tag（deploy-k8s.sh:368-373），
    没有 env 批量 --set。worker 的 env 接线改由 chart values（worker.env.codeVersion）
    完成，部署侧只需追加一行 `--set worker.env.codeVersion=$TAG` —— 属 Todo 2
    与 server.env.codeVersion 同批的改动，刻意不在此并发触碰同一脚本段。

2.7 worker-src.version.json 纳入 .gitignore
    与 worker-src.tar.gz 同源产物，每次打包重写（含 sha256/时间戳），入库只会
    制造无意义 diff。运行期由 web 静态服务提供，与 tarball 生命周期一致。
    注意：Todo 4 执行器须容忍该文件缺失（无 pack 的纯 web 部署不会有它）——
    计划已规定「version.json 缺失/不匹配 → 放弃并 warn」。

[6] 单测覆盖（13 例，worker/src/code-version.spec.ts）
--------------------------------------------------------------------------------
优先级三态：env 压过文件 / env 缺省读文件 / 两者皆缺回落 dev
env 空串与纯空白视为未设置（继续读文件；文件亦缺则 dev）
文件存在但解析不出（空文件 / 纯注释 / 无该常量 / 空串值）→ dev
manual-<date> 形态版本串可解析（与 2.x 回退路径对齐）
parseStampedVersion：单引号 / 双引号 / CommonJS exports / 无 const 前缀 四种写法
parseStampedVersion 负例：EXPECTED_WORKER_CODE_VERSION、WORKER_CODE_VERSION_X 不误命中
   ↑ 该负例在首轮实测中**真实失败**（正则左边界未收紧，误取同后缀常量），已修复
     为 /(?:^|[^\w$])WORKER_CODE_VERSION\s*=\s*(['"])([^'"\r\n]+)\1/
defaultVersionFileReader（真实文件系统 tmpdir）：文件存在→返回文本；缺失→undefined + warn
缺失文件经 resolveCodeVersion 端到端 → dev
默认 reader 指向 __dirname/version.js（ts-jest 下 src/ 无该文件 → dev）
