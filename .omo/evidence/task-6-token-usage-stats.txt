  投递 A2（同一 step-finish part id ⇒ 同一自然键 ⇒ 同一主键；eventId/seq/text 全换新）
    rows 4 → **4**（未增）   msgs 8 → **9**（新增一条 agent 消息）
    新消息原文：m_0000000017 "qa-usage-e2e idempotency probe B (same step-finish part id => same natural key)"
    $ SELECT COUNT(*) FROM model_usages WHERE total_tokens=3180 AND cost=0.0333; → **1**

**判定**：A2 的消息行确实落库了 ⇒ 该请求**完整走完了** handleTaskCompleted（含
recordModelUsage 之后的落库/广播/emitFinal），并没有被任何内存闸门提前短路；
而 `model_usages` 行数**没有增加** ⇒ 挡住重复的唯一机制就是 DB 主键唯一约束
（`id = us_ + sha256(自然键)[0:32]` → P2002）。这正是 Todo 3 设计的仲裁层，
且是跨进程（重启/多副本）成立的。

**同进程内存闸门（顺带实测，非替代）**
  在不重启的情况下对同一 sessionId 复投（eventId 各不相同），ingress 日志确认事件
  已被接收（`[ingress] task.completed workerId=w_compose_worker taskId= agentId=a_project_manager`），
  但 model_usages 行数与消息数均不变 → 进程内 `completedSessions` 先行拦截。
  两层职责与 Todo 3 证据 §2 的描述完全一致。

12. 观察到的既有问题（非本功能引入，未修，供 F1/F3 定夺）
================================================================================
12.1 `task.completed` 事件里 `taskId: ""`（空串而非缺省）会让回复落库炸 FK
  实测：ingress `this.str(raw.taskId)` 把 "" 保留成 ""，随后
  `prisma.message.create({ taskId: '' })` 触发
  `Foreign key constraint violated on the fields: (task_id)`，
  server log 两行（WorkerDispatcher error + ChatService emitError）。
  真实 worker 的团队直聊**不传** taskId（worker log `taskId=-`），所以线上不触发；
  只有合成事件显式传空串才会踩到。与本功能无关，且「统计写入不阻断主链路」反而被
  这次故障佐证（用量行照落）。
12.2 sink 的日志全是 logger.debug，compose server 以 info 级运行
  `$ docker logs aiagents-compose-server | grep -c '"level":20'` → **0**
  ⇒ `[usage] 用量已记账` / `[usage] 同一 completion 重复投递，主键仲裁下已存在，跳过`
  这些行在 compose 环境永远不可见。本次幂等结论因此改用「行数 + 同批次消息行」证明。
  如需可观测性，建议 F 波评估是否把 P2002 分支提到 warn（本 todo 不改代码）。
12.3 团队「主 agent 门禁」使统计 tab 在本环境只有 1 个成员
  （§2）多成员 × 多模型的表格/透视/Top3 由 Todo 4 单测（多成员/多模型三层一致性）与
  Todo 5 的真实 Chromium 冒烟（2 成员 × 2 模型 fixture）覆盖，本 todo 不重复。
12.4 opencode free 端点不稳
  `opencode/ling-3.1-flash-free` → "Upstream request failed: Endpoint is unavailable."；
  `opencode/big-pickle`（serve 默认）与 `opencode/space-bunny-free` 正常。
  影响：真实回合的模型覆盖只有 2 个（unknown + space-bunny-free），不是环境限制而是上游抖动。
