# 修复「模型提问/权限确认弹窗不触发」bug 的 E2E 证据（2026-08-12）

## 根因
`web/hooks/use-sse.ts` 的 `matchesScope` `task:` 分支白名单缺 `agent.question`。
server 广播的 `agent.question` 事件（scope=task）被前端过滤丢弃 → `onAgentQuestion` 永不触发 → 弹窗不出现。

## 修复（唯一代码改动）
`web/hooks/use-sse.ts:85-88` `task:` 分支白名单加 `"agent.question"`：
```ts
["agent.loading", "agent.error", "team.changed", "agent.status", "agent.question"].includes(ev.type)
```

## 断点排查结论（私聊补拉兜底）
- `web/app/(main)/messages/[id]/page.tsx:571-575` questions 补拉查询 `enabled: !!channel?.taskId`。
- 后端 `ChatService.createDmChannel`（chat.service.ts:432-493）**强制绑定 taskId**（`taskId: dto.taskId`），
  `toChannelDto`（:649-668）**始终返回 taskId**（含 private 频道）。
- DB 实测：`c_0000000006 = private / task_id=t_0000000002 / agent_id=a_tester` → taskId 非空，补拉可用。
- **结论：私聊补拉无第二断点，无需修改后端。**

## 环境
- docker-compose：server(:13000)/worker(:14000)/web(:13001)，web 镜像重建（含修复代码）
- worker serve: opencode 1.18.16（--pure）
- 平台登录：admin / admin123；会话 c_0000000006（a_tester, task t_0000000002）

## 触发方式（serve 测试注入端点）
serve 1.18.16 支持 `POST /api/session/{id}/permission` 注入权限请求（effect=ask 产生 pending）：
```
curl -X POST -H "Content-Type: application/json" \
  -d '{"action":"external_directory","resources":["/etc/*"]}' \
  http://127.0.0.1:14000/api/session/<ses>/permission
→ {"data":{"id":"per_ff58e0c52001...","effect":"ask"}}
```
worker `PendingQuestionDetector`（exec-server.ts:585-641）onPoll 检测 listPermissions → 上报
`session.permission` 事件 → server ingress 落库 agent_questions（taskId 兜底）→ realtime 广播
`agent.question`（scope=task，payload 带 taskId）→ **前端 matchesScope（修复后）放行** → onAgentQuestion → 弹窗。
