【缺陷发现与修复（todo 4 / todo 2 缺陷，E2E 暴露）】
--------------------------------------------------------------------------------
缺陷 1：渲染 git.ts 的 loadCredential 引用 CommonJS 编译产物 exports.GIT_CREDS_FILE
  现象：git_clone 报「仓库凭证文件不存在或损坏」（凭证文件明明存在）
  根因：git-tools.ts 的 loadCredential 引用模块级 GIT_CREDS_FILE，TS 编译为 CommonJS 后
        toString() 内联进 ES module git.ts 时变成 exports.GIT_CREDS_FILE，而 git.ts 无
        exports 对象 → ReferenceError 被函数内 catch 吞掉 → 误报「文件不存在或损坏」。
        jest 未捕获因 CommonJS 环境 exports 有效。
  修复：loadCredential 内局部 const credsFile = path.join(os.homedir(), ...)（自包含），
        不再引用模块级常量。
  测试：git-tools.spec.ts 新增「渲染产物不引用 exports」防回归断言（not.toMatch(/exports\./)）。
  验证：渲染产物 grep 无 exports.，仅含 const credsFile = path.join(...)。

缺陷 2：渲染 git.ts 的 runGit/cwdOrigin 引用 child_process_1（TS 编译别名）
  现象：git_clone 报「child_process_1 is not defined」
  根因：import { spawnSync } 为命名导入，TS 编译成 const child_process_1 = require(...)，
        toString() 内联时函数体为 child_process_1.spawnSync(...)，而渲染 git.ts 的 import
        是 import { spawnSync } from "node:child_process"，child_process_1 未定义。
  修复：源码 import 改为 import * as child_process from 'child_process'（namespace 导入，
        编译产物保留原变量名 child_process），函数体用 child_process.spawnSync，
        渲染模板 import 同步为 import * as child_process from "node:child_process"。
  测试：spec 新增断言 not.toMatch(/child_process_\d+/) + import * as child_process + 
        child_process.spawnSync。
  验证：渲染产物 grep 无 child_process_1，含 child_process.spawnSync。

缺陷 3：server 下发 GitCredentialEntry 缺 permission 字段（todo 2/4 契约缺陷）
  现象：write 授权仓库 git_push 仍报「仓库 X 未授予 write 权限，禁止 push」；
        worker 落盘条目 permission=undefined。
  根因：buildGitCredentialsPayload 打包只含 repoUrl/authType/key/fingerprint，
        未携带 permission；resolveWorkerActiveRepoUrls 只返回 repoUrl 集合。
  修复：
  - server GitCredentialEntry 接口加 permission?: string
  - resolveWorkerActiveRepoUrls 返回 Map<repoUrl, 最高权限>（多 agent 授权取
    write > read，凭证面=worker 级语义）
  - buildGitCredentialsPayload 透传 permission
  - worker-protocol.ts GitCredentialEntry 加 permission（双写契约）
  - worker git-credential-injector buildGitCredsFile 保留 permission 落盘
  测试：workers.service.spec 的 dispatchGitCredentials 用例更新 mock 含 permission，
        断言 payload 含 permission: 'read'/'write'。
  验证：PATCH 授权 write 后 worker 落盘条目 perm=write；git_push 通过校验实际 push 成功。

缺陷 4：全部凭证吊销后 worker 侧残留明文凭证（安全缺陷，todo 2 缺陷）
  现象：DELETE 最后一个测试仓库（gc_0000000009）后，worker 凭证文件仍残留
        e2e-write-repo 的私钥明文（entries=1）。
  根因：buildGitCredentialsPayload 用 findMany({where:{revokedAt:null}}) 判断——
        「全部已吊销」（rows=[]）与「从未配置」（rows=[]）不可区分，
        rows.length===0 一律返回 null → dispatch 跳过 → worker 不收到清空命令。
  修复：先 gitCredential.count() 区分：count===0（从未配置）→ null 跳过；
        count>0 但未吊销行为空（全部已吊销）→ 返回空数组 → 下发 credentials=[] 清 worker。
  测试：spec「从未配置」用例加 count.mockResolvedValue(0)；其余 dispatch/replay 用例
        加 count>0 mock；C5(R5) register 用例加 count=0。
  验证：全量吊销后重启 worker → server 下发「git 凭证下发：worker=1 个 credentials=0」
        → worker 日志「凭证文件已更新（0 条）」→ 凭证文件 entries=0（残留清除）。

修复后全量回归：server 990 全绿；worker 335 全绿（+1 防回归）；tsc 双端 0 错误。
修复涉及 commit：并入 todo 4（git.ts 渲染缺陷 1/2）与 todo 2/4（permission 契约缺陷 3、
吊销清空缺陷 4）对应 commit（计划 Commit: N 允许修复并入对应 todo commit，不新建）。
