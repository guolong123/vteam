## 2. Migration

`server/prisma/migrations/20261009020000_capability_memory_org_tools/migration.sql`
— 11 statements, no DDL, sha256 `49f4d7539d37228490e62928cb1fce1a5c8798152844679e4c18e7d91a3fa035`.

- `execution_policies` × 2 — `ep_project_manager` only (`type='template'`), one key per
  statement, guarded by `JSON_CONTAINS_PATH(...)=0` **and** by
  `JSON_CONTAINS_PATH(...'$.tools.vteam_memory_update')=1`. The second guard is a hard
  requirement: without it, a row whose `config` has no `tools` would get a brand-new 2-key
  `tools` object which, under `resolveGuardTools`' whole-object-wins semantics, would evict
  PM's other 28 tools from the allowlist.
  The other 6 builtin policy rows get **nothing** — their factory `toolAllows` never contained
  these tools and this layer's "missing ⇒ not in allowlist" already equals the intended deny;
  writing explicit `'deny'` would diverge from the fresh-install value.
- `agent_roles` × 8 — per factory matrix: PM `true`, other 6 builtin `false`, 3 external
  `false`, everything else (`ar_general` + historical custom) `true`.
  External roles get `false` (deviation from 20260929000000's blanket exemption, argued in the
  file header: the exemption list `EXTERNAL_AGENT_UNMANAGED_CAPABILITY_KEYS` was emptied on
  2026-09-30, so external matrices are now fully managed, the factory value for these two keys
  is `false`, and there is no user decision exempting externals from memory-org tools).
- `agent_roles` × 1 — `capabilities_configured_at` stamp, `IS NULL` only (never overwrites an
  operator's existing stamp).

Idempotent: every write is `JSON_CONTAINS_PATH(...)=0`-guarded, one key per statement, so a
re-run on an already-backfilled DB is a safe no-op.

## 6. Known limitation (disclosed)

No MySQL client / server is reachable in this environment (`command -v mysql` → none; tests run
on sqlite by `server/test/setup-env.js`), so the SQL was **never executed**. Confidence comes
from three sources instead:
1. the SQL idiom is byte-for-byte the one already deployed in production by
   `20260929000000_capability_git_web_tier` and `20260926000000_secret_command_capability`;
2. the behavioural spec reimplements MySQL's `JSON_CONTAINS_PATH(doc,'one',p)=0` ≡ "path absent"
   and `JSON_SET` only-add semantics, and is driven by the parsed SQL rather than a hand copy;
3. a real `prisma migrate deploy` should be exercised on a staging MySQL before rollout, as the
   house DDL-guard specs are text-parse only and structurally cannot detect a runtime SQL error.
