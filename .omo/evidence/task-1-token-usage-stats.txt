SENTINEL DECISION (must match Todo 3 / usage-sink)
--------------------------------------------------------------------------------
CHOICE: literal string  'unknown'

Exported as worker/src/protocol/worker-protocol.ts:
  export const UNKNOWN_MODEL_KEY = 'unknown';

Rationale: Todo 2's model_usage.model column stores `providerID/modelID` composite
string. When payload.model is absent/null the worker emits 'unknown' so the field is
ALWAYS a non-empty string -> downstream never needs a null check, and "unknown" is
distinguishable from any real model id.

Todo 3 MUST use the same literal 'unknown' as its own fallback. NOTE for the sink
implementer: worker/ and server/ are separate processes with no shared import path
(architecture decision 1B - worker must not import server code), so the constant is
declared independently on both sides; only the VALUE must match byte-for-byte.

Empty-string handling (slightly beyond the literal spec, defensive):
usageModelKey() also maps {providerID:'', modelID:''} -> 'unknown' rather than
emitting a junk '/' key into the DB.
