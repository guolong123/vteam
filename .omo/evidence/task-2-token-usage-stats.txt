### 2.1 DDL 正确性不是手搓的 —— 用 Prisma 自己的 migrate diff 反证

无 shadow DB 也能跑 `migrate diff`（纯 schema→schema），用它把「加入 ModelUsage 前后」
两个 schema 的差异导出，得到 Prisma 自己会生成的 DDL，与手写迁移逐列比对：

```
$ npx prisma migrate diff --from-schema-datamodel <裁剪掉用量域的 schema> \
                          --to-schema-datamodel prisma/schema.prisma --script

-- CreateTable
CREATE TABLE `model_usages` (
    `id` VARCHAR(191) NOT NULL, ... `cost` DOUBLE NULL,
    `created_at` DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
    INDEX `idx_usage_team_member`(`team_id`, `team_member_id`),
    INDEX `idx_usage_team_model`(`team_id`, `model`),
    INDEX `idx_usage_created`(`created_at`),
    PRIMARY KEY (`id`)
) DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

差异仅此一条、零外键。手写迁移采用 `20261009010000_memory_refcount/migration.sql` +
squashed_baseline 的列式方言（`varchar(191) CHARACTER SET utf8mb4 COLLATE
utf8mb4_unicode_ci` / `int` / `double` / `datetime(3)`，2 空格缩进），
把 Prisma 输出的 `VARCHAR(191)`/`INTEGER`/`DOUBLE`/`DATETIME(3)` 换成本仓既有
migration.sql 的等价写法 —— 两者在 MySQL 8 上是同一张表，仅大小写与类型别名不同。

### 2.2 迁移内容要点

- 只 1 条语句：`CREATE TABLE model_usages (...)`，无 ALTER / DROP / RENAME / TRUNCATE。
- 列（16）：`id` / `team_id` / `team_member_id` / `session_id` / `channel_id` /
  `agent_id` / `task_id`(NULL) / `model` / 六个 `*_tokens` int NOT NULL DEFAULT 0 /
  `cost` double DEFAULT NULL / `created_at` datetime(3)。
- 索引（3）：`idx_usage_team_member (team_id,team_member_id)`、
  `idx_usage_team_model (team_id,model)`、`idx_usage_created (created_at)`。
- 零 FK / 零 CONSTRAINT（软关联）。
- 零 UPDATE / INSERT / DELETE。

## 3. resyncIdPrefix 落点（计划要求二选一：本 todo 不产出服务 → 记精确位置）

本 todo 是纯 store 层，不创建任何 service，故**未**新增 `onModuleInit`。责任与位置
已写进两处代码注释（不是口头交接）：

- `schema.prisma` 用量域注释：「落库方（usage-sink，写入点在 worker-dispatcher 的完成
  事件路径）必须在 `onModuleInit` 调 `resyncIdPrefix(this.prisma.modelUsage, 'us',
  this.idGen)` —— 否则重启后计数器归零、nextId('us') 撞既有主键 P2002」。
- 同一段注释也出现在 migration.sql 文件头（迁移可能被单独 review，注释必须在场）。
- 守卫 spec 第 13 条把 `resyncIdPrefix(this.prisma.modelUsage, 'us'` 字面量钉在 schema
  上：Todo 3 落地消费侧时，这条断言会确认口径没被改写成别的前缀。

对标先例：`memories.service.ts:24,62`（`MEMORY_ID_PREFIX = 'me'` + `onModuleInit` 内
`resyncIdPrefix(this.prisma.memory, ...)`）、`session-lifecycle.service.ts:63`。
既有的 `common/id-resync.guard.spec.ts` 断言「凡 nextId 生成点必须有 resync」——
本 todo 未新增 nextId 调用点，故该守卫当前仍绿（待 Todo 3 引入 nextId('us') 时，
它会自动要求配套 resync）。
