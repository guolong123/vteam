[0] 根因
--------------------------------------------------------------------------------
- chart ConfigMap（vteam-config）固定下发 WORKER_ID=w_<release>（如 w_vteam），
  worker Deployment 所有副本共享同一 WORKER_ID。
- server workers.register() 以 dto.workerId 为主键 upsert（server/src/workers/
  workers.service.ts:243）→ 后注册副本覆盖先注册副本 → 页面/API 只显示 1 个 worker。
- 实证（修复前 DB）：workers 表仅 1 行 id=w_vteam，2 个 pod 共用。
- worker 侧读取（worker/src/config.ts:95）：
  workerId = (env.WORKER_ID ?? '').trim() || `w_${hostname}` —— env 值直接用，
  无覆盖逻辑；hostname 在容器内即 pod 名（天然唯一）。→ 无需改 worker 代码。

[1] 修复 diff（chart/vteam/）
--------------------------------------------------------------------------------
a) templates/deployment-worker.yaml —— WORKER_ID 由 pod 名注入（downward API）：
   env 段新增（显式设置 worker.env.workerId 时优先用该值）：
     {{- if .Values.worker.env.workerId }}
     - name: WORKER_ID
       value: {{ .Values.worker.env.workerId | quote }}
     {{- else }}
     - name: POD_NAME
       valueFrom:
         fieldRef:
           fieldPath: metadata.name
     - name: WORKER_ID
       value: "w_$(POD_NAME)"
     {{- end }}
   （K8s env value 支持 $(VAR) 引用同容器先前 env；POD_NAME=metadata.name 全局唯一）

b) templates/configmap.yaml —— 移除共享 WORKER_ID 键（避免 envFrom/env 歧义）：
   -  WORKER_ID: {{ .Values.worker.env.workerId | default (printf "w_%s" .Release.Name) | quote }}

c) values.yaml —— worker.env.workerId 注释更新：
     空 = 自动按 pod 名生成（w_<pod 名>，多副本天然唯一）；显式设置时用该值

d) README.md —— 关键 values 表 + 与 compose 对齐点补充 WORKER_ID 语义说明
