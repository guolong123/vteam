## 一、权限链路（代码层核实）

taskTransition (platform-mcp.service.ts:606)
  → assertWorkerTask(ctx, taskId, selfInstanceId)    // 归属校验（前置）
  → TasksService.transitionByAgent(taskId, selfInstanceId, action, reason?)
      → task.mainAgentInstanceId === instanceId ? 放行 : 403 TASK_STATUS_MAIN_AGENT_ONLY

## 二、实证发现的真实缺陷（修复前）

首次真实调用（非主实例 ta_38，selfInstanceId 正确、团队内活跃成员）：
  error: "selfInstanceId 与执行该任务的实例（ta_0000000037）不一致，禁止冒充"

根因：assertWorkerTask 回退分支 `session.findFirst({ where: { taskId, workerId } })`
在多实例任务（t_12 下 5 个会话并存）返回**首条 session（恰好是主实例 s_37）**，
导致：
- 合法成员 ta_38~41 被误判"禁止冒充"（提示不准确，未走到 transitionByAgent）
- 无法落到"仅主 Agent"403，与任务目标（团队内非主实例落"仅主 Agent"提示）不符

修复（platform-mcp.service.ts assertWorkerTask）：
  where 增加 `...(selfInstanceId !== undefined ? { taskAgentId: selfInstanceId } : {})`
  → selfInstanceId 提供时按实例精确匹配自身 session；无匹配 → 403"禁止跨任务访问"
  （安全不降级：跨任务/冒充实例因无自身 session 仍被拦）。
