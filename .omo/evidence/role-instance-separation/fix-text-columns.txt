================================================================================
vteam 修复证据 — Task/Issue/Project/Skill description 列改 TEXT
日期: 2026-08-14
任务: 任务创建 500 —— PrismaClientKnownRequestError: value too long for column
      description（VARCHAR(191) 容量不足，用户提交超长 description）
================================================================================

[1] 根因
--------------------------------------------------------------------------------
- tasks.description / issues.description 列为 VARCHAR(191)（init / issue_management 迁移），
  CreateTaskDto / CreateIssueDto / UpdateTaskDto / UpdateIssueDto 的 description 无 MaxLength
  约束，用户提交超长文本 → MySQL 报 `value too long for column description` → 500。
- 同类先例：Agent.prompt / Skill.content / credential_ref 已 TEXT（F3-1 同根因）。

[2] 修复内容（schema.prisma + 迁移）
--------------------------------------------------------------------------------
schema.prisma 4 处 description 加 @db.Text：
  - Task.description        String?   @db.Text
  - Issue.description       String?   @db.Text
  - Project.description     String?  @db.Text   （同类预防，无 MaxLength 用户长文本）
  - Skill.description       String?  @db.Text   （同类预防）
新建迁移 server/prisma/migrations/20260814150000_text_columns/migration.sql：
  ALTER TABLE `tasks`    MODIFY `description` TEXT NULL;
  ALTER TABLE `issues`   MODIFY `description` TEXT NULL;
  ALTER TABLE `projects` MODIFY `description` TEXT NULL;
  ALTER TABLE `skills`   MODIFY `description` TEXT NULL;
title / 短字段 / artifact_versions.change_note 等不改。

[3] 长文本字段排查结果（grep schema 无 @db.Text 的 String 列）
--------------------------------------------------------------------------------
| 模型/列                     | 类型    | 处置          | 理由                              |
