日期：2026-08-14
任务：为 vteam 项目创建 Helm chart（对齐 docker-compose.yml 全部服务），K8s 形态部署 server/web/worker + 可选内置 MySQL + init Job。

## 1. Chart 结构树

```
chart/vteam/
├── Chart.yaml                 # name: vteam, version: 1.0.0, appVersion: "1.0.0", type: application
├── values.yaml                # 镜像/replicas/资源/secret/持久化/ingress（db.enabled=true 默认）
├── values-dev.yaml            # dev 覆盖示例（小资源 + 显式 dev 密码）
├── README.md                  # 安装/镜像构建/secret 生成/端口/Ingress 说明
└── templates/
    ├── _helpers.tpl           # 名称/labels/secretName/随机值缓存（secret↔configmap 同源）
    ├── configmap.yaml         # DATABASE_URL 拼装 + 非敏感 env（NODE_ENV/PORT/JWT时效/首字超时/worker env）
    ├── secret.yaml            # JWT_SECRET/WORKER_TOKEN/MODEL_CREDENTIAL_KEY/DB_PASSWORD
    ├── deployment-server.yaml # env + /app/uploads 挂载 + startup/readiness/liveness 探针
    ├── deployment-web.yaml    # 无运行时代理 env + $HOSTNAME 探针
    ├── deployment-worker.yaml # X_WORKER_TOKEN + worker-work→/data/keta-worker + worker-home→/root
    ├── statefulset-mysql.yaml # mysql:8 + volumeClaimTemplates + mysqladmin ping readiness（db.enabled 时）
    ├── job-init.yaml          # prisma migrate deploy && node dist/prisma/seed.js + wait-db initContainer
    ├── service-server.yaml    # ClusterIP :3000
    ├── service-web.yaml       # ClusterIP :3000
    ├── service-worker.yaml    # ClusterIP :4000（serve）
    ├── service-mysql.yaml     # Headless :3306（db.enabled 时）
    ├── pvc.yaml               # uploads / worker-work / worker-home
    ├── ingress.yaml           # /api/v1→server、/→web（默认关闭）
    └── NOTES.txt              # 部署后使用说明
```

## 6. 设计要点（与 docker-compose 对齐）

- **DATABASE_URL 拼装**：configmap 中 `mysql://root:<dbPassword>@<release>-mysql:3306/aiagents`；external 模式直接使用 `db.external.url`。密码经 `_helpers.tpl` 的 set 缓存保证 secret.yaml 与 configmap 引用同一生成值（避免 DB 密码失配）。
- **Secret 生命周期**：首次安装自动生成随机值（randAlphaNum），`lookup` 复用在 cluster 中已存在的 Secret → helm upgrade 不轮换密码；生产建议 `--set secret.*=$(openssl rand -hex 32)` 显式注入；`secret.existingSecret` 支持外部 Secret 引用。
- **init 门控**：initContainer（node net 探测 mysql service:3306）等待 DB 就绪 → 对齐 compose `depends_on: db(service_healthy)`；Job backoffLimit=6 + ttlSecondsAfterFinished=300。
- **web 镜像代理**：`values.web.image.proxyTarget` 仅为构建参数文档（rewrites 编译进 routes-manifest，运行时无 env 注入）。
- **worker advertise**：`WORKER_ADVERTISE_HOST=http://<release>-worker`，worker 注册上报 baseUrl=`<advertiseHost>:<servePort>` → server 经 worker Service :4000 访问（对齐 compose 网络内互通）。
- **探针**：server `/api/v1/health`、web `fetch($HOSTNAME:3000)` 均为 exec(node -e fetch)，与 node:22-alpine 无 curl/wget 的镜像约束一致；worker 无 HTTP 探针（对齐 compose 无 healthcheck，活跃判定由 server 心跳承担）。
- **持久化**：uploads→/app/uploads、worker-work→/data/keta-worker、worker-home→/root 对齐 compose 三卷；mysql 用 StatefulSet volumeClaimTemplates（标准做法，替代 PVC 清单）。

## 7. Risks

- 内置 MySQL 为单副本 StatefulSet（数据卷 RWO），无高可用/备份策略——生产建议切换 `db.enabled=false` + 外部托管数据库。
- 随机密码生成依赖 Helm 的 `randAlphaNum`（首装写入 Secret），若 Secret 被删除则升级会生成新密码与 MySQL 数据失配——需备份 Secret 或显式注入 `secret.dbPassword`。
- `secret.existingSecret` + 内置 MySQL 同时启用时须显式提供 `secret.dbPassword`（configmap 拼装 DATABASE_URL 需明文密码），README 已注明。
- 镜像需预先构建并推送 registry（README 提供三服务构建命令，含 web 的 API_PROXY_TARGET 构建参数）。
- 渲染验证未做真实集群 dry-run（无集群）；worker `HOME=/root` 与 opencode 会话库路径依赖镜像默认行为，真实部署建议先 smoke test。
