================================================================================
Fix: Agent 工作状态在页面切换/刷新后丢失（真实 running 被误显示为「就绪」）
================================================================================
日期：2026-08-13
分支：feature/git-repo-credentials

--------------------------------------------------------------------------------
1. 根因
--------------------------------------------------------------------------------
前端任务详情页 web/app/(main)/tasks/[id]/page.tsx：
- sessionByAgent 状态初始为 {}（useState({})，:1541），只靠 SSE 增量事件驱动
  （useRealtimeEvents：agent.loading / agent.status / session.updated）。
- Next.js 客户端路由切页 → 组件卸载重建 + SSE 连接重置（首连 since=latest）→
  sessionByAgent 复位为空 → 成员面板默认显示「就绪」。
- SSE 重连只收「连接时刻之后」的新事件（skipHistory=true），正在工作的 agent
  不会重放 running 状态 → 执行中状态在切页回来时丢失。

后端已有真实状态源 sessions.status（SESSION_STATUS：created/active/running/idle/
frozen/archived；dispatch 时 updated=running、回复回流收敛=idle），但 GET /tasks/:id
（toTaskDto）此前未返回各实例会话状态 → 前端无从在挂载时恢复。

--------------------------------------------------------------------------------
2. 修复方案
--------------------------------------------------------------------------------
后端（打通真实状态源）：
- server/prisma/schema.prisma：TaskAgent 增加 sessions 关系（Session 增加
  taskAgent 反向关系）。仅 Prisma 层补关系（sessions.task_agent_id 列早已存在），
  无需 DB 迁移；prisma generate 再生客户端即可。
- server/src/tasks/tasks.service.ts：
  · TASK_AGENTS_INCLUDE 的 taskAgents.include 增加
    sessions: { select: { id, status }, where: { status: { not: 'archived' } } }
  · TaskAgentInstance 类型增加 sessions?
  · toTaskDto 实例项增加 sessionStatus（sessions[0].status，每实例恒 1 条会话取首项）
    与 sessionId（供前端建 sessionId→instance 映射收敛 SSE）。

前端（初始快照 + 增量不冲突）：
- web/app/(main)/tasks/[id]/page.tsx：
  · TaskInstance 接口增加 sessionStatus / sessionId（对齐后端 DTO）。
  · 新增 sessionSeedRef 守卫的初始化 effect（仅挂载首次执行）：
    - sessionByAgent 仅「填充缺失 key」：inst.sessionStatus && !(inst.id in prev)，
      不覆盖已到的 SSE 实时状态（避免 refetch/SSE 竞态覆盖 running/idle 切换）。
    - 按 inst.sessionId 建立 sessionId→instanceId/agentId 映射（agentIdBySessionRef /
      instanceIdBySessionRef），保证执行中切页回来时 session.updated idle 仍能收敛。
  · SSE 增量驱动（onSessionUpdated / onMessage 收敛）保持原样，未改事件协议。

--------------------------------------------------------------------------------
4. 风险与说明
--------------------------------------------------------------------------------
- 每实例一会话为既有设计约束（sessions.uk_sessions_task_agent 唯一 [taskId,
  taskAgentId]），取 sessions[0] 安全。
- archived 终态会话不参与展示（where 过滤），归档任务成员回退「就绪」，语义不变。
- SSE 断线重放的历史回复（channel scope）可能在极少数连接级重连时经 onMessage
  收敛清除 running 快照——与原「历史收敛」设计一致，属既有边界；正常切页路径
  （连接保活）不受影响。
