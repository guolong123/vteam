T4 修复：notify_agent（agent 互 @）落库 sender 归属 bug（BUG 修复证据）
=========================================================================
日期：2026-08-13
复现任务：t_0000000012（项目经理-1 分配任务给测试-1，群聊显示"测试的头像/名字"但内容是项目经理的）

一、根因
---------------------------------------------------------------------
T4 设计 notifyAgent（platform-mcp.service.ts :308-351）时契约定为"sender=目标实例"：
落库 senderId=目标实例 agent id（targetAgentId）、senderInstanceId=targetInstanceId、
mentions 标 @ 目标。这与群聊普通消息（group_post sender=发送者实例）语义相反——
前端按 sender 渲染头像/名字，导致"头像是目标实例（测试）的、内容是发送者（项目经理）写的"。
T5 前端 senderNameFromMentions 兜底（senderId 命中 mentions[].agentId 时取 name）进一步
放大该 bug：senderId=targetAgentId 恰好命中 mentions 里的目标 agentId → 显示目标别名。

二、修复 diff 摘要（platform-mcp.service.ts notifyAgent，不改 schema/前端/dispatch 触发）
---------------------------------------------------------------------
触发语义不变：targetInstanceId 仍精确触发目标实例（dispatchAgentMention 原样保留）。
显示语义修正（对齐 group_post 普通消息）：
1) 新增私有方法 resolveSenderAgentId(taskId, instanceId)（group_post 亦复用）：
   taskAgent.findFirst({ id: instanceId, taskId }) 查实例行 → 返回 ta.agentId（真实模板
   agent id）；实例行缺失（存量/回退，instanceId 本身可能是 agent id）→ 原样返回。
2) notifyAgent 落库消息：
   - senderId = resolveSenderAgentId(taskId, selfInstanceId)（发送者实例解析的真实模板
     agent id，如 a_project_manager）
   - senderInstanceId = selfInstanceId（发送者实例，如 ta_0000000037）
   - mentions = [{ type:'agent', instanceId: targetInstanceId, agentId: 目标实例 agent id,
     name: 目标实例别名 }]（@ 目标语义不变，仅表示 mention 归属）
   - content.text = `@目标别名 content`（保持现有拼接）
   - dispatchAgentMention({ taskId, channelId, text, targetInstanceId }) 原样（触发目标实例）
   - 返回结构 { messageId, channelId, targetInstanceId } 不变
语义：MCP notify_agent = "发送者通知目标实例"。消息是发送者的发言（@目标），目标实例被触发处理。

三、spec 更新（platform-mcp.service.spec）
---------------------------------------------------------------------
- notifyAgent 用例的 taskAgent.findFirst mock 改为分流实现（mockTaskAgentRows）：
  发送者实例 ta_sender → { agentId: 'a_sender' }（resolveSenderAgentId 解析）；目标实例
  ta_tester → { agentId: 'a_tester', alias:null, agent:{id,name:'测试'} }（@ 目标/mentions）。
- 主用例断言改为：senderId='a_sender'（发送者 agent id）、senderInstanceId='ta_sender'
  （selfInstanceId）、mentions 含目标实例（ta_tester/a_tester/测试）；dispatchAgentMention
  触发断言、目标实例无会话抛错向上传播断言保留。
- worker-dispatcher.spec 无 notifyAgent 落库形状断言（仅 tools 清单含 notify_agent 字符串），无需改。

六、风险
---------------------------------------------------------------------
- 触发链路零改动：dispatchAgentMention/worker-dispatcher 原样，目标实例触发不受影响。
- 兼容性：resolveSenderAgentId 实例行缺失时原样返回（存量 agent id 直传兼容），与
  group_post 共用同一解析器行为一致。
- 无 schema/前端改动，无新依赖。
- 前端 senderNameFromMentions（T5 兜底）仅当 senderId 命中 mentions 时生效——新语义下
  senderId=发送者、mentions=目标，二者不再重叠，兜底路径自然不触发，无需前端改动。
