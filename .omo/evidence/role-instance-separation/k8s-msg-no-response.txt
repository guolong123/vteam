六、根因定位（证据链）
--------------------------------------------------------------------------------
1. worker 上报 capabilities.baseUrl = http://vteam-worker:4000
   （configmap WORKER_ADVERTISE_HOST: http://vteam-worker，共享 ClusterIP 名）
2. server WorkerClient.resolveExecBaseUrl()（worker.client.ts:431）：
   capabilities 无 execBaseUrl → 取 baseUrl origin + capabilities.execPort(4198)
   → http://vteam-worker:4198
3. vteam-worker 为 ClusterIP Service，仅暴露 4000（serve）端口：
   $ kubectl get svc vteam-worker -o jsonpath ports → [{"name":"serve","port":4000}]
   → 4198 未暴露 → server 内实测 fetch http://vteam-worker:4198/execute
     → TypeError: fetch failed（连接拒绝）
4. 而 pod 专属 headless DNS 下 4198 可达（实测 HTTP 400，端口通）：
   vteam-worker-1.vteam-worker-headless.vteam.svc.cluster.local:4198 ✓
5. 结论：worker 上报地址用错 Service 名（共享 ClusterIP 而非 pod 专属 headless），
   且 ClusterIP 未暴露 exec 端口 → dispatch 必然失败 → 发消息只有 ACK 无回复。

七、修复（chart/vteam/templates，REV 12）
--------------------------------------------------------------------------------
1. statefulset-worker.yaml：新增 env WORKER_ADVERTISE_HOST
   value: "http://$(POD_NAME).vteam-worker-headless.{{ .Release.Namespace }}.svc.cluster.local"
   → 每副本上报唯一 baseUrl（http://vteam-worker-N.vteam-worker-headless...:4000）
2. configmap.yaml：移除共享 WORKER_ADVERTISE_HOST（注释说明由 StatefulSet 按 pod 注入）
3. helm upgrade vteam chart/vteam（-n vteam，保留全部既有 image/secret/values）
