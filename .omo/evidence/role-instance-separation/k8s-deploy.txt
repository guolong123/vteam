[7] 验证修正 (重要) — 外部可达性链路
--------------------------------------------------------------------------------
初轮 port-forward 验证有误: 本机 13000/13001 已被 docker compose 旧部署
(aiagents-compose-server/web, 本机常驻) 占用, kubectl port-forward 绑定失败
("bind: address already in use"), 当时 curl 打到的是 compose 部署而非 K8s。
另: web (Next.js standalone) 只监听 $HOSTNAME(pod IP) 而非 loopback,
kubectl port-forward 转发到 pod 127.0.0.1:3000 也会 connection refused。

纠正方案: 启用 chart ingress (nginx class, host=vteam.ketaops.cc), 经集群
ingress-nginx NodePort 32054 验证 (集群已有 ingress-nginx, LoadBalancer pending,
裸金属走 NodePort; ingress-nginx controller 位于 worker-02/worker-05)。

最终 K8s 链路验证 (全部经 ingress, 唯一可信入口):
- http://<node>:32054/              Host: vteam.ketaops.cc  → web 200 (真实 K8s web pod)
- http://<node>:32054/api/v1/health Host: vteam.ketaops.cc  → {"status":"ok"} 200
  (web rewrites 代理 → vteam-server:3000, 证明重建 web 镜像 API_PROXY_TARGET 生效)
- 登录 admin/admin123 → 200 (user admin, role admin)
- GET /api/v1/agents → TOTAL 5, types=['template'] (产品经理/项目经理/架构师/开发者/测试)
- seed-admin/Admin@123456 登录 → POST /projects/p_seed_1/tasks → 201
  taskId t_0000000001 "K8s冒烟-任务创建" status=pending
- DB 最终计数 (K8s mysql): agents=5 users=3 projects=2, tasks 含 t_0000000001
- worker: w_compose_worker 注册 + 心跳 201 (server 日志 heartbeat 请求可见)

补充: helm upgrade 注意事项 — Job spec.template 不可变, 改 values 后 upgrade 前需
kubectl delete job vteam-init (seed 用 upsert 幂等, 重跑安全); upgrade 必须带
完整原始 values (-f values-dev.yaml + secret.* + image.*), 否则 PVC 尺寸/Secret
漂移导致失败。
