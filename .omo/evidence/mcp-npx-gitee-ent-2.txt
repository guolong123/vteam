## 8. 真正的残留问题（本次修复点）
- tools 表 tl_0000000002（gitee-ent, source=mcp）的 mcp_server 字段值 = **`npx`**，
  而真实 MCP server 名 = `npx_gitee-ent`（id=ms_0000000001）。
- 前端 skills 页按 tool.mcpServer 反查 GET /mcp-servers（id/name 双键 map）→ `npx` 必失败
  → UI 显示「remote/未连接」兜底，即使 worker 已 connected。
- 根因：UI「注册 MCP 工具」弹窗的 MCP server 标识为自由输入（placeholder 如 filesystem），
  用户填 `npx`（非完整 server 名/ID），弱关联断裂。属产品 UX 缺口 + 后端无存在性校验。

## 修复
### A. 数据修复（立即生效）
```
UPDATE tools SET mcp_server='npx_gitee-ent' WHERE id='tl_0000000002';
```
- 修复后前端展示模型模拟：npx_gitee-ent_gitee-ent type=local status=connected ✓
