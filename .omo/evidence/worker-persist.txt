# Worker 容器工作目录与用户目录持久化 —— 端到端验证证据
# 日期: 2026-08-12
# 改动: 仅 docker-compose.yml（SCOPE 内，未改 worker/server/web 代码、未改 Dockerfile）

## 改动内容
1. worker.environment 新增 `WORK_DIR: /data/keta-worker`（serve cwd + .opencode 注入 + agent 工作区）
2. worker.volumes 新增两个命名卷挂载：
   - `worker_work:/data/keta-worker`  # 工作目录（serve cwd、.opencode 注入、git clone 的仓库、任务文件）
   - `worker_home:/root`             # 用户目录（opencode.db 会话库、auth.json、.keta-git-creds.json、log）
3. 底部 volumes 段新增 `worker_work:` / `worker_home:`（与 mysql_data/uploads_data 并列）

## 1. 语法校验
命令: `docker-compose config`
结果: 通过（无 YAML 错误）
- worker environment 含 WORK_DIR: /data/keta-worker
- volumes: worker_work -> /data/keta-worker, worker_home -> /root
- 底部 volumes: mysql_data / uploads_data / worker_home / worker_work

## 2. 重建部署
命令: `docker-compose up -d --build worker`
结果:
- State=running Running=true RestartCount=0
- `docker exec aiagents-compose-worker node -e "...existsSync('/data/keta-worker')"` = true
- `docker exec aiagents-compose-worker env | grep WORK_DIR` = WORK_DIR=/data/keta-worker
- 日志: 「注册成功: workerId=w_compose_worker」「opencode serve 就绪: http://127.0.0.1:4000」

### 存量数据迁移（首次挂载 volume 时容器 writable layer 会清空，先停容器备份再还原）
- 备份: `docker stop worker && docker cp worker:/root /tmp/opencode/worker-persist-backup/root && docker cp worker:/tmp/keta-worker /tmp/opencode/worker-persist-backup/keta-worker`
- 还原: 重建后 `docker cp` 回 /root 与 /data/keta-worker
- 迁移后: opencode.db(2682880B)、auth.json(600)、.keta-git-creds.json(600)、.opencode/tools/git.ts 均在

## 风险
- 首次应用本配置时会经历一次数据迁移（本验证已备份并还原，历史会话完整保留）；
  后续重建不再需要。
- 若未来手动 `docker compose down -v` 删除所有 volume，worker 数据仍会清空（预期行为）。
- WORK_DIR 改 /data/keta-worker 后，镜像内 /tmp/keta-worker 的 dist/node_modules 不受影响
  （Dockerfile WORKDIR 未变），serve cwd 为空卷自动重建 .opencode。
