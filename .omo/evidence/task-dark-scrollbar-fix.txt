=== WHY BOTH `::-webkit-scrollbar` AND `html` ITSELF ===
Two selector groups per rule: the bare `::-webkit-scrollbar` (html element's own
scrollbar) and the descendant one. Without the first, the DOCUMENT/root scrollbar
would keep the light UA style even in dark mode, since ::-webkit-scrollbar is NOT
inherited (unlike scrollbar-color).

   either side, so specificity alone decides. The sidebar's hidden scrollbar is NOT

Two independent guarantees stack here:
  (1) specificity — sidebar (0,1,1) strictly greater than ours (0,0,1);
  (2) cascade order — the sidebar CSS is a runtime-injected <style>{sidebarCss}</style>
      (system-sidebar.tsx:138) rendered in the body, i.e. AFTER globals.css in tree
      order, so it also wins any tie.
scrollbar-color is inherited onto .sysnav-scroll, but is inert there because
scrollbar-width:none suppresses the scrollbar entirely.
Verified in COMPILED output: `:where()` survived minification verbatim (not optimized away).

=== LIGHT-MODE NON-REGRESSION ===
Every selector in the block is prefixed with `:where(html.dark)`. In light mode <html>
never carries `.dark`, so NOTHING matches: not the ::-webkit pseudo-elements, not the
scrollbar-color/scrollbar-width declaration. There is no unscoped fallback and no
non-dark selector group anywhere in the block. Light mode therefore keeps the exact
UA/system default scrollbar rendering — behaviourally identical to before this change.
Confirmed by exhaustive scan of the compiled stylesheet: every scrollbar rule present is
html.dark-scoped; there are no other scrollbar rules in the build output.
Scrollbars are NOT hidden globally — only the pre-existing sidebar stays hidden, as before.

=== @supports not selector() GUARD — RATIONALE ===
Chromium/Safari ignore the entire ::-webkit-scrollbar styling the moment
`scrollbar-width` is anything other than `auto`. Setting it unconditionally would give
Firefox a slim scrollbar but cost Chromium the 10px sizing, the 8px radius and the
:hover highlight — i.e. degrade the very engine where the bug was reported.
`selector(::-webkit-scrollbar)` is false only in engines lacking ::-webkit-scrollbar
support (Firefox), so `@supports not selector(...)` confines `scrollbar-width: thin`
to exactly those. Firefox: slim + correct dark colours via scrollbar-color.
Chromium/Safari: 10px rounded thumb + hover highlight via ::-webkit rules.
Verified intact in compiled CSS:
  @supports not selector(::-webkit-scrollbar){:where(html.dark){scrollbar-width:thin}}
Safe degradation: engines that do not understand `@supports selector()` drop the whole
block rather than mis-applying it.
