E1 算术独立复算（封顶在健康补拉不可达）
--------------------------------------------------------------------------------
帧来源：每条 message.part.delta 经 realtime.emit 广播一帧（worker-event.ingress.ts:834），
无合批；事故实测帧率 7/s 与 35/s（a3a17c0），44/s 为峰值包络；帧体 = 全量 accumulated
message（incident 记录 ~250KB-1MB）。
补拉耗时：getEventsSince = findFirst + findMany(id 索引, take 1000)，正常 ms 级；100ms
为宽松的 worst-normal 上界。
  100ms × 44/s = 4.4 帧；4.4 × 1MB = 4.4MiB
  1000 / 4.4 ≈ 227× 余量；64MiB / 4.4MiB ≈ 14.5× 余量
  1000 帧需 22.7s（44/s）才会触条数顶；64MiB 需 1.45s（1MB/帧）才会触字节顶
  → 健康补拉（ms-100ms 级）不可能触顶；只有悬挂/降级补拉才收敛。作者算术复核为真。
  反向边界（N2）：2s 慢补拉 × 44/s × 1MB = 88MB > 64MiB ⇒ 字节顶在「慢但正常」的
  峰值组合下可触达一次；后果 = 淘汰最旧帧 + 1 行 warn；非 delta 被淘汰帧仍在 DB
  backlog 中经 seen 去重补回，delta 被淘汰帧由终帧 + REST 覆盖 ⇒ 无消息损失。

E3 死线早触语义对抗审查（最高风险项）
--------------------------------------------------------------------------------
代码事实（realtime.controller.ts:215-273）：
  - 到点：replaying=false；按数组序（= 广播插入序）下发已累积缓冲；清空缓冲；
  - 迟到 settle：bufferReleasedByDeadline=true ⇒ **整体 return，backlog 一帧不发**；
  - 论证原文「迟到 backlog ⊆ 已送达集合」依赖：落库先于广播 + Node 单线程微序。
(a) 补拉永不 settle：订阅者得到 [订阅, T+30s] 窗口内经封顶收敛的缓冲（最旧淘汰），
    此后的实时帧直通。丢失 = 请求的 (since, 订阅时刻] 全部历史 + 被淘汰帧。
(b) 补拉在死线后 settle：整个迟到 backlog 被跳过，丢失同 (a)（且无淘汰也全丢）。
收敛性：EventSource onerror 重连带 since=lastId，而 lastId 已被缓冲/直播帧推过
    丢失区间 ⇒ 重连不会补拉缺失历史；消息内容经 REST 历史收敛（web/hooks/use-sse.ts
    首连恒 since=latest、历史由各页 REST 加载，即设计如此）；非消息类事件
    （task.status.changed 等）要等页面 REST 重载才恢复。
静默性：不静默——死线回调 warn 一行「[liveBuffer] 补拉重放期超过 30000ms 未返回…」。
对抗用例（替身副本实证，2/2 通过）：
  T1 断连不泄漏：hung 补拉中 unsubscribe → 推进 2×死线时长，warn 0 次、0 下发、
     监听器已摘 ⇒ teardown clearTimeout 有效（另有 unref 兜底）。
  T2 淘汰+跳过迟到 backlog = 具体丢帧：hung → 推 1005 帧（淘汰 ev_1..ev_5）→ 死线
     下发 ev_6..ev_1005 → 迟到 backlog = [ev_3]（已落库、从未送达）⇒ 终态 received
     不含 ev_3 且游标已越过 ev_3。
     结论：` ⊂ 已送达` 的精确表述应为 `⊂ 已送达 ∪ 已淘汰`。可达条件 = 悬挂 ≥30s
     ∧ 30s 内 ≥1000 帧（≈33 帧/s 持续）∧ 丢失事件为非 delta 落库事件。降级路径 +
     warn 可见 ⇒ 按任务定义的 blocker 判据（静默 ∧ 正常路径）不成立，记 note N1。
