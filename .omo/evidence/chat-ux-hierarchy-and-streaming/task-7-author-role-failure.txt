3. 红期测试即最终测试（透明记录两次测试侧收敛）
======================================================================
3.1 第一次红跑（task-7-e2e-red-iter1.log）暴露的测试自身 bug：
    例 3 写成 `external.getByTestId("chat-bubble").toHaveCount(1)` → Expected 1 / Received 0。
    原因：external 行的列表直接子元素**就是** chat-bubble 根节点，后代查询取不到自身
    （B2 既有 bubbleCount helper 注释已记录同一事实）。产品行为正确。
    修正：改为对节点自身断言 `toHaveAttribute("data-testid","chat-bubble")` 与
    `toHaveAttribute("data-type","agent")`，并补上该行的 B9 断言（role 标签 + 裸 id 扫描）。
3.2 第二次红跑（task-7-e2e-red-iter2.log）：
    例 3 改后红在 `Expected "开发者" / Received "a_ghost_ext"`（正确的红）；
    例 1、例 2 与第一次红完全一致。
3.3 实现后首跑（无独立日志，见下方 3.4 说明）有两处失败，均因**既有结构**：
    external 渠道徽标本来就是 chat-bubble-author 的子元素（B1 之前的既有布局），
    整个 author span 的文本是 "开发者外部渠道"，而断言写的是整串相等 "开发者"。
    修正：把这两处从「整串 author span」收敛到「author span 的首个子 span（= 主文本）」：
      `expect(author.locator(":scope > span").first()).toHaveText("开发者")`
    收敛方向是**更严**（逐字锁定主文本），同时保留并新增
    `not.toContainText("a_ghost_ext")` 与整行 innerText 裸 id 扫描，未删除任何断言。
3.4 为保证「红跑 = 最终测试文本」，修正后重新执行了 §1 的 R-B 红跑（task-7-e2e-red.log），
    三处失败全部复现且第三处用的正是 `:scope > span` 选择器 →
    不存在「改测试迁就实现」的情况，红绿差异只来自 4 个产品文件。
