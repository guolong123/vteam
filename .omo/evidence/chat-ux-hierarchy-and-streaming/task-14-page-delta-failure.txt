现象: 实现生效后 Todo14-3 仍 Expected 2 / Received 1 (10s 超时)。
根因 (读库源码, 非猜测):
  web/node_modules/@tanstack/query-core/src/query.ts:400-415
    if (this.state.fetchStatus !== 'idle' && this.#retryer?.status() !== 'rejected') {
      if (this.state.data !== undefined && fetchOptions?.cancelRefetch) {
        this.cancel({ silent: true })      // 只有已有 data 才取消重发
      } else if (this.#retryer) {
        return this.#retryer.promise        // data undefined → 并入在途请求, 不产生第二次 HTTP
      }
    }
即: “初始请求被挂起 + cache 无数据”时, refetch() 不会产生第二次 history 请求 ——
这是 React Query 的去重设计, 不是实现缺失。
处置 (两处, 都不放宽验收):
  a) Todo14-3 改为可稳定观察的空缓存态 (error + idle, data===undefined):
     harness.failPrivateHistoryAttempts=2 → 初始 2 次尝试 500 → 前 2 次 /messages 回退也 500 →
     查询落 error/idle → delta 触发的 refetch() 必然发出新的 session-history 请求 (2→3)。
  b) 原“挂起”形态保留为 Todo14-3b, 断言其真实可保证的结果: delta 不丢、放行后消息渲染、
     回退请求数 0。
之后复跑 → Todo14-3 / 3b 双绿, 请求数证据见 task-14-page-delta.txt 第 6 节。
