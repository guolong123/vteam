6. 空缓存补拉的请求数证据
--------------------------------------------------------------------------
“目标 query cache 无数据”在本栈下唯一稳定可观察的状态是
query 处于 error + fetchStatus=idle (data === undefined) —— 原因:
  @tanstack/query-core/src/query.ts:405-415  fetching 中调用 refetch()
  只有 state.data !== undefined 才 cancelRefetch 并重发; data undefined 时
  直接 return this.#retryer.promise (内部并入既有请求, 不产生第二次 HTTP)。
因此 harness 用 failPrivateHistoryAttempts=2 造出稳定空缓存 (staleTime=30s, retry=1)。

Todo14-3 (私聊 ch_dm_1, Tab 激活, 空缓存):
  阶段                      /channels/:id/session-history   /channels/:id/messages(回退)
  ------------------------- ------------------------------ -----------------------------
  初始 2 次尝试 (均 500)    2                              2        → 进入 error/idle
  发出 1 个 delta 后        3   (+1, 恰好一次补拉)         2        (不变)
  再发 1 个 delta (去重门)  3   (不变)                      2        (不变)
  断言: expect(history).toBe(3) / expect(fallback).toBe(2) / 补拉结果渲染 DELTA_TEXT → 全 PASS
  → “首个 delta 触发恰好一次 follow-up history request 并渲染消息” 成立。

Todo14-3b (初始 history 请求被挂起、cache 恒 undefined 的原始竞态):
  history 请求数 = 1 (被挂起), 放行后消息渲染可见, fallback = 0 → PASS
  说明: 该形态下 refetch() 被 React Query 并入在途请求 (无第二次请求),
        关键结果是“delta 不丢、消息最终可见”。

Todo14-6 (群聊 Tab, 有 DM delta): privateHistory = 0 → 未选中私聊频道不触发任何私聊拉取。
Todo14-5 (终态优先): 同 id 的旧 delta 之后, TERMINAL_TEXT 仍在、旧 delta 文本 0 处 → PASS
  (upsertMessage 未被修改, git diff hooks/use-realtime.ts 为空)。
