3. PERSIST SEMANTICS — 本 todo 选定的口径
--------------------------------------------------------------------------------
  **absent → 保留已有值（整键不写，绝不写 null）**，register 与 heartbeat 一致。

  理由：codeVersion 与既有 defaultModelId 同为「worker 自报的可选事实」。
  写 null 的后果是：同一 workerId 上一次新版 worker 注册上报了 SHA，随后一次
  旧版 worker（不带该字段）重注册就把版本抹成未知 —— UI 徽章从「具体版本」
  退化成「未知」，而真相（worker 确实跑着新版）被丢掉。NULL 只应表示「从未上报过」。

  其他口径：
    - 空串 / 纯空白 → 视为未上报（同 absent）
    - > 191 字符 → 截断到 191（MySQL 严格模式 1406 会让整个注册/心跳失败；
      截断只损失展示精度，版本串本就是给人眼比对的短标识）
    - 新建行（create）时缺席 → 列取默认 NULL = 从未上报
  选定口径已由 13 条 service spec 钉住（含「整键缺席」`'codeVersion' in data === false`）。
