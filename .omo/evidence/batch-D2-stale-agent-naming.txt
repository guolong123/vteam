────────────────────────────────────────────────────────────────────────
0. 本批要闭合的缺陷（批次 D 报出来但**没有**修的那条）
────────────────────────────────────────────────────────────────────────
批次 D-1 修了**配置侧**的 fail-open：`/agent-policies` 拉取失败时，worker 改为
**保留**上次注入的受管 agent 块（不再删除）⇒ 权限集**既不收窄也不放大**。

但**派发侧**仍在放大权限，且批次 D 无法修（派发属另一批次）：

1) server/src/chat/worker-dispatcher.ts（改前 ~2931-2950）
     const resolvedAgentName: string | null =
       opencodeAgentName ??                                   // 成员显式绑定的外部 agent
       (policyCandidateAgent &&
       workerSupportsAgentPolicies(worker, policyCandidateAgent)
         ? policyCandidateAgent
         : null);
     ...
     ...(resolvedAgentName ? { agent: resolvedAgentName } : {}),   // 两者皆无 → 省略 agent 键
   省略 agent 键 ⇒ opencode 跑**引擎默认 agent** ⇒ 角色 `permissions[]`
   （edit deny / bash ask / MCP denies）**对该轮不生效** ⇒ 平台声明的权限与
   运行时行为分叉 ⇒ **权限放大**。

2) server/src/workers/workers.service.ts（改前 ~225-243）——门：
     const gate = caps.agentPolicies;
     if (!gate || gate.enabled !== true) return false;
     return Array.isArray(gate.names) && gate.names.includes(agentName);
   批次 D 的失败上报是 `{ enabled: false, names: [] }` ⇒ 门返回 false ⇒
   agent 名被丢掉 ⇒ 回到 (1) 的放大路径。

3) **信息在源头就被销毁了**：失败上报 `names: []` ⇒ server 分不清
   「本地**仍有**受管块（批次 D 保留的）」与「从来就没有过 agent 策略支持」。
   批次 D 特意保留的 `manifest.agentNames` 里其实**还留着**上次成功写入的名。

4) 文档缺陷：批次 D 在 worker/src/protocol/worker-protocol.ts 写「陈旧即不派发」——
   **代码从来不是这样**：派发照旧发生，被丢掉的只是 agent 名，而丢名字**正是**放大动作。

本批（D2）三件事：
  D2-1 worker 失败上报**上次已知名** + `stale: true`（信息不再在源头销毁）；
  D2-2 server 的门在 `stale:true` 且候选名在上次已知名内时**放行**；
  D2-3 派发侧在「靠陈旧报告放行」时**留痕**（该轮跑的是上次已知权限集）；
  D2-4 改掉批次 D 那句不成立的注释。

────────────────────────────────────────────────────────────────────────
1. D2-1：worker 上报形状（改前 → 改后）
────────────────────────────────────────────────────────────────────────
改前（批次 D）：
  成功        → { enabled: true,  names: <本次写入名> }
  失败中性化  → { enabled: false, names: [] }                 ← 信息被销毁
改后（本批）：
  成功        → { enabled: true,  names: <本次写入名> }        （**不带** stale = 新鲜）
  失败中性化  → { enabled: false, names: <上次已知名>, stale: true }

上次已知名从哪来：worker/src/resources/injector.ts 的
  `writeNeutralized()` 读 manifest 的 **agentNames** 键（批次 D-1 特意保留的那个键：
  "受管块名字**不清零**：块仍在 opencode.json 里（未删除、未改写）"）。
  首次注入（**从未**成功注入过）⇒ manifest.agentNames 为空 ⇒ `names: []` + `stale: true`
  （这仍然是**诚实**的：本轮确实未刷新，且本地确实没有受管块）。

传播链（否则 server 看不到 stale）：
  injector.writeNeutralized → InjectReport.agentPolicies
    → worker/src/index.ts buildCapabilities（透传 stale，缺席则不带）
      → capabilities.agentPolicies（注册上报）
        → server/src/workers/dto/register-worker.dto.ts WorkerAgentPoliciesDto.stale
          （⚠️ 全局 ValidationPipe 是 whitelist:true —— DTO 不声明 stale 会被**静默剥离**）
            → server/src/workers/workers.service.ts workerSupportsAgentPolicies

4. D2-4：批次 D 那句不成立的注释（改前 → 改后）
────────────────────────────────────────────────────────────────────────
改前（worker/src/protocol/worker-protocol.ts，批次 D 加的）：
  「…`enabled:false` 只表示「策略**陈旧**」⇒ server 的 `workerSupportsAgentPolicies`
    据此不派发需要策略的 agent（陈旧即不派发）。」

改后（本批）：
  「…`enabled:false` 只表示「本轮**未刷新**」。
   ⚠️ 批次 D-2（**修正批次 D 注释里那句不成立的保护**）：批次 D 的注释写「陈旧即不派发」，
   但代码**从来不是**这样——派发照旧发生，只是能力位门把 **agent 名丢掉** ⇒ opencode 跑
   **引擎默认 agent** ⇒ 角色的 `permissions[]`（edit deny / bash ask / MCP deny）**对该轮
   完全不生效** ⇒ 权限被**放大**（fail-open）。批次 D-2 的实际行为：…
     server 的能力位门在 `stale:true` 且候选名在 `names` 内时**放行** ⇒ 该轮仍点名角色
     agent ⇒ 跑在**保留的**（上次已知）角色权限集上，既不收窄也不放大；派发侧另有日志留痕。」

worker/src/resources/injector.ts 的同款注释（InjectReport.agentPolicies / writeNeutralized）
也一并改正（原文同样写着「不派发需要策略的 agent（stale-true 防护在派发侧）」）。

────────────────────────────────────────────────────────────────────────
5. 派发到**陈旧** worker 的前后对比（结论）
────────────────────────────────────────────────────────────────────────
改前：opencode 跑**引擎默认 agent**（payload 里**没有** agent 键）
      ⇒ 该角色的 `permissions[]`（edit deny / bash ask / MCP denies）**完全没生效**
      ⇒ 实际权限**比平台声明的更宽**（放大，fail-open）。
改后：opencode 跑**角色 agent**（payload 里带 agent 键 = 该角色的 agent 名）
      ⇒ 该轮落在**保留在 worker 本地的受管块**上 ⇒ 角色的 `permissions[]` 生效
      ⇒ 实际权限 = 平台声明的那一套（**上次已知**的版本，不是本轮的），**不放大**。
      ⚠️ 陈旧时适用的是**上次已知**的权限集（可能已过期）——这由 D2-3 的日志留痕，
         以及控制面恢复可达后的下一次成功刷新来收敛。
