# 团队协作规约（草案 v1，试运行版，拟转正为 docs/agent-platform/30-团队协作规约.md）

> 来源：2026-09-15 协作 5 幕剧本实测（见 `.omo/plans/learning-mode-private-knowledge.md §9`）。
> 实测结论：点对点配合顺畅（求助接力/越界转交/失败升级全过），广播必炸（1 个 @all 引 6 人群答），
> 定向 @ 无超时升级（12 分钟零回复也无人跟进）。本规约先以文档 + team 记忆试运行，跑顺后再固化进各角色 persona。
> 状态：草案（B 方案），未进 persona，违例不拦截只记录。

## 1. 总则

- 群聊是工作区，不是聊天室：每条消息要么推进任务，要么沉淀信息。
- 默认点对点，能 @ 单人就不 @all；能查 librarian/记忆/文档库，就不 @ 真人。
- 谁接活谁闭环：接到 @ 或转交必须有回执（做完/做不了/转给谁），不许石沉大海。

## 2. 求助三要素（@ 人必须带齐）

格式：`背景（一句话） + 要什么（具体交付物） + 期望（谁、何时）`。

- 反例：`@开发者-1 帮忙看下`（缺三要素，打回）。
- 正例：`@开发者-1 我是测试-1，为回归测试准备。请提供 e2e-c 场景的可验证清单（含前置条件、入参、期望输出），拿到后我发群。今天内给我。`
- 接到要素不全的求助：先追问要素，不开工（实测 Act1 范本）。

## 3. 转交闭环（重要转交必须落 issue）

- 口头转交只用于通知，责任转移一律落 issue（标题 + 指派到实例 + 验收口径）。
- 转交格式：`转交 @X：事项 + 已有材料（issue/产出物 id）+ 期望动作`，被转交人须回执确认接手。
- 越界请求：拒绝 + 指路，不代做（实测 Act2 范本：开发拒代判验收→转交 PM→PM 点名测试出结论，全程带证据指针）。
- 转交链超过 3 轮未闭环：升级主 Agent，必要时提示成员介入。

## 4. 广播纪律（@all）

- `@all` 仅用于：需全员知晓的结论/决策、点名长期不回复的成员、紧急阻塞。
- 私域问答禁止 `@all`：先问 librarian（`@知识管理员-1`）；librarian 说不知，再定向问对口角色。
- 收到 `@all`：与自己无关不回复；librarian 只答沉淀相关；禁止用 `@all` 收尾（实测 Act4 反例：6人群答 + 两条收尾 @all）。

## 5. 定向 @ 超时升级（暂行口径，待度量校准）

- 被 @ 后 10 分钟无回执：发起人先在群里再点名一次；仍无响应则升级主 Agent，由主 Agent 改派或落 issue。
- 失败即报：`notify_agent` 失败（实例不存在/无会话）不重试、不伪造成功，核对 `team_view` 后汇报 + 给替代路径（实测 Act3 范本：错误码原文 + 7 成员核对）。
- 主 Agent 定时巡检兜底：长时间无进展的任务由巡检发现并推进。

## 6. 升级路径

成员互助 → 主 Agent 协调 → 落 issue 跟踪 → 提示成员（人）介入。每一级都要留痕（群消息或 issue），不许口头升级无记录。

## 7. 度量（协作健康度，出口径）

- 转交响应时长 P50/P90（@ 发出→目标首次回复）。
- 转交闭环率（有回执/解决的比例）。
- 广播率（@all 占群消息比）与找错人率（越界拒绝占比）。
- 定向 @ 超时率（10 分钟无回执占比）。
- 重复打扰率（librarian 可答却 @ 真人的比例）。
