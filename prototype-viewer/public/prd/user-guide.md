# Orchestra 用户手册

> 面向平台使用者的操作指南：登录、配置模型、创建 Agent、编排流程、发起任务、审批、管理生态与观测。本文档从"如何做"出发，只讲界面操作，不涉及技术实现。
> 关联文档：[需求规格说明书](requirements.md)（功能全貌）· [开发计划](development-plan.md)（版本范围）

---

## 1. 快速开始

Orchestra 是一个任务编排平台。你可以把公司里由多个角色协作完成的业务过程，比如"需求分析 → 人工评审 → 设计 → 开发 → 测试 → 验收"，定义成一套可重复执行的流程，然后让 Agent 去跑，在关键节点由人来把关。

平台把流程里的事分成几类对象：模型端点（Agent 的"大脑"）、Agent（执行者）、技能（可复用的能力包）、流程（协作编排）、任务（一次执行）、审批（人工决策）、触发器（自动发起任务的开关）。后面的章节按这个顺序逐一介绍。

### 1.1 登录

打开平台控制台，首次进入会看到登录页。把管理员发给你的访问令牌（token）粘贴到输入框，点击「连接」即可进入。

- 令牌只保存在当前浏览器里，用于请求认证；再次打开页面通常无需重新输入。
- 右上角「退出」按钮可清除令牌，退出登录。

### 1.2 切换命名空间

顶栏左侧有「命名空间」下拉框。命名空间是资源与数据的隔离边界，Agent、流程、任务、凭证都归属某个命名空间，不同命名空间互不可见。

切换命名空间后，页面上的所有数据都会变为该命名空间下的内容。

- 顶栏下拉即可切换，常用的有 `default`、`dev`、`qa` 等，`system` 为系统保留命名空间。
- 也可以在「全局设置」中修改默认命名空间，下次进入直接落在该命名空间。

### 1.3 认识主界面

左侧菜单按业务分组：总览、任务、审批、编排、管理、生态、设置。右上角显示平台 API 连接状态（在线 / 离线），绿点表示一切正常。

- **平台总览**：任务统计、最近任务、待审批事项，一屏掌握全局。
- 每个页面的右上角有刷新按钮，列表类页面会定时自动刷新。

下面从"第一次配置平台"开始，走一遍完整的使用路径。

## 2. 配置模型端点

模型端点是 Agent 推理时使用的大模型接入配置，包含服务商、接口地址、模型名称和计费单价。Agent 只引用端点，不直接写死模型，以后换模型只改端点即可。

在左侧「管理」分组点击「Model Endpoint」进入管理页。

@page[model-endpoints]

### 2.1 新建端点

1. 点击「新建 Endpoint」。
2. 填写名称；选择服务商（openai、anthropic、deepseek、ollama、azure-openai 等，也可自定义）。
3. 填写接口地址、默认模型，如需认证可引用一个已配置的凭证（见第 11 章）。
4. 可选配置备用模型：主模型不可用时（如限流、超时）会自动切换。
5. 填写计费单价（输入 / 输出每百万 token 的价格）与上下文窗口大小，任务成本统计会用到。
6. 保存后端点即出现在列表中。

### 2.2 管理端点

- 点击列表行可查看详情（含完整配置）。
- 「编辑」修改配置，删除前请确认没有 Agent 正在引用它，否则会被平台拦截。

### 常见场景

- 团队为节省成本只允许部分模型：把便宜模型建成一个端点，多个 Agent 共用。
- 主模型限流频繁：配置好备用模型，任务会自动降级切换，不中断执行。

## 3. 创建 Agent

Agent 是流程中的执行单元。它拥有自己的提示词、使用的模型、可调用的工具和执行上限。你可以为每个角色（需求分析、架构师、测试、开发）创建一个 Agent。

在左侧「管理」分组点击「Agent 管理」进入列表，点「新建 Agent」开始创建。

@page[agents]

### 3.1 填写配置

创建表单分四个区块，从上到下依次填写：

1. **基本信息**：名称、描述；运行时默认是 opencode，保持默认即可。
2. **模型与提示词**：选择第 2 章配置好的 Model Endpoint；工作目录留空则使用运行时实例的默认工作区；在提示词中写明这个 Agent 的职责与工作方式。
3. **工具权限**：填写这个 Agent 可以调用的工具（工具格式为 `插件名.工具名`，可从第 10 章的工具管理页查询可用工具）。允许工具列表必须是已填写工具的子集，平台会做校验，防止越权。
4. **执行上限**：最大推理步数、单次任务超时（秒）、Token 预算。防止 Agent 失控长期空转或超支。

### 3.2 后续管理

- Agent 列表支持搜索，行内可查看详情、编辑、删除。
- 被已发布流程引用的 Agent 不能被删除，平台会明确提示。

### 常见场景

- 建一个"需求分析师"，提示词里写明"基于 issue 描述输出结构化需求文档"，并授权它读写 issue 仓库的工具。
- 建一个"架构师"，提示词要求输出技术方案，模型用更强的大模型端点，Token 预算给足。

## 4. 管理技能与技能市场

技能是可复用的能力包：一段提示词模板，可以附带绑定的工具和说明文档。把高频能力（如"需求文档生成""测试用例生成"）做成技能，多个 Agent 可以按需引用，不用在每个 Agent 里重复写提示词。

在左侧「生态」分组点击「Skills 管理」进入页面。

@page[skills]

### 4.1 在命名空间内创建技能

1. 切到「命名空间 Skills」标签页，点击「新建 Skill」。
2. 填写名称、展示名称，选择分类：
   - **提示词模板**：纯提示词，通用能力。
   - **工具绑定**：提示词加工具组合，如"调用 GitHub 读取 issue 再生成文档"。
   - **模板**：可参数化渲染的文档 / 代码骨架。
3. 填写语义化版本（如 `1.2.0`，发布后不可变）、提示词正文。
4. 工具绑定类技能需声明绑定的工具；如有依赖插件可填写依赖项。
5. 保存后可用上方分类栏筛选，查看版本、发布状态。

### 4.2 发布到市场与安装

- 点击技能的「发布到市场」，技能即对市场可见；重新编辑会产生新版本，可再次发布。
- 切到「市场」标签页可浏览目录：名称、最新版本、分类、描述。
- 点击「安装到当前命名空间」，可选择精确版本或填写版本范围（如 `1.2.x`）。依赖的插件会自动安装。市场安装的副本与源技能隔离，各自独立维护。

### 常见场景

- 团队沉淀"代码评审"技能并发布到市场，QA 团队在自己命名空间安装使用。
- 技能升级后，希望只对新任务生效：发布新版本，引用方按版本范围解析。

## 5. 编排流程

流程是把多个 Agent 的协作关系画成一张图：节点是 Agent 或审批关卡，连线决定流转方向。支持顺序执行、条件分支、并行分支、循环和人工审批关卡。

在左侧「编排」分组点击「流程定义」进入列表，点「新建流程」打开画布。

@page[flows]

### 5.1 使用画布编排（推荐）

@page[flow-editor]

1. 从左侧节点库点击或拖拽添加节点：
   - **Agent**：选择一个已创建的 Agent 作为执行节点。
   - **审批关卡**：该节点执行完成后暂停，等待人工审批（见第 8 章）。
   - **并行 / 汇合**：多路同时执行；汇合节点可设置"全部完成再继续"或"达到部分数量即继续"。
   - **循环**：节点循环执行，必须设置最大迭代次数防止死循环。
2. 在节点间连线，表达流转关系：
   - **顺序**：上一个完成后执行下一个，上游输出可传给下游。
   - **条件**：根据上游输出判断走哪条分支（可基于内容包含、正则或 JSON 字段取值），并设置默认分支兜底。
   - **并行**：同时进入多个下游节点。
3. 选中节点在右侧属性面板编辑：Agent 引用、输出名、审批人、条件表达式等。
4. 画布与 JSON 互为等价：右上角可切换到 JSON 模式直接编辑或查看定义，两种方式来回切换内容一致。
5. 保存前平台会自动校验：是否存在环、节点引用是否存在、条件是否合法。

### 5.2 发布与版本管理

- 流程列表展示状态（草稿 / 已发布）、版本号、节点数。点击「发布」即生成一个新版本快照。
- 已发布的版本不可变；发布新版本后，运行中的旧任务不受影响，新旧版本并行。
- 流程详情页（点流程名进入）有只读画布、版本历史和版本对比：可查看 v1 到 v2 的差异（节点、连线、审批关卡的新增与变更）。

### 常见场景

- 软件交付流程：需求分析 → 审批 → 设计 → 审批 → 开发 → 测试 → 验收审批。
- 用并行节点让架构师与测试用例设计同时开工，汇合后再进入开发节点。

## 6. 设置触发器

触发器让任务不再需要手动发起：到点自动跑、收到外部事件自动跑、群里发指令自动跑。平台支持三种触发器：定时、Webhook、企业微信消息。

在左侧「任务」分组点击「触发器配置」进入页面，点「新建触发器」，选择类型。

@page[triggers]

### 6.1 定时触发器

按 cron 表达式周期生成任务：

1. 选择「定时」，填写 cron 表达式（5 段：分 时 日 月 周，支持 `*`、步长、范围、列表），平台会校验表达式的合法性。
2. 可填写时区；选择要执行的流程（仅已发布流程可选）。
3. 打开「启用」开关，列表会展示下次触发时间。

### 6.2 Webhook 触发器

外部系统（如代码托管平台）发事件到平台时触发任务：

1. 选择「Webhook」，填写签名密钥（发送方需携带 HMAC 签名，平台校验）。
2. 填写幂等键来源（如 `header:X-GitHub-Delivery`），同一事件重复投递不会重复执行。
3. 选择关联流程。配置完成后，把页面展示的路径配置到外部系统的回调地址。

### 6.3 企业微信消息触发器

在企微群里 @机器人 发指令即可发起任务：

1. 选择「企业微信 IM」，填写回调验签信息（Token、EncodingAESKey、CorpId）。
2. 设置指令前缀（默认 `@机器人 `）与命令关键字（如 `发起需求分析`）。
3. 配置企微用户与平台账号的映射关系，平台据此校验发起人权限。
4. 保存后页面会展示回调 URL，把它配置到企业微信应用的接收消息地址。

### 常见场景

- 每天 9 点定时跑一次"数据巡检"流程。
- GitHub 创建 issue 时，通过 Webhook 自动触发"需求分析"流程。
- 测试群内发"@机器人 跑回归测试 #123"，QA 直接触发回归。

## 7. 发起与查看任务

任务是流程的一次运行实例。你可以手动发起，也可以靠第 6 章的触发器自动发起。

在左侧「任务」分组点击「任务列表」进入。

@page[tasks]

### 7.1 发起任务

- 任务列表页点「新建任务」：选择一个已发布流程，填写任务输入（JSON 对象，会被流程节点引用）。
- 或在流程详情页点「触发任务」，流程已固定，只需填输入。
- 发起后任务进入列表，状态从「待执行」开始流转。

### 7.2 查看任务状态

任务有八种状态，列表和详情页都有状态标识：

| 状态 | 含义 |
|---|---|
| 待执行 / 运行中 | 排队中或正在执行 |
| 等待审批 | 停在审批关卡，等人决策（见第 8 章） |
| 成功 / 失败 | 终态 |
| 已取消 / 已阻塞 / 已过期 | 干预或异常终态 |

任务详情页展示基本信息（流程、命名空间、触发方式、当前节点、Worker、重试次数）、任务输入、最近错误和节点产物。

### 7.3 运行中的干预

在任务详情页，根据当前状态可执行：

- **暂停 / 强制暂停**：运行中暂停任务，等待当前步骤收尾后冻结；暂停后任务停在「已暂停」，点「恢复」继续。
- **取消**：停止一个待执行或运行中的任务。
- **重新执行**：失败或取消的任务可重试。
- **重跑**：终态任务可重新跑一遍，会生成一个全新任务实例（名称带 `#rerun-N`），原任务与执行记录完整保留。

### 7.4 查看执行过程（Trace）

任务详情页点「查看 Trace」进入全链路视图：按时间线展示模型调用、工具调用、审批暂停、错误等信息，节点间用树形缩进体现调用关系。可按类型筛选，点击步骤查看请求 / 响应摘要。Trace 页会实时刷新。

### 7.5 成本与产物

任务详情页底部有两个页签：

- **成本**：按日期和 Agent 汇总的输入 / 输出 token 数与折算成本。
- **产物**：任务执行归档的产物清单（版本、格式、类型、关联的 issue / PR），点击可查看详情。

### 常见场景

- 一个流程跑挂了，进详情页看 Trace 定位是哪个工具调用出错。
- 上个月各 Agent 花了多少 token：任务详情成本页签按 Agent 汇总一目了然。

## 8. 审批中心

审批是平台"人工在环"的核心：流程执行到审批关卡会停下来，等有权限的人决策，未批准不会继续。决策有三种：通过、打回重做、拒绝。

在左侧「审批」分组点击「审批中心」进入。

@page[approvals]

### 8.1 处理待审批

1. 列表顶部统计卡展示待审批数量、已处理数量、平均耗时。
2. 待审批项展示类型（任务审批 / 工具审批）、关联任务、节点、当前轮次、审批人和过期时间。
3. 列表页可直接「通过」或「拒绝」；更完整的决策（含打回重做）在审批详情页操作。

### 8.2 审批详情与三种决策

点待审批项进入详情页，可看到被审批的产物预览、提交人、产生该产物的 Agent、检查点位置、TTL 剩余时间与审批历史轮次。

决策区有三个按钮：

- **通过**：批准后任务从暂停点精确恢复继续执行，已完成的节点不会重跑。
- **打回重做**：携带意见打回给上游 Agent 重做，进入下一轮评审（轮次 +1）。达到最大轮次仍未通过会升级为阻塞。
- **拒绝**：任务标记为失败，保留驳回意见。

每次决策都要填写备注意见，决策后不可撤回；决策人、时间、意见会完整记录并进入审计日志。

### 常见场景

- 需求文档质量不过关：打回重做并附上"补充验收标准"的意见，Agent 修订后再次提交审批。
- 高风险工具（如删除资源、推送代码）执行前会生成工具级审批，审批通过才放行。

## 9. 使用业务包（Blueprint）

蓝图（Blueprint）是把一组"Agent 定义 + 流程 + 审批关卡 + 默认凭证占位"打包成的业务模板。比如"软件公司开发流程"打包了需求分析、架构师、测试、开发等 Agent 和完整流程，一键安装即可复用，不用从零搭建。

在左侧「生态」分组点击「蓝图市场」进入。

@page[blueprints]

### 9.1 安装蓝图

1. 浏览蓝图列表，查看内容统计（包含几个 Agent、几个流程、几个审批关卡）与版本。
2. 点击「安装」，在弹窗中选择目标命名空间。
3. 蓝图声明了默认凭证占位时，按提示配置对应的 Secret 参数（键值对）。
4. 安装成功后，可在流程定义列表看到生成的流程，按需修改即可。安装副本与源蓝图相互独立。

### 常见场景

- 新项目组接入：装一份"软件公司开发流程"到自己的命名空间，改改提示词就能跑。
- 用蓝图统一各团队交付流程的标准版本，再允许各团队在副本上微调。

## 10. 插件与工具

平台只做编排，具体执行（构建、部署、代码托管）交给第三方系统，通过插件对接。插件安装后注册一组工具；Agent 通过工具权限引用这些工具。

### 10.1 插件市场

在左侧「生态」分组点击「插件市场」进入。内置插件包括 Jenkins、GitHub、Gitee、MCP、企业微信等，未安装的可点击「安装」，已安装的可「启用 / 禁用 / 卸载」。卡片会展示插件提供的工具清单。

@page[plugins]

### 10.2 MCP 服务

在左侧「生态」分组点击「MCP 服务」进入。MCP 是标准协议，外部服务通过它接入平台后，工具会被自动发现：

1. 点「注册 MCP Server」，选择传输方式：
   - **本地 stdio**：填写启动命令与参数（如 `npx ...`）。
   - **远程 HTTP**：填写服务地址。
2. 注册后可点击「同步工具」，平台会连上服务并自动发现其工具列表。
3. 展开条目可查看已发现的工具及参数摘要。同步后的工具可直接被 Agent 引用。

@page[mcp-servers]

### 10.3 工具管理

在左侧「生态」分组点击「工具管理」进入。这里是平台全部已注册工具的统一视图：

- 可按来源筛选（内置 / 外部插件），顶部统计工具总数。
- 展开某工具可查看它的来源与**引用它的 Agent 列表**，方便评估变更影响。
- 工具的启停由所属插件控制（在插件市场操作），这里只做查看。

@page[tools]

### 常见场景

- 装 Jenkins 插件并配置地址后，Agent 就能调用"触发构建""查询构建状态"等工具。
- 团队自建的服务用 MCP 接入，同步出工具后分发给各 Agent 使用。

## 11. 凭证与安全

平台里需要密钥的地方（模型认证、插件令牌、通知签名等）统一走凭证管理。凭证加密存储，界面上任何位置都只显示掩码，明文永不回显。

在左侧「设置」分组点击「凭证管理」进入。

@page[secrets]

### 11.1 新建与管理凭证

1. 点「新建 Secret」，填写名称，添加一组键值对（如 `apiToken` 和对应的值）。
2. 保存后列表展示数据键和掩码值；详情可查看完整键名与加密密钥标识。
3. 需要轮换时用「更新」：以全量替换的方式写入新值，旧密文即被覆盖。
4. 「删除」移除不再使用的凭证。

### 常见场景

- 创建模型端点时引用 `openai-key` 凭证，接口地址和密钥分开维护。
- 配置企业微信通知或插件时引用对应凭证，密钥不落明文。

## 12. 审计与观测

### 12.1 审计日志

每一次资源变更、任务操作、审批决策、插件安装都会被记录，且只追加、不可篡改。在左侧「设置」分组点击「审计日志」进入。

@page[audit-logs]

- 支持按操作者、操作类型（创建 / 更新 / 删除 / 审批 / 发布 / 暂停 / 恢复 / 重跑等）、命名空间、关键字、时间范围筛选。
- 每条记录展示操作时间、操作者、动作、资源类型与名称、来源（控制台 / API / CLI / Webhook / IM）、执行结果（成功 / 拒绝 / 出错）。
- 平台拒绝的越权操作也会留下记录，方便排查。

### 12.2 任务可观测

任务的执行细节在第 7 章已介绍（Trace、日志、成本）。任务 Trace 与审计日志是两条互补的观测链路：Trace 看"任务内部怎么跑的"，审计看"谁在平台里做了什么"。

### 常见场景

- 排查"是谁改了生产流程"：按操作者与时间范围筛选审计日志。
- 合规审计：导出指定时间段内全部审批决策与资源变更记录。

## 13. Eval 评估

Eval 评估用于衡量 Agent 的输出质量：把一组带期望输出的 golden 样例喂给目标 Agent（或流程），真实跑出结果后按评分维度打分，最终生成可追溯的评估报告。调整提示词或模型后，用同一数据集回归，就能量化变化。

在左侧「编排」分组点击「Eval 评估」进入，页面分「EvalDataset」与「EvalRun」两个页签。

@page[evals]

### 13.1 准备数据集（golden 样例）

1. 切到「EvalDataset」页签，点「新建数据集」。
2. 填写名称、描述；选择评估目标：指定一个 Agent 或一个流程（二选一）。
3. 配置评分维度（JSON）：每个维度选择判定方式：
   - **精确匹配**：输出与期望完全一致（适合结构化输出）。
   - **部分匹配**：按关键词、包含关系或相似度打分（适合自然语言）。
   - **自定义判定**：脚本或 LLM 判定。
4. 录入 golden 样例（cases）：每条包含输入、期望输出，可配权重与判定覆盖。
5. 数据集按版本管理，版本不可变；导入新样例会生成新版本，已发起的评估不受影响。

### 13.2 发起评估运行

1. 切到「EvalRun」页签，点「新建运行」。
2. 选择数据集（可选固定版本）、评估目标（可覆盖数据集设置）、并发数、单条用例超时。
3. 保存后可点「start」开始；运行中可「cancel」，结束后可「rerun」生成新一轮。
4. 每条用例对应一个真实任务，可跳转到该任务的 Trace 查看执行过程。

### 13.3 查看评估报告

点「报告」查看运行结果：

- **汇总**：加权总分、通过率、通过 / 失败用例数、总耗时、token 与成本、各维度得分。
- **明细**：逐条用例的输入、期望输出、实际输出、各维度得分、通过判定与耗时。
- **对比**：同一数据集多轮运行的趋势对比，定位调整后哪些样例变好、哪些变差。

### 常见场景

- 改动了"代码评审"Agent 的提示词，跑同一数据集对比新旧得分，确认没有回归。
- 上线前用 golden 集对多个候选模型打分，选择更优模型接入端点。

## 14. 运行时管理

运行时是 Agent 实际执行所使用的引擎实例（opencode 服务）。平台支持管理多个实例：按环境（dev / ci / prod）隔离部署，或按区域就近执行。Agent 创建时可指定实例，未指定则用默认实例。

在左侧「设置」分组点击「运行时管理」进入。

@page[runtimes]

### 14.1 管理实例

1. 点「新增实例」：填写名称、服务地址（endpoint）、默认工作目录；如服务需要认证，可开启 Basic Auth 并填写用户名密码。
2. 保存后点「测试连接」，平台会直连服务健康检查接口确认可用性。
3. 列表展示实例的连接状态（已连接 / 异常）与认证信息，支持编辑、删除。
4. 顶部统计条展示实例总数与已连接数量。

### 常见场景

- 建 `dev` 与 `prod` 两个实例，开发用 Agent 指向 dev，生产流程用 prod，环境隔离。
- 实例故障时把 Agent 的实例引用切到健康实例，配合任务恢复机制续跑。

## 15. 命令行工具（CLI）

除了 Web 控制台，平台提供 `orchestra` 命令行工具。Web 给人用，CLI 给 AI、脚本和自动化用：同样的操作，命令行方式可确定性执行、输出 JSON 方便程序解析。命令与平台 REST API 一一对应：资源为命令组、动作为子命令。

### 15.1 配置

使用前配置两个环境变量：

```bash
export ORCHESTRA_URL=http://<平台地址>   # 平台地址
export ORCHESTRA_TOKEN=<你的访问令牌>      # 令牌，不落盘明文
```

### 15.2 常用命令

| 场景 | 命令示例 |
|---|---|
| 查看资源列表 | `orchestra agent list`、`orchestra flow list`、`orchestra task list` |
| 创建资源 | `orchestra agent create ...`、`orchestra flow create ...` |
| 发布流程 | `orchestra flow publish --name <flow>` |
| 发起任务 | `orchestra task create --flow <flow> --input '{"k":"v"}'` |
| 查看任务与执行 Trace | `orchestra task get --name <task> --trace` |
| 生命周期干预 | `orchestra task pause/resume/cancel/retry --name <task>` |
| 审批决策 | `orchestra approval list`、`orchestra approval decide --name <approval> --action approve --comment "..."` |
| 插件 / 技能 / 凭证 | `orchestra plugin install ...`、`orchestra skill list`、`orchestra secret create ...` |

- 默认输出 JSON（`--output table` 可切换为表格）。
- 所有命令确定性执行，无交互式提示，非必填参数走默认值，适合脚本调用。
- 命令行操作同样进入审计日志，来源标记为 CLI。

### 常见场景

- CI 流水线里用 `orchestra task create` 发起验收任务，用 `orchestra task get --trace` 拉取结果。
- AI 编码工具调用 `orchestra` 操作平台，完成"创建 Agent → 发布流程 → 跑任务 → 查 Trace → 做审批"的自动化闭环。

## 16. 全局设置

全局设置是平台级配置的集中入口：访问令牌、默认命名空间、平台健康检查、各插件的连接配置、通知规则与投递记录。

在左侧「设置」分组点击「全局设置」进入。

@page[settings]

### 16.1 认证与连接

- 可修改访问令牌与默认命名空间，保存后立即生效并重新加载界面。
- 点击「检测」可手动执行健康检查，确认平台 API 与各服务连接正常。

### 16.2 插件连接配置

安装插件后，在这里集中配置各插件的连接信息：

- **Jenkins**：服务地址、用户名、令牌。
- **GitHub / Gitee**：访问令牌、可选的自建服务地址。
- **企业微信**：机器人 Webhook 地址。

配置保存为凭证加密存储；已配置的密钥字段留空会拦截提交，避免误清空。

### 16.3 通知规则与投递记录

- **通知规则**：订阅哪些任务事件（成功、失败、等待审批等）投递到哪些渠道，可随时启停。
- **投递记录**：每次通知的投递状态与尝试次数，投递失败可见可排查，不静默丢失。

### 常见场景

- 把任务失败与等待审批事件通知到企业微信群，审批人直接在群里收到卡片。
- 排查"为什么没收到通知"：查看投递记录的状态与重试次数。
